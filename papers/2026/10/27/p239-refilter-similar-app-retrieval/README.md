# [2609.25306] ReFilter: Bridging Embeddings and LLM Filtering cho Similar Mobile App Retrieval

## Problem
- Prior work dùng embedding-based retrieval cho app similarity: capture semantic/topical similarity nhưng fail identifying FUNCTIONALLY similar apps (apps user sẵn sàng chọn làm substitute — cùng user need). Ví dụ paper nêu: app học tiếng Tây Ban Nha vs app học tiếng Đan Mạch semantically related nhưng KHÔNG functionally similar (different user needs). Apps chia sẻ screenshot UI tương tự (password manager vs expense tracker list-based UI) vẫn khác purpose. Multimodal (screenshots/permissions/reviews/code-based) conflate functional với descriptive/behavioral similarity. Gap: chưa ai apply LLM-based filtering cho task này vì cost evaluating number lượng app pair lớn.

## Contribution
- ReFilter hybrid 2 stage: (1) Retrieve candidates semantically close bằng embedding (cosine similarity); (2) LLM-based contextual Filtering — đánh giá từng target-candidate pair là functional substitute hay không, kèm justification. Balances efficiency (embedding) + precision (LLM), tránh pairwise LLM evaluation toàn bộ corpus.
- Định nghĩa functional similarity = functional alternatives (user-facing purpose + same user need), không phải textual/market similarity.
- First study apply context-aware LLM filtering vào large-scale mobile app retrieval; replication package public: https://github.com/b-almulla/ReFilter.

## Method (tóm tắt cốt lõi)
- Data: scrape Google Play (Aug 2025), seed 34,364 apps; loại Game + Family; preprocess (non-English filter, remove privacy policy/subscription/contact noise, strip emojis, lowercase, remove HTML, loại description <200 chars + <100 downloads) → 20,635 apps, 48 categories.
- 6 embedding methods 2 modalities: text-only (BGE-AVG, BGE-FIRST = BGE-small-en-v1.5 chunked; Linq = Linq-Embed-Mistral full description no truncation), multimodal (SigLIP2-AVG, SigLIP2-TopN = so400m-long, Voyage AI Voyage-multimodal-3 unified). Cosine similarity, top-k candidates k ∈ {5,10,...,50}.
- Ground truth: 10 target apps × top-50 candidates mỗi method merged label-once → 1,315 pairs evaluation + 450 dev + 450 test (10 unseen categories, finalized prompt); 2 annotators 95% confidence/10% margin, Cohen's Kappa 0.79 (substantial), disagreements resolve → first author labels rest. Annotation rule: target's primary user-facing purpose trước, candidate có satisfy same need không; secondary-feature-only sharing = dissimilar (snoring app vs sleep-remedy app dissimilar trừ khi sleep-remedy cũng support snore recording).
- LLM filter: GPT-5 (paper typo "GPT-55"), feed k=45 candidates + descriptions, prompt functional-substitute verdict + justification; GPT-5 no temperature=0 → 3 runs averaged. 0-shot dev false negatives (75 cases) phân tích manual → 5 error categories → 2-shot examples chọn đại diện recurring challenges, không random.
- Metrics: Precision=TP/(TP+FP); Recall (conditional)=TP_LLM/TP_method (retention sau filter); Pooled recall=TP_method/union TP all-methods (recall = lower bound do pooling); F1 harmonic.
- RQ3: 1,156 target apps (15 largest categories, 95%/10% sampling); Kruskal-Wallis + Dunn post-hoc Holm; Wilcoxon signed-rank vs Google Play Similar Apps; K-Means yearly time series (silhouette → k=3).

## Key Findings
- RQ1: Linq highest precision, pooled recall, F1 across ALL k — LLM-based embedding model capacity quan trọng hơn pooling strategy; BGE-FIRST slightly > BGE-AVG (functional cues often EARLY trong description). Multimodal limited gains: screenshots introduce noise (interface layout không phản ánh function); SigLIP2-AVG > SigLIP2-TopN; Voyage > SigLIP2 tại k≥20 nhưng comparable/lower tại small k. Embedding-only modest: best F1 60% at k=45 (Linq); precision peak 86% tại k=5.
- RQ2 (test dataset, Table 2): few-shot config 0/2/4/6-shot — Precision 99/97/98/97%; Conditional Recall 74/84/84/84%; CR-F1 83/90/89/89%; Pooled Recall 61/70/70/70%; PR-F1 80/86/86/85%. 2-shot sweet spot: recall UP, precision minimal impact; beyond 2-shot flat/decline. LLM filtering precision 97% (vs embedding-only 86% tại k=5) và PR-F1 60%→86%. Output DYNAMIC count: 0 đến 45 apps/target — 1 test app không có substitute → model correctly return ZERO (robust no false positives).
- False negative 0-shot (75 cases, 5 categories): core feature secondary in candidate (28 — password manager vs authenticator có password mgmt function), same goal different implementation method (18 — Spanish learning app vs video-teaching approach), candidate fulfills part of core feature (11 — all-in-one astrology vs single horoscope/tarot/numerology), misidentified core feature (10 — offline vs cloud password manager), different purpose same core feature (8 — mute-communication TTS vs general TTS). Pattern: LLM avoids false positives nhưng overly conservative với functional overlap → few-shot covering recurring confusions improves recall.
- RQ3: category variation — Personalization/Social/Photography highest counts; Business/Tools/Sports fewer (design-driven categories dense clusters; utility distinct). Downloads: apps ít downloads hơn có significantly MANY similar apps — Kruskal-Wallis H=180.0, p<0,001, ε²=0,15; Dunn Holm-corrected 500+/1,000+ ranges > almost all higher ranges (p<0,001 most) — chủ yếu watch apps (near-identical variant clusters). Vs Google Play: Play mean ≈93 similar apps vs framework ≈21, Wilcoxon p<0,001, Play lớn hơn 1,031/1,156 apps — Play optimization discovery/engagement (quality, ratings, reviews, downloads, appeal, interaction), framework = functional equivalence, và framework đôi khi uncover relevant apps Play không surface.
- Temporal clustering (k=3 silhouette): Slow Linear Growth (normalized entropy 0,98, avg release 2019, diverse mature ecosystem); Early Rapid Growth (entropy 0,97, avg release 2016, established domains, alternatives emerge early then stabilize); Late Rapid Growth (entropy 0,82, Personalization-dominated, avg release 2022, template-driven ecosystems, repeated developers, growth after 2020).
- Cost: candidate retrieval one-time embedding cost; GPT-5 filtering ≈4,2 giây và $0,04 USD per target-app query (trung bình, 1,156 queries).

## Actionable Insights
- Semantic similarity ≠ functional similarity: embedding-only ceiling F1 60% → pipeline retrieve-then-filter cho user-facing recommendation: embedding recall (cheap) + LLM verdict "candidate có là substitute của target không" (precise). Ví dụ: feature "bài viết liên quan" trên blog — embed tất cả bài, cosine top-45, LLM filter 2-shot hỏi "reader của bài A có chấp nhận bài B làm thay thế không", F1 90% (conditional) thay vì 60%.
- Error-analysis-driven few-shot beats random examples: phân tích 75 false negatives 0-shot → 5 categories → chọn 2 examples cover recurring confusion; 2-shot optimal (recall 74→84%, F1 83→90%), 4/6-shot không gain. Ví dụ: khi build LLM filter cho product recommendation, trước hết đánh giá manual 50–100 failure cases, pick 2 examples cover top-2 recurring confusion patterns (undervalued secondary features; same goal different presentation).
- Dynamic count beats fixed top-k: LLM returns 0–45 similar apps (zero khi không có substitute — tránh forced false positives); density varies by category + popularity (watch apps near-identical clusters at low download). Ví dụ: hệ thống "sản phẩm tương tự" không hardcode "hiển thị 10 mục" — để LLM decide count per item, log distribution theo category.
- Text beats multimodal cho functional similarity: screenshots add noise (password manager vs expense tracker list UI); text-only LLM embedding (Linq full description) wins; BGE-FIRST > BGE-AVG → put core purpose EARLY in description. Ví dụ: viết mô tả sản phẩm/content, câu đầu tiên = user need cốt lõi, đừng đầu tư image embedding cho task similarity.
- Platform "similar" lists ≠ substitutes: Google Play mean 93 vs framework 21 (p<0,001, 1,031/1,156 larger) — discovery-oriented, không functional equivalence. Ví dụ: competitor analysis tự build substitute list, đừng tin "similar items" của marketplace (chúng tối engagement, không substitution).

## Assumptions & Limitations
- Điều kiện: functional-substitute definition cần annotation guideline rõ ràng (κ=0,79); preprocessing loại mô tả ngắn/low-download apps → bias về established quality apps; recall metrics relative to pooled union top-50 of all methods → recall là LOWER BOUND không absolute recall (paper thừa nhận).
- Paper thừa nhận: description có thể incomplete/falsely advertised/marketing-oriented; Google Play only — generalization sang Apple App Store chưa chứng minh; chỉ 20 target apps / 1,765 unique pairs manual eval → generalizability performance hạn chế; future work mở rộng categories/apps.
- [MY OWN]: ground truth = 2 annotators (first+second author) — self-validated, no independent third rater; GPT-5 filtering cost $0,04/query tại scale 1,156 queries = ~$46 total — affordable nhưng scales linear với query count; embedding stage choices (Linq) tied to Sept-2025-era models, model mới hơn có thể shift ranking; "functional similarity" definition assumes single primary purpose — multi-purpose apps boundary fuzzy (astrology example chính là boundary case).
