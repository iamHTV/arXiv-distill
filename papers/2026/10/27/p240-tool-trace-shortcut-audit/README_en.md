# [2610.25540] Auditing Tool Traces in Agentic LLMs: Source Localization and Counterfactual Dependence Testing

## Problem
- Agentic LLM pipelines (tool use / RAG / chained tool returns) have an evaluation failure mode that ordinary benchmark checks miss: serialized tool results can contain HIDDEN LABEL SHORTCUTS — entry identifiers, version strings, file paths, duplicated fields, template artifacts — that correlate with labels without carrying the intended scientific semantics (introduced by deposition, annotation, sampling, serialization). Such shortcuts survive semantic data splits because identifier generation does not follow scientific grouping. Screening only the concatenated tool trace also misses patterns confined to one component because heterogeneous results dilute them. Result: apparently rigorous performance may be shortcut exploitation, not evidence-grounded reasoning. Gap: no prior method separates (a) WHICH tool result carries the shortcut from (b) WHETHER the frozen LLM actually depends on it.

## Contribution
- Two-stage audit separating source localization from behavioral verification:
  - Stage 1 — PT2D (Per-Tool TF-IDF Decomposition): audit EACH tool section independently (TF-IDF + balanced logistic regression), keeping the concatenated trace only for comparison → overcomes the dilution effect.
  - Stage 2 — Token-Class Redaction: trace the suspect source and substrings to serialized fields, group values into token classes, redact the complete class in every prompt-bearing field, and re-evaluate the frozen LLM (counterfactual, no retraining) → tests model dependence.
- Dilution validation via real tool-subset sweeps and synthetic label-independent additions.
- Case-study overturn: an apparent evidence-grounded generalization (AUROC 0.8136 vs 0.4928 baseline) turns out to be a PDB-identifier shortcut — redacting identifiers collapses to chance.

## Method (core)
- Setup: Dfit/Deval audit partitions aligned with the evaluation protocol (split-agnostic); each example (xi, yi ∈ {0,1}, Ei = [e(1)i..e(T)i]) — a tool trace is the ordered collection of serialized tool results (distinct from a reasoning trace produced by the LLM itself).
- Stage 1: for each scope s ∈ {full, 1..T}: TF-IDF features ϕs (word 1–2-grams for lexical content, char 2–5-grams and char 3–5-grams for identifier fragments), balanced logistic regression gs on Dfit, score Deval → AUROC As. Carriers ranked by comparing At to full-trace scope, chance, and other tools — no universal threshold. No LLM retraining, no parameter access. Evidence is associational (a predictive pattern need not be used by the LLM).
- Stage 2: group suspect values sharing generating semantics into candidate token classes (entry identifiers, version strings, file-path components); target the COMPLETE class (an isolated TF-IDF n-gram covers only part of a shortcut-bearing value); redaction Rc replaces every occurrence in ALL prompt-bearing fields with a class-specific placeholder, preserving labels and reference answers; global replacement prevents duplicated values surviving elsewhere; one class at a time at a frozen checkpoint → ∆Ac = Aorig − ARc (positive = performance lost, ∆A = A_orig − A_redacted). Non-overlapping recurring classes serve as controls.
- Case study: binary TCR–pMHC binding, dataset Slone et al 2025 with peptide-disjoint cluster splits from Abeer et al 2026: cluster 0 = 12,940 training (3,483 positive) + 1,438 validation (397 positive); clusters 1–5 = 4,898 test (264 positive). Qwen3-4B fine-tuned on task fields + complete five-tool trace. Five fixed-order tools: (1) CDR3β biophysical descriptors (length, composition, charge, flexibility, contact potential); (2) McPAS-TCR retrieval and similarity; (3) ThermoMPNN mutation-level ∆∆G; (4) CDR3β positional stability and hotspots derived from (3), adapted from Biomni; (5) structure-based interface descriptors (buried surface area via FreeSASA, contact distance, hydrogen bonds, salt bridges). Tools receive candidate fields and the modeled complex, never labels.

## Key Findings
- Fine-tuned Qwen3-4B: Aorig = 0.8136 test AUROC (clusters 1–5 joint) vs label-balanced no-evidence baseline 0.4928 (development comparison) — at face value, evidence-grounded generalization.
- PT2D full-trace scopes near chance: Afull = 0.4818 (word 1–2), 0.4677 (char 2–5), 0.4876 (char 3–5) → full-trace screening reports little leakage (a false negative). Per-tool decomposition reverses this: Tool 3 (predict-thermompnn-ddg) reaches A3 = 0.6288 / 0.6365 with character features; Tool 5 (which also serializes the PDB identifier) is weaker at A5 = 0.5259–0.5310; Tools 1, 2, and 4 remain near chance. The char 3–5-gram gap A3 − Afull = 0.1489 shows aggregation hides a strong local signal.
- Logistic-regression weights localize the Tool 3 signal to PDB-ID fragments inside ThermoMPNN_inference_<pdb_id>.csv: word features stay at chance (A3 = 0.4946) while char features reach 0.6365 — the signal is identifier fragments, not biological language; prefixes such as "_21" favor binders and "_17" favor non-binders; a two-digit PDB-prefix lookup reaches AUROC 0.6967, motivating complete PDB-ID redaction.
- Dilution sweeps: progressively appending Tools 1, 2, 4, 5 to Tool 3 decreases the char 3–5-gram diagnostic AUROC monotonically from 0.6365 to 0.4876; label-independent synthetic additions reproduce the decay, reaching chance by K = 5 — explaining the full-trace false negative and motivating per-tool decomposition.
- Frozen-checkpoint redaction (Table 1): Original 0.8136; PDB-ID redacted 0.4972 → ∆APDB = +0.3163 (nearly all above-chance ranking performance eliminated → chance); Peptide redacted 0.8152 → ∆Apeptide = −0.0017 (control stable — rules out direct reuse of the literal epitope sequence). Together: TCR-task behavior depends on dataset-specific identifiers rather than the intended biological evidence.

## Actionable Insights
- "The agent uses the evidence" may just be identifier pattern-matching: tool augmentation looked excellent (0.81 vs 0.49 baseline) but removing PDB IDs collapsed it to 0.50. Example: before trusting that your RAG/support agent "utilizes retrieved data", redact suspected identifier classes (order IDs, ticket IDs, template tokens) from tool outputs and re-run — a performance collapse means shortcut-matching, not reasoning.
- Screen each tool result SEPARATELY, never only the concatenated trace — dilution hides shortcuts: full-trace TF-IDF ≈0.48 (chance) while the single carrier tool reached 0.64 (gap 0.1489; monotonic decay 0.6365→0.4876 when appending tools; synthetic decoys reproduce it). Example: for a 4-tool agent (search + CRM + calculator + scraper), run cheap TF-IDF + logistic-regression diagnostics PER TOOL OUTPUT FIELD; never trust whole-trace screening alone.
- The word-vs-character n-gram split fingerprints the shortcut TYPE: word at chance (0.4946) + char 2–5 spike (0.6365) means the signal lives in identifier fragments; top fragments ("_21" binders, "_17" non-binders, prefix lookup 0.6967) identify WHICH serialized field to sanitize. Example: when auditing agent tool outputs, a char-ngram spike localizing to a filename/ID pattern → anonymize that field immediately.
- The redaction protocol NEEDS a control class: peptide redaction ∆A = −0.0017 (stable) validates that the PDB collapse is specific, not generic redaction damage. Example: always redact one non-overlapping control class alongside the suspect class — a drop without a stable control proves nothing.
- Detection is cheap and model-agnostic: Stage 1 uses only TF-IDF + balanced logistic regression — no LLM retraining or parameter access, works on frozen checkpoints. Example: an auditable production-agent pipeline — a per-tool-result diagnostic classifier plus frozen re-evaluation with placeholders — can run in CI before publishing benchmark gains.

## Assumptions & Limitations
- Conditions: requires labeled audit partitions aligned with the evaluation protocol; tool results are serialized into text (serialization choices themselves can create artifacts); Stage 2 requires a frozen checkpoint with an identical generation/parsing/scoring pipeline.
- Paper-acknowledged: PT2D evidence is associational — a predictive text pattern need not be used by the downstream LLM; redaction may remove correlated signals or shift the input distribution, so conclusions are limited to model behavior; short-prefix attribution comes only from PT2D weights (redaction supports dependence on the complete class); the complete class is targeted because an isolated n-gram covers only part of a shortcut-bearing value.
- [MY OWN]: single domain (TCR–pMHC), single model (Qwen3-4B), single fine-tuning run — generalization to other agents/domains unproven; the logistic-regression diagnostic is LINEAR — non-linear shortcuts may evade (character n-grams partly compensate); peptide-disjoint splits are specific to biological benchmarking; "chance" is ~0.5 in a binary context — multi-class tasks need an appropriate chance baseline; numeric separators/serialization conventions differ per toolchain, so token-class definition needs domain knowledge; workshop paper (AgenticLS, NeurIPS 2026), not full peer review.
