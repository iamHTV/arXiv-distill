# [2609.28572] Where Cyber Agents Struggle: Bottleneck Analysis of Multi-Stage LLM Agents

## Problem
- Success rate đơn lẻ đối với multi-stage LLM agent che giấu 3 thứ: inefficiency (<nested... no — efficiency), adaptation qua retries, và recognition of success/failure. Agent có thể complete attack workflow nhưng vẫn brittle, costly, hoặc dựa trên interpretation sai của execution evidence. Final success indicator capture không distinction giữa (a) command execution thành công vs state cần thiết cho next stage đã establish chưa; (b) eventual success có conceal costly repetition không. Capability score (InterCode, CyBench) answer different question với diagnosis of persistent difficulty. Gap: chưa có framework tách resource consumption khỏi behavioral interpretation, và tách acting model khỏi orchestration + validation components quanh nó.

## Contribution
- Two-resolution framework nối resource localization với trajectory diagnosis:
  - Task-level (subtask-conditioned, cost-aware score): với shared expert-defined decomposition, z-normalize tokens/attempts/time per subtask across models → Bm(si) = α[z(tokens)]+ + β[z(N)]+ + γ[z(time)]+ ([z]+ = max(0,z)) — relative resource amplification, kể cả subtask eventual-success.
  - Trajectory-level: 5-judge LLM panel trên full trace → primary category + contributing bottlenecks + mechanism tags + severity + recovery assessment.
- Separation of primary bottlenecks, mechanisms, recovery, và framework contributions (validator/framework contributions recorded riêng, không mutually-exclusive category).
- Case study reveal scenario-dependent relation giữa scaffolding (expert-defined / self-scaffolded / fully autonomous) và diagnosed bottlenecks — S2 reverses thứ tự S1 gợi ý.
- Diagnostic, KHÔNG phải model ranking hay causality demonstration.

## Method (tóm tắt cốt lõi)
- Hệ thống Autonomous Adversary (framework Mamun et al. 2026): acting LLM = orchestrator (plans + execution context); cyber executor (chạy commands: shell/PowerShell, WMIC, Mimikatz, Caldera-agent deployment → trả stdout/stderr/exit status/tool responses/side effects); system validator (so evidence vs success criterion → continue/retry/submit/halt) — validator DÙNG SAME MODEL với acting agent; memory: plan history, actions, observations, validator decisions, outcomes; validator-accepted outcome KHÔNG independently verified.
- Môi trường: controlled range (segmented subnets, remote-admin services, root domain + subdomains, domain controllers, domain-joined workstations, security misconfigurations); KHÔNG active defender, KHÔNG detection penalty → results về planning/execution/state interpretation/recovery, không phải resilience chống adaptive defense.
- 2 lateral-movement scenarios: S1 (low-privilege workstation, active admin session; 9 expert subtasks: execution-context setup, agent deployment, credential acquisition, identity transition, protected-resource access, restoration); S2 (admin foothold trên jump server; 10 subtasks: intermediate workstation, credential recovery/reuse, writable DC resource, domain-admin execution, restricted-file retrieval, artifact removal).
- 6 acting models: Claude Opus 4.5, Sonnet 4.5, Gemini 3 Pro Preview, GPT-5.1, GPT-4o-mini, DeepSeek-V3.2-Speciale; cohort compare 4 models nhất quán nhất. 3 modes: E (human expert supply ordered subtasks + verification criteria — red-teaming expert đã solve thủ công), S (model tự generate subtasks + intermediate success criteria), A (objective + initial foothold info → recon + security-state representation + tự intermediate objectives/order).
- Selection: run có greatest judge-verified task progress per config (BEST-CASE observed, không average); token per-call reference 45,000 (input+output 1 call); Opus S2-A panel INC (provider cybersecurity safety filter block judge call) → excluded khỏi aggregates (missing data, không phải model failure); GPT-4o-mini omit some (structured output fail, little progress); DeepSeek omit some (provider errors).
- Trajectory judge panel (5 models qua OpenRouter): DeepSeek V4 Pro, GPT-5.6 Sol, Kimi K3, Gemini 3.6 Flash, GPT-5.6 Luna Pro; planning judge = GPT-5 Codex; validator-quality judge = Claude Sonnet 4.5. JSON schema (progress, categories, tags, Boolean recovery/contribution, severity 1–5, confidence 0–1 = metadata KHÔNG phải vote weight); temperature 0, ≤5,000 output tokens, ≤3 attempts; prohibitions: không infer credentials từ username, không auto-accept validator conclusion, không mistake superficial command variation for recovery.
- Aggregation: modal category set C(τ) = argmax nc(τ); support A(τ) = max nc/Jτ; ties EXPLICIT (unique mode có thể chỉ 2/5 votes, không nhất thiết majority); setting-level mean support; mechanisms/adaptation/contributions = nested descriptive counts, denominators KHÔNG phải sample size.
- 7 local planning labels (visible plan structure, không hidden reasoning): plan similarity; single-point dependency; over-specification; missing environmental probing; lack of recovery paths; tool misalignment; inefficient planning depth.
- Meaningful adaptation definition: changes operative hypothesis, resolves prerequisite, gathers discriminating evidence, changes dependencies, hoặc adopts substantively different strategy. Changing syntax/wrappers/tools/protocols/hostnames while preserving failed assumption = repetition, KHÔNG phải recovery.

## Key Findings
- Validator evidence assessment (S1, 19 successful + 18 unsuccessful explanation runs; judge = Claude Sonnet 4.5 với raw evidence + successful Opus 4.5 reference-run evidence — reference = semantic context, KHÔNG human ground truth): overall explanation-quality 0.79 (success) vs 0.84 (unsuccessful); evidence grounding 0.81 vs 0.90; specificity thấp 0.69 vs 0.68; cautiousness khác lớn 0.70 vs 0.92 → success explanations prone to overstatement khi evidence incomplete. Đánh giá explanations, KHÔNG phải success-classification accuracy; không có human reference labels.
- Task-level resource maps: S1 = several isolated high-score cells; S2 = repeated elevated scores + additional elevated cells (within-subtask relative patterns; blank cells = subtask agent never reached, KHÔNG zero; zero ≠ intrinsic ease — expensive subtask shared equally across models có no positive deviation). S2 heatmap chỉ 7/10 subtasks (no agent reached final three); GPT-4o-mini vắng mặt S2 (không complete subtask đầu). Difficult S1 cases → tool misalignment + fragile invocation structures; S2 thêm over-specification + missing environmental probing. Comparable resource scores nhận different diagnoses → localization + interpretation complementary.
- Trajectory diagnoses (23 completed cohort trajectories, 29 complete panels = 145 judgments):
  - S1-E: action execution unique modal cho Opus, Gemini, GPT-5.1 (support varies Gemini AE chỉ 2/5 vs GPT-5.1 5/5); Sonnet tie AE/PL. Diagnoses: command realization, quoting/escaping, credential-tool invocation, lateral-agent deployment.
  - S1-S: ALL FOUR planning-limited 4/5–5/5 support (khó constructing/validating dependencies khi decomposition model-generated; KHÔNG causal estimate).
  - S1-A heterogeneous: Opus recovery-limited (collected nhưng không operationalize credential artifacts); Gemini unanimous planning-limited (credentials + lateral payload ASSUMED rather than established); Sonnet planning 3/5; GPT-5.1 tie planning/framework (trace end before credential-inspection actions execute).
  - S2 reverses S1 ordering: S2-E Opus+Sonnet planning, Gemini recovery, GPT-5.1 planning/recovery tie (unverified credentials, share permissions, identity transitions); S2-S three trajectories AE majorities, Opus tie execution/planning — recurring blockage: agent deployment wrong executable, unresolved variables, placeholder commands, acceptance of process creation as evidence of operational callback; S2-A all three panels planning 3/5 (missing Opus panel → no complete 4-model conclusion).
- Mean modal support: S1-E 0.65, S1-S 0.90, S1-A 0.70, S2-E 0.65, S2-S 0.65, S2-A 0.60 — low support = substantive uncertainty (several plausible explanations), không reporting inconvenience.
- Deletion robustness: 12/23 completed cohort panels ≥4/5 support (survive removal of any one judge, includes all 4 S1-S panels); 11 panels lack guarantee — checks sensitivity to one deleted vote, not chance-corrected reliability/human correctness/repeated-run robustness.
- No meaningful adaptation: S1 5/20 (E) → 15/20 (S) → 20/20 (A); S2-E và S2-S all 20/20. Counterexample: S1-S Opus abandons unsuccessful credential extraction, switches to password spraying, completes objective.
- Mechanism frequencies (Table 5, all completed panels, non-exclusive): S1-E CCE 18/30 (command-construction error), UA 5/30, PRQ/SPD 3/30; S1-S UA 25/30, PRQ 20/30, SPD 11/30, IR 11/30; S1-A UA 15/25, PRQ 15/25, SPD 12/25, IR 8/25; S2-E UA 18/25, PRQ 13/25, IR 12/25; S2-S CCE 13/20, UA 12/20, PRQ 9/20; S2-A UA 13/15, PRQ 13/15, SPD 6/15. Recurring interpretation: credentials của one domain identity assumed to authenticate different domain identity; changing execution tools preserves unresolved dependency.
- Mean severity 4.03–5.00 (thang 5) across settings. Validator/framework contributions trong 72–100% judgments (S1-A 18/25): accepting file/process creation or echoed output as evidence of successful execution; advancing with unverified identities; terminating without effective recovery path; failing to retry malformed model outputs → check surrounding execution loop, không chỉ acting model.

## Actionable Insights
- Success rate đơn lẻ nói dối: agent complete workflow nhưng vẫn brittle/costly/wrong-evidence. Evaluate 4 axes đồng thời: outcomes, evidence interpretation, resource use, adaptation after failure. Ví dụ: content-ops agent — đừng track "tasks done"; log per-stage tokens/attempts/time, validator verdicts, và retry có change strategy (meaningful adaptation) hay chỉ rephrase (repetition).
- Repetition ≠ recovery: đổi syntax/wrappers/tools/hostnames mà keep failed assumption = không adaptation. Meaningful adaptation = change operative hypothesis / resolve prerequisite / gather discriminating evidence / change dependencies / adopt substantively different strategy. Ví dụ: agent log flag retry loops giữ same root assumption (retry same API với headers khác) — burn budget không progress.
- Autonomy level changes bottleneck LOCATION: expert-defined → execution errors (command realization, quoting/escaping, credential-tool invocation); self-scaffolded → planning limits (dependency construction); fully autonomous → planning + recovery spread, variation grows (S1-A/S2-A heterogeneous, support 0.60–0.70). Ví dụ: agent có fixed playbook → audit command/tool execution; agent tự plan → audit plan construction + dependency validation — audit khác nhau per autonomy level.
- Validators optimistic + nonspecific: quality 0.79–0.84, grounding 0.81–0.90 nhưng specificity chỉ 0.68–0.69; cautiousness success 0.70 vs failure 0.92 — success verdict overstate khi evidence incomplete; validator-accepted ≠ independently verified (accepts file/process creation or echoed output = success evidence). Ví dụ: "done" check phải verify observable end-state (post thật sự xuất hiện trong CMS) không Agent claim (process started); success report yêu cầu specific evidence.
- Bottlenecks CLUSTER ở dependency-heavy stages (credentials, identity transitions, lateral movement → tổng quát: unverified prerequisites, single-point dependencies, unsupported assumptions). Self-scaffolded/autonomous: unsupported assumptions dominate (25/30, 13/15); expert-guided: command-construction errors dominate (18/30, 13/20). Ví dụ: pipeline agent — add prerequisite-validation gates giữa các stage (stage kế không start nếu prior outputs chưa verified), đặc biệt khi agent tự plan stages.
- Judge panels expose uncertainty: unique modal category có thể chỉ 2/5 votes; mean support 0.60–0.90; low support = substantive uncertainty — don't force single root cause; deletion check (≥4/5 survive drop 1 judge) trước khi act on diagnosis. Ví dụ: auto-diagnose failures bằng LLM judges → report vote distribution + support, not just "the cause is X".
- Severity cao (mean 4.03–5.00/5) ngay cả best-case trajectories + framework contributions 72–100% → fix execution loop (validator criteria, observability, retry policy) cùng model, không chỉ prompt model.

## Assumptions & Limitations
- Điều kiện: shared expert-defined decomposition mới cho task-level z-normalization (agent-generated subtask indices KHÔNG comparable across agents); mỗi setting cohort cần ≥2 models có valid observations; validator = same model as acting agent (comparisons concern combination); environment không có active defender.
- Paper thừa nhận: diagnostic evidence from SELECTED high-performing trajectories (best-case), KHÔNG estimates model-level failure prevalence; 2 scenarios 1 environment; LLM-judge agreement ≠ independent human validation; incomplete coverage (Opus S2-A INC, GPT-4o-mini/DeepSeek omissions) + best-trajectory selection limit within-model variability conclusions; framework contributions KHÔNG quantify how much improvement a different validator would produce; mechanism counts non-independent (denominators ≠ sample size); no causal estimate of scaffolding effect; no budget-effect isolation (token reference 45k/call chosen, not studied); no statistically validated score–severity relationship.
- [MY OWN]: cost-aware score cohort-dependent (weights α=β=γ=1 arbitrary, no sensitivity study) — absolute B values không transferable sang team/model khác; 45k token reference may truncate và truncation confound attempt counts; single-environment controlled range (no defender) khác production SOC; pentest-domain agent results transfer sang benign agent pipelines only qua framework abstraction, không qua specific bottleneck map; 5-judge panel qua OpenRouter models names (DeepSeek V4 Pro, GPT-5.6 Sol/Luna Pro, Kimi K3, Gemini 3.6 Flash) rất mới — reproducibility depends on availability; confidence 0–1 không calibrated.
