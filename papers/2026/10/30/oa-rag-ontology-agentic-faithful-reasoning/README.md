# 2610.36335 OA-RAG: Ontology-based Agentic RAG for Faithful LLM Reasoning

## Problem
- RAG (retrieval-augmented generation — tạo nội dung nâng cường bằng truy xuất) hiện tại chủ yếu lấy text chunk rồi để LLM (large language model — mô hình ngôn ngữ lớn) tự reason (lập luận) từ retrieved text (văn bản đã truy xuất). Lỗ hổng: logical relationship (quan hệ logic hình thức) giữa các khái niệm bị bỏ qua, kết luận rely (dựa) nặng vào parametric knowledge (kiến thức tham số) của LLM → answer faithfulness (mức độ trung thực của câu trả lời với nguồn kiến thức) không được kiểm soát, dễ hallucination (ảo tưởng — câu trả lời có vẻ hợp lý nhưng sai).
- Prior work (công trình trước) chưa giải quyết được: (1) ontology (bản thể học — biểu diễn hình thức khái niệm + quan hệ theo Semantic Web standard) chứa CẢ formal axiom (tiên đề hình thức, logic mô tả Description Logic dưới OWL — Web Ontology Language) lẫn informal annotation (chú thích phi hình thức: định nghĩa, đồng nghĩa, comment), nhưng các hệ thống chỉ khai thác một trong hai; (2) không biết trước câu hỏi cần pattern (mẫu suy luận) nào — formal reasoning hay ontology-grounded hay ontology-assisted — nên không có hệ thống nào adaptive select (chọn thích ứng) giữa ba pattern và report mức độ grounding (neo bằng chứng) của từng câu trả lời.

## Contribution
- OA-RAG: agentic framework (khung phương pháp tác tử) đầu tiên kết hợp formal OWL reasoning với LLM reasoning. Với mỗi câu trả lời, nó report ontology observation (quan sát ontology dùng làm bằng chứng) kèm grounding level (mức độ neo) gồm 4 bậc: entailed (được chứa logic), supported (được hỗ trợ nhưng không chứa chặt), related (chỉ liên quan), unrelated (không liên quan).
- Formulate (hình thức hóa) 3 reasoning pattern theo bậc faithfulness giảm dần, và xây benchmark QA tự động từ 3 ontology quy mô lớn (GO, FoodOn, SNOMED CT) cho 2 pattern đầu.
- Số liệu cốt lõi: vượt strongest baseline (đường cơ sở mạnh nhất) 10–15 điểm phần trăm trung bình trên Test 1–2 (44.3% vs 28.9% với Llama-3-8B-Instruct; 59.7% vs 49.7% với Qwen3.5-9B); Test 3 (ontology-assisted) vẫn competitive (cạnh tranh) trong khi dùng 10× ít token hơn baseline mạnh nhất (9.7k vs 96.7k token/question với Qwen3.5-9B).

## Method (tóm tắt cốt lõi)
- Stage 1 — pre-tool reasoning (suy luận trước công cụ): LLM lập luận chỉ từ ngữ cảnh đầu vào + parametric knowledge, tạo preliminary answer (câu trả lời tạm, draft ỹ) nếu thông tin đủ.
- Stage 2 — ReAct loop (vòng hành động–quan sát): agent prompt giới thiệu ontology tool; mỗi action là SPARQL query (truy vấn ngữ nghĩa) lên ontology service: DESCRIBE "A" (lấy concept card — thẻ khái niệm: tên, định nghĩa, parents, children, stated relations, annotations); ASK {"A" "r" "B"} (kiểm tra subsumption O |= A ⊑ ∃r.B có entailed bởi ontology reasoner — bộ suy luận hình thức — không; open-world assumption — giả định thế giới mở — nên Not Entailed không nghĩa là false); SELECT (lấy concept/relation thỏa điều kiện). Query fallback (lùi truy vấn): SELECT rỗng → so sánh với concept card bằng BM25 lấy top-k candidate. Name linking (liên kết tên): exact match (khớp chính xác) → ambiguous (mơ hồ, trả candidate để disambiguate — gỡ mơ hồ) → unknown-name fallback (BM25 pool 200 tên, rerank bằng string similarity, top-5 gợi ý sửa query).
- Stage 3 — answering (trả lời) 2 bước: (1) lọc observation thất bại/rỗng → evidence digest (bản tóm tắt bằng chứng) E; câu trả lời ŷ = M(P_fin, q, E, ỹ) nếu E ≠ ∅, ngược lại M(P_own, q) — parametric knowledge; (2) attribution turn (lượt gán nguồn): prompt P_att lấy cited evidence Ĉ ⊆ E (bằng chứng được trích dẫn) + grounding level ĝ. ## Key Findings
- Dataset: 3 ontology (GO, FoodOn, SNOMED CT), mỗi ontology 300 MCQ (câu hỏi trắc nghiệm) + 200 OQ (câu hỏi mở). Test 1 (formal reasoning) 1,500 câu hỏi trên source ontology; Test 2 (ontology-grounded LLM reasoning) 1,477 câu hỏi trên revised ontology; Test 3 (ontology-assisted) 6,781 câu hỏi từ MedQA, USMLE Step 1/2/3, MedMCQA, PubMedQA (SNOMED CT làm ontology nền), theo experimental setup của OntoTune.
- OA-RAG đạt best average accuracy (độ chính xác trung bình tốt nhất) với cả 2 backbone (mô hình nền): 50.5% Llama-3-8B-Instruct và 68.1% Qwen3.5-9B trên toàn bộ 5 setting (cấu hình) test.
- Test 1–2 trung bình: 44.3% vs 28.9% strongest baseline (+15.4 điểm, Llama); 59.7% vs 49.7% (+10.0 điểm, Qwen). OntoTune-sft/sft+dpo (fine-tuning — tinh chỉnh — ontology) chỉ cải thiện nhẹ OQ (7.8%→11.2% Test 1); MedRAGdoc và i-MedRAGdoc (medical RAG — RAG y khoa) thua base model trên OQ cả 2 backbone.
- Test 3: OA-RAG Qwen 84.9% với context window (cửa sổ ngữ cảnh) 8,192 token; i-MedRAGdoc(262k token) cần 22 vs 5.8 LLM call (lời gọi mô hình), 96.7k vs 9.7k token/question (10×), retrieved text (văn bản truy xuất) ~66× lớn hơn, generate (sinh) ~5× token; cùng cửa sổ 8,192 token i-MedRAGdoc giảm xuống 66.7% vs 84.9% của OA-RAG. RAGont(text) beat RAGdoc(text) cả 2 backbone → ontology là retrieval source (nguồn truy xuất) cô đọng hơn textbook.
- Grounding level làm signal (tín hiệu) reliability (độ tin cậy): entailed+supported chiếm 70.0% (Llama) / 53.2% (Qwen) câu hỏi, unrelated chỉ 0.2%/7.8%. Qwen Test 3: entailed 94.9% correct, supported 82.1% (2 bậc này chiếm 39.7% câu hỏi) vs 72.1% remaining (còn lại) → bậc grounding cao hơn accuracy (độ chính xác) cao hơn.
- Evidence retrieval (truy xuất bằng chứng) là bottleneck (nút cổ chai) chính: fully retrieved gold evidence 61.7% MCQ vs 23.6% OQ; khi evidence đã retrieved thì 95.1–98.4% MCQ / ≥77.8% OQ được cite (trích dẫn) vào câu trả lời; Qwen retrieve mạnh hơn Llama rõ rệt.
- Ablation (nghiên cứu loại bỏ thành phần), average Qwen: OA-RAG đầy đủ 68.1% → bỏ ReAct loop 52.6% (−15.5) → bỏ answering step 65.2% (−2.9) → bỏ query fallback 67.7% (−0.4). Llama: 50.5% → 36.7% (−13.8) → 44.7% (−5.8) → 48.7% (−1.8).
- Case study (nghiên cứu trường hợp): pre-tool answer plausible (có vẻ hợp lý) nhưng sai do loose association (liên kết lỏng lẻo) — ontology relation trực tiếp sửa: Halothane hepatitis → causative agent (tác nhân gây) halothane (đổi E→A); blind staggers → altLabel (nhãn thay thế) của Selenium poisoning (đổi D→C).

## Actionable Insights
- Pattern "draft trước – verify sau bằng structured source" (nguồn có cấu trúc): sinh nháp từ knowledge nội bộ rồi kiểm chứng bằng graph/ontology sản phẩm trước khi xuất bản. Áp dụng: bot FAQ khách hàng soạn nháp LLM rồi chạy check DESCRIBE/ASK-style trên catalogue sản phẩm có cấu trúc trước khi gửi câu trả lời.
- Gắn grounding level 4 bậc vào mỗi câu trả lời để UI (giao diện) hiển thị độ tin cậy; chỉ auto-publish (tự động xuất bản) câu entailed/supported, route (đưa) related/unrelated vào review human (duyệt người). Áp dụng: pipeline content fact-check (kiểm chứng sự thật) gắn nhãn bậc neo cho từng claim (khẳng định) trong bài viết.
- Ontology làm retrieval source cô đọng 10× token so với textbook chunk → cost optimization (tối ưu chi phí) cho Q&A domain (lĩnh vực) có schema (lược đồ) có cấu trúc. Áp dụng: thay RAG doc chunk bằng concept card (thẻ khái niệm) cho catalog sản phẩm/dịch vụ, giảm ~10× token/câu hỏi.

## Assumptions & Limitations
- Điều kiện method work: phải có ontology OWL chất lượng + reasoner runtime (môi trường chạy bộ suy luận); domain thiếu ontology chuẩn thì không áp dụng được — paper chỉ đánh giá trên biomedical/healthcare.
- Paper thừa nhận: grounding level là self-assessment (tự đánh giá) của model — "không có formal guarantee (bảo đảm hình thức) về correctness"; open-world assumption: ASK trả Not Entailed không có nghĩa sai vì ontology có thể incomplete (không đầy đủ) (đã instruct model trong prompt).
- Chỉ test 2 backbone 8–9B (Llama-3-8B, Qwen3.5-9B), context cap 8,192 token; không so sánh frontier closed model (model đóng tiên tiến nhất).
- Limitation paper KHÔNG nói: retrieval bottleneck trên OQ (23.6% fully retrieved) vì definition-heavy information (thông nặng định nghĩa) kém accessible với retrieval; single ontology (đơn ontology) mỗi hệ thống — future work mới là agentic web (mạng tác tử) multi-ontology (đa ontology) cross-domain (liên lĩnh vực); concept-card BM25 fallback có thể nhiễu noise (nhiễu) khi ontology nhỏ.
