# 2610.35083 Ask Before You Answer: A Question-Driven Evidence Reasoning Architecture (QERA) for In-Context Learning

## Problem
- AI assistants increasingly reason over a user's own web traces: group chats, community threads, activity logs, revision histories. On CL-bench Life — a benchmark of 405 such tasks with 5,348 human-written rubrics — frontier LLMs solve fewer than one task in five (at the benchmark's release, the best of ten frontier LLMs solved 19.3%, the average 13.8%).
- Gap prior work has not addressed: "the request is not the specification." Over 80% of the benchmark's rubrics share less than 60% of their content words with the final request — they test a rule set two turns earlier, a later message correcting a fact, EVERY record meeting the user's criterion, the person behind each claim. Answering directly, the four LLMs in the study pass 81.1% of explicit rubrics (≥60% content words present in the request) but only 67.4% of implicit ones; 4,352 of 5,333 classifiable rubrics (82%) are implicit. Prior work (CCA, Ctx2Skill, PSCI) either organizes the context's knowledge or induces a specification contract using rubric-style demonstrations from other tasks — none turns the request into typed questions about the context and reuses those questions to check the answer against quoted evidence.

## Contribution
- QERA (Question-driven Evidence Reasoning Architecture): "ask before you answer." A 4-stage pipeline — Ask → Answer → Check → Guarded Repair — using the SAME frozen LLM with ~3–4 calls per task, no training, no rubrics, no demonstrations, task-agnostic prompts.
- Ask returns a requirement checklist O (average 4.2 per task: the user's words verbatim, scope, kind — list/count/compare/infer/write — format, required strings, exclusions, layout of an earlier edited reply) plus typed information needs N (7.6 per task: lookup/enumerate/count/compute/compare/judge). Faithfulness filters Φ implemented in CODE (not LLM) remove every part unsupported by the user's words (exclusions quoting absent words, unrequested formats, never-set date windows, stale templates) and add coverage needs for list/count/timeline/summary/classification requirements (12–16% of tasks).
- Core numbers: highest solving rate on ALL four frontier LLMs (Kimi K3, Grok 4.7, GLM-5, GPT-6-Luna) and in every context category; average 21.0% vs 18.2% for the strongest baseline (PSCI) vs 14.6% for Vanilla (direct answering) — a relative gain of 15% and 43%; rubric pass rate 75.6% vs CCA 73.5% vs Vanilla 69.9%.

## Method (core summary)
- Ask (one structured JSON call): O = requirements, N = needs; Φ turns them into questions Q (7.8 needs per task after filtering). Question types: enumerate 47%, lookup 28%, judge 13%, compare 5%, compute 4%, count 3%.
- Answer: draft y-tilde = M(x, π, Q) — ONE call over the WHOLE conversation (no retrieval, so no evidence loss); Q is advisory only, the user's words and materials override it. Fixed answer protocol π: (i) read every relevant part including later corrections; (ii) give the specifics the materials provide, not category words; (iii) include every qualifying item, with no self-imposed threshold; (iv) open yes/no/count/ranking answers with a committed verdict; (v) show the inputs of every total, share or rate; (vi) keep attributions, format, length, language and exclusions, with no disclaimers.
- Measure (code): m = word/sentence/item counts, user limits, missing strings/headings, excluded items.
- Check (one structured call): answer every question in Q again against the draft and the whole conversation → E: a verdict (pass/partial/fail) plus a quote of the draft per requirement; findings (a fact + a quote under 25 words + its location; one per item for enumerate/count, one per input for compute); status (correct/missing/incomplete/wrong/not applicable); latent gaps, unsupported facts, format violations, an edit plan of at most 12 edits. Three rules keep the check from doing harm: a count is wrong only if the check names the item missed or added; a requested inference resting on stated evidence is not unsupported; no edit may hedge a committed answer.
- Audit (code): findings whose quote does not occur in the conversation are flagged and the repair may not rely on them; typed needs are recomputed (lookup: measured lengths/counts, required strings, exclusions; enumerate: one finding per item; count: count = number of items; compute: inputs' sum/average equals the result; compare: facts on each side the draft never names; judge: quotes + found values). E† = actionable items + audit findings + missing required strings / excluded items / leaked labels in m. If E† is empty, return the draft.
- Repair (one call): patch ONLY what E† flags — apply fixes with the check's facts and quotes, skip fixes the materials contradict, keep definite answers definite, propagate changed numbers, preserve the rest.
- Guard Γ (deterministic code): the patch must be non-empty and not cut off; unless a length fix was requested it keeps at least half the draft's length and 30% of its numbers; it adds no year outside the conversation; and it keeps every word limit, count, required string and exclusion the draft met — otherwise keep the draft y-tilde. A final code pass restores quotations to their source text.

## Key Findings
- Setup: all 405 CL-bench Life tasks (404 contexts, 5,348 rubrics, 13.2 rubrics per task on average; 59.8% of tasks multi-turn); contexts average 19.4K tokens, up to 170.8K. Judge: GPT-5.1 at high reasoning effort, validated at >90% accuracy (manual check of 100 samples), agreeing with Claude Opus 4.6 at 93.2% and Gemini 3.1 Pro at 93.0% (Cohen's κ 0.72/0.71). 4 of 8,100 runs failed on API errors. Paired bootstrap 95% intervals; pooled over 1,620 task–LLM pairs. No method observes rubrics; QERA uses a single task-agnostic prompt set for every task and LLM.
- RQ1: QERA ranks first on all four LLMs; pooled lead significant against every baseline on both metrics (Holm-corrected adjusted p ≤ 0.014): Δ solving vs Vanilla +6.4 [+4.3, +8.5], CCA +2.9 [+0.9, +4.9], PSCI +2.8 [+0.7, +4.9], Ctx2Skill +3.5 [+1.5, +5.6]; Δ rubric vs Vanilla +5.6 [+4.5, +6.8], CCA +2.1, PSCI +2.4, Ctx2Skill +3.1. First in 24 of 32 per-LLM columns.
- Cost: QERA sits on the accuracy–cost Pareto front: 10–26% fewer tokens than PSCI (112k–131k vs 137k–177k per task) and fewer calls (3.8–4.0 vs 5); Ctx2Skill spends 2.4M–3.1M tokens and over 150 calls per task (multi-agent self-play that cannot amortize for a single-task context) — QERA uses 4–5% of those tokens while solving more tasks on every LLM; CCA is cheaper (63k–72k tokens) but solves fewer tasks on all four; ~5× Vanilla's token cost buys a 43% relative solving gain. QERA's median reply (4.7k characters) is shorter than CCA's (6.0k) and PSCI's (4.8k) — the lead is not reply length (CCA on Grok 4.7 has a median of 11.1k characters, 2.4× QERA, and two thirds of CCA's rubric gap there comes from 67 tasks where its reply is >4× longer).
- RQ2 (cumulative ablation on GPT-6-Luna, Table 4): the answer protocol alone lifts solving from 12.1% to 17.0% (+4.9 [+1.7, +8.1]) and rubric pass by +3.8 [+2.0, +5.7] for 3k extra tokens; the request-specific questions add +1.6 rubric points [+0.1, +3.2] (checklist +1.1, information needs +0.5) and raise solving from 17.0% to 18.8%. Stages before the answer deliver 5.4 of QERA's 6.1-point rubric gain over Vanilla on GPT-6-Luna and 6.4 of its 7.4-point gain on implicit rubrics, while explicit-rubric pass stays within 80.2–81.5% across all five cumulative rows. Check & repair only refine numeric requirements: on rubrics mentioning numbers or counts (47% of all rubrics) they add +0.9 [+0.1, +1.8] pooled and leave the rest unchanged (−0.3 [−0.9, +0.3]); overall rubric +0.7 on GPT-6-Luna, +0.4/0.0/+0.1 on Kimi K3/Grok 4.7/GLM-5; pooled solving −0.6 [−1.9, +0.7], not significant; the check consumes 51–56% of QERA's tokens. A generic self-refinement reaches a similar rubric pass rate (73.2% on GPT-6-Luna) with 82k vs 123k tokens. The guard rejects 27 of 1,385 repairs (patches that would drop most specifics, come back empty or be cut off). QERA's two-call draft (54k–64k tokens) already solves more tasks than every baseline on every LLM.
- RQ3: On explicit rubrics all five methods lie within 1.4 points (81.1–82.5%) and QERA ties the best baseline (−0.1 vs PSCI). On implicit rubrics (82% of classified rubrics) QERA passes 74.0%: +2.5 [+1.4, +3.6] over the best baseline (CCA) and +6.6 [+5.3, +7.9] over Vanilla; baselines gain 3.1–4.1 over Vanilla on implicit rubrics. The lead holds in every lexical-overlap band below 60% (+2.1/+2.7/+2.3 points) and ties at ≥60%. QERA is best in every context-length quartile (+1.2–1.8 over that quartile's best baseline; all methods lose 1.1–4.3 points from shortest to longest quartile, QERA 2.6). Highest average in all three context categories: rubric 76.8% vs CCA's 74.7% in Communication & Social Interactions; solving 19.8% vs 16.5% in Fragmented Information & Revisions; smallest lead in Behavioral Records & Activity Trails. Across 36 LLM×subcategory combinations QERA has the highest rubric pass in 20 (PSCI 8, CCA 6, Ctx2Skill 3, Vanilla 0, one tie). What the questions capture: earlier-turn rules (the chess task — Kimi K3's and Grok 4.7's checklists carry the rule forward and both solve it, while Vanilla writes algebraic chess notation with all four LLMs) and complete enumerations (47% of needs ask for EVERY item meeting the user's criterion). Headroom: numbers and counts remain hardest — QERA passes 71.4% of rubrics mentioning numbers or counts vs 79.2% of others; Behavioral Records rubrics are 71% numeric (41%/32% elsewhere), where QERA's lead over PSCI is smallest (21.1% vs 20.7% solving; 73.0% vs 72.4% rubric).

## Actionable Insights
- "Interview the context, not the user": before writing the final reply, turn the request into a requirement checklist plus typed information needs and answer THOSE first — apply immediately to any assistant summarizing a user's own group chats or logs: e.g., a bot summarizing a 3-month Telegram thread runs one JSON Ask call to recover a rule set two turns earlier ("quote prices in USD") and an enumerate need ("every pricing decision") before drafting.
- The fixed answer protocol π (six rules: read everything including later corrections; specifics not category words; every qualifying item; committed verdict; show inputs of every total; keep attributions/format, no disclaimers) is a reusable prompt template — e.g., drop the six rules into the system prompt of any report-generation pipeline over log data, no code needed.
- The post-answer check is only a numeric refinement (51–56% of tokens): when cost matters, run the 2-call draft (Ask + Answer) alone, which already beats every baseline; enable Check/Repair only for tasks with numbers/counts. E.g., a customer Q&A dashboard uses draft-only for everyday queries and the full pipeline for aggregate-number queries.

## Assumptions & Limitations
- Conditions for the method to work: the whole conversation (19.4K tokens on average, up to 170.8K) must fit in every call's context window — QERA uses no retrieval and keeps the entire conversation in each call; contexts exceeding the model's window cannot be processed as-is.
- Acknowledged by the paper: the pipeline is all-LLM — the same LLM writes the checklist and needs, answers them, and checks its own answer; code keeps the questions faithful and verifies every quote, but the LLM can still hallucinate or misread messy context (missing a rule stated turns earlier, misjudging which records meet a criterion), and such errors carry into the answer; question quality depends on the underlying LLM's capability, and different LLMs ask somewhat different questions; the judge is also an LLM (validated, but individual verdicts can be wrong); ~5× the tokens of direct answering; text-only — photos, screenshots, voice messages and videos are not covered; ethics: the conversation is sent to the LLM provider, so a deployment inherits the provider's data-retention terms (locally hosted LLMs avoid this); consent and data governance for personal traces remain with whoever deploys the system.
- Limitations the paper does NOT state: the implicit/explicit rubric split uses a lexical proxy (≥60% content words) that can misclassify borderline rubrics; a single judge model (GPT-5.1) grades every method (method bias if the judge prefers QERA's format — partly controlled since the judge never sees the method); the solving rate is only 21.0%, so "best among compared" does not mean "good enough in practice"; only high-effort reasoning models were evaluated — behavior on non-reasoning models is unknown.
