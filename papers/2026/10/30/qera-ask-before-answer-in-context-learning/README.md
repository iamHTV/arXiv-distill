# 2610.35083 Ask Before You Answer: A Question-Driven Evidence Reasoning Architecture (QERA) for In-Context Learning

## Problem
- AI assistant ngày càng phải reason (lập luận) trên web traces (dấu vết web) của chính user: group chat (trò chuyện nhóm), community threads (chuỗi diễn đàn), activity logs (nhật ký hoạt lượng), revision histories (lịch sử sửa đổi). Trên CL-bench Life — benchmark (tiêu chuẩn đánh giá) 405 task (nhiệm vụ) dạng này với 5,348 rubric (tiêu chí chấm) do người viết — frontier LLM (mô hình ngôn ngữ lớn tiên tiến nhất) giải được DƯỚI 1/5 task (lúc phát hành benchmark, tốt nhất 19.3%, trung bình 13.8%).
- Gap prior work (công trình trước) chưa giải quyết: "the request is not the specification" (yêu cầu không phải đặc tả). Trên 80% rubric của benchmark chia sẻ DƯỚI 60% content words (từ nội dung) với final request (yêu cầu cuối) — rubric kiểm tra rule (quy tắc) user đặt 2 lượt trước, message sau sửa một fact (sự thật), MỌI record (bản ghi) thỏa criterion (tiêu chí), người đứng sau mỗi claim (khẳng định). Trực tiếp trả lời, 4 LLM trong nghiên cứu pass 81.1% explicit rubric (rubric tường minh — ≥60% content words có trong request) nhưng chỉ 67.4% implicit rubric (rubric ngầm). 4,352/5,333 rubric phân loại được (82%) là implicit. Prior work (CCA, Ctx2Skill, PSCI) hoặc tổ chức knowledge của context, hoặc induce contract (rút ra hợp đồng đặc tả) cần rubric-style demonstration (minh họa) từ task khác — không ai biến request thành typed questions (câu hỏi có kiểu) về context và tái sử dụng chúng để kiểm tra câu trả lời với evidence (bằng chứng) được trích dẫn.

## Contribution
- QERA (Question-driven Evidence Reasoning Architecture — kiến trúc suy luận bằng chứng điều khiển bằng câu hỏi): "ask before you answer" (hỏi trước khi trả lời). Pipeline 4 stage (giai đoạn): Ask → Answer → Check → Guarded Repair, dùng CÙNG một frozen LLM (mô hình đóng băng — không đổi weights (trọng số)) ~3-4 call (lời gọi)/task, no training, no rubrics, no demonstrations, prompt task-agnostic (không phụ thuộc task).
- Ask trả về requirement checklist O (trung bình 4.2/task: user's words verbatim, scope (phạm vi), kind (kiểu: list/count/compare/infer/write), format, required strings, exclusions, layout của reply trước) + typed information needs N (7.6/task: lookup/enumerate/count/compute/compare/judge); faithfulness filters Φ bằng CODE (không phải LLM) loại bỏ mọi phần không được user's words support (loại trừ trích dẫn từ vắng mặt, format không yêu cầu, date window user không đặt, stale template) và bổ sung coverage cho requirement list/count/timeline/summary/classification (12–16% task).
- Số liệu cốt lõi: solving rate (tỷ lệ giải quyết) cao nhất trên CẢ 4 frontier LLM (Kimi K3, Grok 4.7, GLM-5, GPT-6-Luna) và mọi context category; trung bình 21.0% vs 18.2% PSCI (baseline (đường cơ sở) mạnh nhất) vs 14.6% Vanilla (direct answering) — relative gain (lợi thế tương đối) 15% và 43%; rubric pass rate 75.6% vs CCA 73.5% vs Vanilla 69.9%.

## Method (tóm tắt cốt lõi)
- Ask (1 structured JSON call): O = requirements, N = needs; Φ biến thành questions Q (7.8 needs/task sau lọc). Question types (kiểu câu hỏi): enumerate 47%, lookup 28%, judge 13%, compare 5%, compute 4%, count 3%.
- Answer: draft ỹ = M(x, π, Q) — MỘT call trên TOÀN conversation (không retrieval → không mất evidence); Q chỉ mang tính advisory (tham khảo), user's words và materials ghi đè lên Q. Fixed answer protocol π (cố định): (i) đọc mọi phần liên quan gồm cả corrections (sửa lỗi) ở lượt sau; (ii) cho specifics (chi tiết cụ thể) materials cung cấp, không dùng category words (từ loại); (iii) gồm MỌI qualifying item (mục đủ điều kiện), không tự đặt threshold (ngưỡng); (iv) yes/no/count/ranking mở bằng committed verdict (phán quyết dứt khoát); (v) show inputs của mọi total/share/rate; (vi) giữ attributions (gán nguồn), format, length, language, exclusions, không disclaimer (từ từ chối trách nhiệm).
- Measure (code): m = word/sentence/item counts, user limits, missing strings/headings, excluded items.
- Check (1 structured call): trả lời lại MỌI câu Q against draft + toàn conversation → E: verdict (pass/partial/fail) + quote of draft cho mỗi requirement; findings (fact + quote <25 words + location; 1/item cho enumerate/count, 1/input cho compute); status (correct/missing/incomplete/wrong/N/A); latent gaps, unsupported facts, format violations, edit plan ≤12 edits. 3 rules chống hại: count chỉ sai nếu check nêu item missed/added; inference dựa stated evidence không phải unsupported; không edit nào hedging (mơ hồ hóa) committed answer.
- Audit (code): findings có quote KHÔNG xuất hiện trong conversation x → flagged (đánh dấu), repair không được dựa vào; recompute typed needs (lookup: đo độ dài/đếm, required strings, exclusions; enumerate: 1 finding/item; count: count = #items; compute: inputs sum/average = result; compare: facts mỗi side; judge: quotes + values). E† = actionable items + audit findings + missing strings/excluded items/leaked labels. E† = ∅ → trả draft.
- Repair (1 call): patch CHỈ những gì E† flag — áp fix với facts+quotes, skip fix materials mâu thuẫn, giữ definite answers definite, propagate (lan truyền) changed numbers, preserve rest.
- Guard Γ (code, deterministic): patch non-empty, không cut off (cắt cụt); trừ khi length fix được yêu cầu, giữ ≥50% draft length và 30% numbers; không thêm year ngoài conversation; giữ mọi word limit/count/required string/exclusion draft đã đạt — nếu không giữ draft ỹ. Code pass cuối restore quotations về source text.

## Key Findings
- Setup: 405 task CL-bench Life (404 contexts, 5,348 rubrics, 13.2 rubric/task; 59.8% task multi-turn (nhiều lượt)); context trung bình 19.4K token, tối đa 170.8K. Judge (trọng tài) GPT-5.1 high reasoning effort, validated >90% accuracy (manual 100 samples), agreement với Claude Opus 4.6 93.2% / Gemini 3.1 Pro 93.0% (Cohen's κ (hệ số kappa Cohen) 0.72/0.71). 4/8,100 run thất bại API. Paired bootstrap (lặp lại bootstrap) 95% interval (khoảng), 1,620 task–LLM pairs pooled.
- RQ1: QERA first trên cả 4 LLM; pooled lead significant vs mọi baseline cả 2 metrics (Holm correction (hiệu chỉnh Holm) adjusted p ≤ 0.014): Δ solving vs Vanilla +6.4 [+4.3, +8.5], CCA +2.9 [+0.9, +4.9], PSCI +2.8 [+0.7, +4.9], Ctx2Skill +3.5 [+1.5, +5.6]; Δ rubric vs Vanilla +5.6 [+4.5, +6.8], CCA +2.1, PSCI +2.4, Ctx2Skill +3.1. First 24/32 per-LLM columns.
- Cost: QERA trên accuracy–cost Pareto front (mặt trước Pareto độ chính xác–chi phí): ít hơn PSCI 10–26% token (112k–131k vs 137k–177k/task) và ít call hơn (3.8–4.0 vs 5); Ctx2Skill tốn 2.4M–3.1M token + >150 call/task (self-play (tự chơi) multi-agent không amortize được) → QERA dùng 4–5% token đó và solve nhiều hơn mọi LLM; CCA rẻ hơn (63k–72k) nhưng solve ít hơn trên cả 4; ~5× token của Vanilla đổi lấy +43% relative solving. Median reply (trung vị) QERA 4.7k ký tự < CCA 6.0k, PSCI 4.8k (lead không phải do dài reply — CCA Grok 4.7 median 11.1k ký tự = 2.4× QERA, 2/3 gap rubric của CCA đến từ 67 task reply dài >4×).
- RQ2 (ablation (nghiên cứu loại bỏ) GPT-6-Luna, Table 4): answer protocol π một mình: solving 12.1%→17.0% (+4.9 [+1.7, +8.1]), rubric +3.8 [+2.0, +5.7], +3k token; request-specific questions (checklist +1.1, needs +0.5): +1.6 rubric [+0.1, +3.2], solving 17.0→18.8%. Trước answer = 5.4/6.1 rubric points gain và 6.4/7.4 gain trên implicit rubrics; explicit rubric pass giữ 80.2–81.5% mọi row. Check&repair: chỉ refine (tinh chỉnh) numeric requirements — rubric có nhắc numbers/counts (47% tổng): +0.9 [+0.1, +1.8] pooled; rubric khác −0.3 [−0.9, +0.3]; overall rubric +0.7 (GPT-6-Luna), +0.4/0.0/+0.1 (Kimi/Grok/GLM); pooled solving −0.6 [−1.9, +0.7] không significant; check chiếm 51–56% token QERA. Self-refine generic đạt rubric tương đương (73.2%) với 82k vs 123k token. Guard reject (từ chối) 27/1,385 repair (patch rỗng/cụt/bỏ mất specifics). Draft 2-call (54k–64k token) đã solve nhiều hơn mọi baseline trên mọi LLM.
- RQ3: explicit rubric — 5 method trong vòng 1.4 điểm (81.1–82.5%), QERA tie (−0.1 vs PSCI); implicit rubric (82% classified) — QERA 74.0%, +2.5 [+1.4, +3.6] vs best baseline CCA, +6.6 [+5.3, +7.9] vs Vanilla; lead giữ mọi băng lexical overlap (gối từ vựng) <60% (+2.1/+2.7/+2.3 points), ≥60% tie. Best mọi context-length quartile (tứ phân vị), +1.2–1.8 vs best baseline từng quartile; mọi method giảm 1.1–4.3 points ngắn→dài (QERA −2.6). Best average cả 3 category; rubric Communication 76.8% vs CCA 74.7%; solving Fragmented Information & Revisions 19.8% vs 16.5%. 36 combination LLM×subcategory: QERA highest rubric pass 20 (PSCI 8, CCA 6, Ctx2Skill 3, Vanilla 0, 1 tie). Questions capture: earlier-turn rules (chess task: Kimi K3 + Grok 4.7 carry rule forward → solve; Vanilla cả 4 LLM viết algebraic chess notation) và complete enumerations (47% needs yêu cầu MỌI item thỏa criterion). Headroom (dư địa): numbers/counts hardest — QERA pass 71.4% rubric nhắc numbers vs 79.2% rubric khác; Behavioral Records 71% rubric numeric (41%/32% elsewhere), lead nhỏ nhất ở đó (21.1% vs 20.7% solving, 73.0% vs 72.4% rubric vs PSCI).

## Actionable Insights
- "Interview the context, not the user" (phỏng vấn ngữ cảnh, không phỏng vấn user): trước khi sinh câu trả lời cuối, biến request thành checklist requirement + typed information needs rồi trả lời CHÚNG trước — áp dụng ngay cho assistant tổng hợp group chat/logs của chính mình: ví dụ bot tóm tắt thread Telegram 3 tháng chạy 1 JSON call Ask để trích rule ở lượt trước ("báo giá theo USD") + enumerate need ("mọi decision về giá") trước khi soạn tóm tắt.
- Fixed answer protocol π (6 rules: đọc hết gồm corrections; specifics không category words; mọi qualifying item; committed verdict; show inputs của total; giữ attribution/format, không disclaimer) là prompt template (khuôn lệnh nhắc) reusable (dùng lại) ngay — ví dụ chèn 6 rules này vào system prompt (lệnh nhắc hệ thống) của mọi pipeline sinh báo cáo từ data logs, không cần code gì thêm.
- Check sau answer chỉ refinement numeric (chiếm 51–56% token) → khi cost (chi phí) quan trọng, chạy 2-call draft (Ask+Answer) đã beat mọi baseline; chỉ bật Check/Repair cho task có numbers/counts. Ví dụ: dashboard Q&A khách hàng dùng draft-only cho query thường ngày, full pipeline cho query tổng hợp số liệu.

## Assumptions & Limitations
- Điều kiện method work: toàn conversation (19.4K token trung bình, tới 170.8K) phải nằm trong context window mỗi call — QERA KHÔNG dùng retrieval, giữ whole conversation trong mọi call; context vượt window model thì không áp dụng nguyên vẹn.
- Paper thừa nhận: pipeline all-LLM — cùng LLM viết checklist, trả lời, tự check; code giữ faithfulness + verify quotes nhưng LLM vẫn có thể hallucinate (ảo tưởng)/misread (đọc sai) messy context (miss rule ở lượt trước, misjudge record nào thỏa criterion) → error carry vào answer; quality questions phụ thuộc capability LLM; LLM khác hỏi khác; judge cũng là LLM (validated nhưng verdict cá nhân vẫn sai được); ~5× token direct answering; text-only — photos/screenshots/voice/video chưa cover; ethics: conversation gửi tới LLM provider → data-retention terms (điều khoản giữ dữ liệu) của provider, local hosting (tự lưu trữ) tránh được; consent (đồng thuận) + data governance (quản trị dữ liệu) cho personal traces thuộc về người deploy (triển khai).
- Limitation paper KHÔNG nói: rubric implicit classification dùng lexical proxy (≥60% content words) — proxy này có thể misclassify ở biên; benchmark judge GPT-5.1 duy nhất cho mọi method (method bias (thiên lệch) nếu judge ưa format QERA — kiểm soát một phần bằng judge không thấy method); solving rate chỉ 21.0% → headroom còn lớn ở chính benchmark, kết luận "best among compared" không có nghĩa "đủ tốt thực tế"; evaluate 4 reasoning model high effort — behavior trên non-reasoning model chưa rõ.
