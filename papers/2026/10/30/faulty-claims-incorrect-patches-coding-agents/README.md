# 2610.32338 From Faulty Claims to Incorrect Patches: An Empirical Study of Task-Grounded Reasoning in Coding Agents

## Problem
- Coding agent (tác nhân viết code) ngày càng giải được nhiều issue thật nhưng vẫn fail âm thầm: nộp plausible patch (bản vá có vẻ đúng) pass own validation (kiểm chứng riêng) mà không implement behavior (hành vi) yêu cầu. Prior work (công trình trước) phân tích trajectory (hành trình hành động) qua task-agnostic pattern (mẫu không phụ thuộc task): repeated actions (hành động lặp), untested fixes (sửa chưa test) — mô tả agent HÀNH ĐỘNG thế nào, không phải agent HIỂU sai gì.
- Gap: một agent có workflow exemplar (mẫu chuẩn, không anti-pattern (phản mẫu) nào) vẫn sản xuất patch sai khi hành động trên faulty task understanding (hiểu sai task): niềm tin sai về code hiện tại behavior, requirement (yêu cầu), hoặc cơ chế fix. Phát hiện điều này cần check understanding NGƯỢC với task — mà prior work chưa làm. Native CoT (chain of thought — chuỗi suy nghĩ gốc) của reasoning model (model reasoning) là proxy (đại diện quan sát được) duy nhất của task understanding, nhưng chưa ai verify (kiểm chứng) từng claim (khẳng định) trong CoT against evidence (bằng chứng) rồi trace (truy vết) nhân-quả tới patch defect (lỗi bản vá).

## Contribution
- Nghiên cứu empirical (thực nghiệm) đầu tiên về task-grounded reasoning (TGR — lập luận neo task: claim whose truth checkable (kiểm chứng được) từ task statement, repository tại base commit (commit gốc), library docs). Method: decompose CoT thành atomic reasoning units (đơn vị suy luận), classify 4 types (O original implementation / G implementation gap / S semantic constraint (ràng buộc ngữ nghĩa — requirement) / F fix mechanism), assessment agent (tác nhân đánh giá) gather evidence → verdict supported/refuted/unresolved (FEVER fact verification (xác minh sự thật)); refuted = faulty claim (khẳng định lỗi). Manual trace corrective patch (bản vá sửa chuẩn vàng) → key faulty claim (khẳng định lỗi then chốt) → replay (phát lại) trajectory với claim được sửa ngay trước submission để xác nhận nhân-quả.
- Scale: 400 trajectories, 4 open-weight reasoning model (model trọng số mở) 2 họ (DeepSeek-V3.2, DeepSeek-V4.1-Flash, Qwen3.6-27B, Qwen3.8-27B), mini-swe-agent scaffold (khung agent), 100 instances SWE-bench Pro; 76,537 reasoning units từ 28,001 steps; extraction + assessment bằng GPT-5.6-Luna; manual validation Cohen's κ (hệ số kappa) 0.937 (extraction) / 0.877 (assessment), precision (độ chính xác) 86.3%.

## Method (tóm tắt cốt lõi)
- Extraction (2.3): mỗi step CoT → LLM sinh normalized claim + verbatim quote + type + files; quote mismatch → retry 1 lần. Validation: 300 steps sample, 2,149 units — 93.3% correct, 2.9% không phải unit, 3.8% sai type.
- Assessment (2.4): assessment agent (mini-swe-agent + GPT-5.6-Luna, reasoning effort max) chạy fresh container với original repository tại base commit; KHÔNG nhận trajectory observations, generated patch, oracle patch (bản vá chuẩn vàng), test results → judgment chỉ dựa evidence tự gather; 4 tools: shell (inspect repo + run tests), documentation fetcher, citation recorder (ghi exact source excerpts), submission. Per-type instructions: O trace code; G compare implementation vs requirement; S reconstruct requirement + tìm input phân biệt; F tìm counterexample (phản ví dụ). Verdicts: supported / refuted / unresolved.
- Tracing (2.5): 2 authors đọc corrective patch (edit áp lên incorrect patch để pass toàn bộ validation tests (test kiểm chứng) + thỏa requirement) → identify key faulty claims (faulty claim liên quan defect: nếu được sửa, agent có cơ hội tránh defect); replay trajectory đến ngay trước submission, gửi user message sửa claim, agent revise + resubmit; compare diff (sự khác biệt) với targeted fix (phần sửa mục tiêu); chạy validation tests trên patch mới. Replay từ trước submission (không phải từ bước lỗi) để patch cuối đủ gần original để so sánh.

## Key Findings
- RQ1 prevalence (mức độ phổ biến): TGR chỉ 18.5% CoT tokens (4,593/24,784 trung bình/trajectory) nhưng chứa 191.3 reasoning units/trajectory (6.7 units/TGR-step); 40.7% steps (28.5/70.0) có TGR. Model mới think longer 3.6–3.8× (Flash 3.79× V3.2 tokens; Qwen3.8 3.60× Qwen3.6) nhưng TGR chỉ tăng 2.24–2.58× tokens / 1.88–2.11× units → chỉ 12.0% (Flash) / 15.1% (Qwen3.8) additional tokens là task-grounded. Type composition: O 43.9%, S 31.9%, F 22.0%, G 2.3%. TGR front-loaded (front-load — dồn đầu): coverage peak 29.3% ở thập phân thứ 2, giảm 11.9% cuối; F claims 61.3–77.0% nằm nửa đầu trajectory (30–49/100 trajectory có F claim ở thập phân đầu — cơ chế lấy từ task statement trước khi khám phá code, ví dụ navidrome-0488fb9 Qwen3.6 step 1/63); S claims chiếm một nửa TGR tokens cuối cùng (6.0%/11.9%).
- RQ2 faulty claims: assessment agent refutes 8,540/76,537 units (11.2%); estimated error rate 9.6% (lower-bound estimate — cận dưới vì không check recall (độ bao phủ)); 391/400 trajectory (97.8%) có ≥1 faulty claim (V3.2 100%; Qwen3.6 ít nhất 93/100); trung bình 21.4 faulty claims/trajectory (median (trung vị) 14). Model mới resolve nhiều hơn nhưng faulty claims NHIỀU hơn: Flash 2,865 vs V3.2 1,789 (+60%) dù error rate thấp hơn (10.1% vs 13.3%); Qwen3.8 2,707 vs 1,179 (2.30×), error rate 9.8%→12.0% (composition shift alone → 11.7%). Error rate by type: O 13.5%, F 14.7%, S 5.5% (thấp nhất mọi model, 4.8–8.1% vs ≥10.2% các type kia) → agents hiểu requirement tốt hơn hiểu code. Error forms (dạng lỗi, confirmed sample): Misstatement (phát biểu sai) 53.3%, Overgeneralization (khái quát quá mức) 24.7%, Misreference (tham chiếu sai) 11.3%, Omission (bỏ sót) 10.7% — chỉ ~1/9 faulty claims tham chiếu object sai/không tồn tại; 59.0% O errors là misstatement (1/3 toàn bộ confirmed faulty claims). S errors 2/3 là scope sai (overgeneralization/omission).
- RQ2↔outcome: unresolved trajectories có 25.2 vs 17.9 faulty claims — chủ yếu vì nhiều claims hơn (Flash 1.97× faulty nhưng 1.62× units); error rate chỉ cao hơn 0.9–2.1 điểm phần trăm; 38 tasks mixed-resolution: +1.9 điểm, 95% bootstrap interval (khoảng bootstrap) −0.2 đến 4.0 → KHÔNG significant (có ý nghĩa thống kê). 96.7% resolved trajectories (205/212) vẫn chứa faulty claims — recovery (agent tìm evidence sau mâu thuẫn claim) hoặc patch không phụ thuộc claim. Two trajectories nhiều faulty claims nhất (128 mỗi trajectory) đều resolve.
- RQ3 causal: 127/188 unresolved (67.6%) chứa ≥1 key faulty claim (V3.2 77.2%, Flash 66.7%, Qwen3.6 57.1%, Qwen3.8 69.2%); 182 key claims tổng (80 trajectory 1 claim, 47 trajectory 2–4); type split: O 69 (37.9%), S 61 (33.5%), F 50 (27.5%), G 2. Chỉ ~1/26 faulty claims là key: 4,741 faulty claims trong unresolved (25.2/trajectory), manual sample 17/452 (3.8%) key; assessment agent refutes 150/182 key claims (82.4%) — detect được nhưng chôn mỗi key trong ~26 faulty claims khác.
- Replay (per-claim correction, 182 replays): targeted fix (bản sửa trúng defect) 162/182 (89.0%); pass more validation tests 34 (18.7%); resolve task 21 (11.5%) — 129 replays fix defect nhưng tests không hiện (tests không exercise behavior được sửa, hoặc defect khác còn). Multi-claim trajectories: 91/102 single corrections fix defect, chỉ 9 (8.8%) resolve (vs 12/80 = 15.0% single-claim); correcting ALL key claims một message: 19/47 (40.4%) pass more tests, 10 (21.3%) resolve. Toàn bộ 127 trajectories: 37 (19.7%) pass more tests, 22 (11.7%) resolve; resolution rate 4 models 53.0%→58.5%. Targeted fixes chỉ 40.1% lines của corrective patch → defect còn lại từ edits ngoài/đi ngược reasoning (navidrome-66b74c81: hunk header (tiêu đề khối diff) 77 lines nhưng hunk 81 lines → file bị truncate (cụt); openlibrary-25858f9f: function move nhưng không add vào module mới → import fail).
- Agent hành động theo correction bằng edit nhỏ focused: median 17 steps thêm; revised patch median 13 lines changed vs original median 101 lines. Model mới follow correction đáng tin hơn: Flash + Qwen3.8 targeted fix 100% replays; V3.2 77.0%, Qwen3.6 87.2%. ~1/2 trong 20 replays không targeted fix: agent bỏ qua defective code; 3 replay (đều V3.2) resubmit nguyên patch. openlibrary-09865f5: Qwen3.6 sửa to_dict() thành dict(obj) — đổi API sai lấy API sai khác.
- Resolved ≠ correct: plausible patch pass tests nhưng sai — qutebrowser-a84ecfb (agent narrow task về những gì expected tested; faulty claim nói rõ trong reasoning); qutebrowser-5e0d6dc ("tests won't check" shortcut giữ assignment khiến Array.prototype.at visible với for...in).

## Actionable Insights
- Audit CoT claims trước khi tin patch (áp dụng với model có native CoT visible — open-weight): trích claims O/G/S/F kèm quote, verify mỗi claim against repository + task statement + library docs, chỉ sửa claims mà final patch vẫn build trên (key claims) — vì 96.7% resolved trajectory cũng có faulty claims (presence là weak signal (tín hiệu yếu)), chỉ ~1/26 faulty claims gây defect. Ví dụ: dùng AI agent sửa bug checkout shop → trước khi merge, chạy assessment pass verify claims "hàm X đã làm Y" bằng cách đọc code + dò behavior (execution probes (dò thực thi)), đừng chỉ check tên hàm (misreference chỉ 11.3% — lỗi chủ yếu là misstatement behavior 53.3%).
- Correction message ngay trước submission hiệu quả: 89.0% targeted fix, revision median 13 lines (không rewrite). Ví dụ: pipeline CI cho coding agent — khi checker refute claim, gửi correction + yêu cầu agent revise, rồi chạy targeted tests (test mục tiêu) cho behavior được sửa, không chỉ chạy nguyên validation suite (tests miss 129/162 defect đã fix).
- Anti-pattern scan trong reasoning làm review flag: hedged claims ("Probably exact", "likely") + shortcut statements ("tests won't check") đánh dấu patch cần review người dù tests pass — vì agent narrow task về phần được test. Ví dụ: thêm grep-style rule trong review bot: flag mọi patch kèm CoT chứa "won't check"/"probably" → queue review manual.

## Assumptions & Limitations
- Điều kiện method work: native CoT accessible (open-weight models) — commercial models thường hide native CoT (giới hạn áp dụng trực tiếp; có thể mượn agent framework thoughts nhưng ít detail hơn); scaffold mini-swe-agent + benchmark SWE-bench Pro cố định; evidence sources phải có (task statement, repo base commit, library docs).
- Paper thừa nhận: không check recall assessment agent (error rates là lower bounds; nhưng refutes 82.4% key claims); manual validation trên samples (300 steps, 40 trajectories — đạt kích thước 99% confidence ±5% margin: 2,149/76,537 units vs 660 required; 896/8,540 vs 618 required); chỉ open-weight models, single scaffold, single benchmark; không nghiên cứu dependency giữa faulty claims lẫn nhau hay nguyên nhân model tạo chúng (black box).
- Limitation paper KHÔNG nói: corrective patch do chính authors xây (gold standard), không report inter-annotator agreement cho defect localization + replay judgments; replay timing không thực tế (correction gửi ngay trước submission — production không biết trước); key faulty claim definition mang counterfactual (phản thực) tính chủ quan ("had the claim been corrected, agent would have had a chance"); cost chạy assessment agent ở scale không report; resolution base 53.0% (212/400) nghĩa là kết luận trên population đã fail một nửa — transfer sang scaffold mạnh hơn chưa rõ.
