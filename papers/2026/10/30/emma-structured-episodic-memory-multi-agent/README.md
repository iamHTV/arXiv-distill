# 2610.35966 EMMA: Structured Episodic Memory for Multi-Agent Workflow Synthesis

## Problem
- Deploy (triển khai) LLM agent (tác nhân) vào domain (lĩnh vực) chuyên biệt đòi hỏi procedure (quy trình) mịn + knowledge mà general model không có. Hai cơ chế truyền thống đều tốn kém: parameter training (huấn luyện tham số — SFT (supervised fine-tuning — tinh chỉnh có giám sát)/RL (reinforcement learning — học tăng cường) kiểu GRPO/DAPO) tính toán đắt + artifact (sản phẩm) không inspect (kiểm tra) được không sửa chọn lọc; hand-engineered agent system (hệ thống tác nhân thiết kế tay) chuyển cost (chi phí) sang expert labor (lao động chuyên gia), phải viết lại mỗi domain mới.
- Episodic memory (bộ nhớ giai thoại — persist experience dạng text, weights đóng băng) update ở context level, nhưng single-agent adaptation (thích ứng đơn tác nhân) khó giảm cross-task interference (nhiễu liên task), nhất là task phức tạp (multi-application navigation, data pool analysis). Multi-agent evolution (tiến hóa đa tác nhân) giảm bớt nhưng prior work (ACE, GEPA, EvoMAS, ADAS) thiếu definition rõ về update rules và để backbone model (model nền) quyết định thay đổi ở đâu, bao nhiêu → ill-scoped evolution (tiến hóa mất phạm vi): learning follow structural preference (thiên kiến cấu trúc) của backbone thay vì observed failures — Figure 1: Opus 5 tích lũy skills, DeepSeek v3.2 lại liên tục tạo agents mới (mỗi backbone một habit khác nhau).
- Gap: chưa có hệ thống nào làm ownership (quyền sở hữu update) và admissibility (tính được chấp nhận) của update là explicit — mỗi failure phải được gán đúng scope (phạm vi) sở hữu nó và sửa bằng đúng một edit bị chặn (bounded) trong scope đó.

## Contribution
- EMMA (structured Episodic Memory for Multi-Agent workflow synthesis): formulate (hình thức hóa) multi-agent workflow synthesis thành episodic learning trên cấu hình hệ thống — controller routing memory (bộ nhớ định tuyến controller), specialists inheriting generalist prompt (chuyên gia kế thừa prompt đa năng), per-step procedural skills (kỹ năng thủ tục từng bước) — đều là memory entries.
- Structured reflection + scoped update: reflector (bộ phản chiếu) gán mỗi failure đã diagnose (chẩn đoán) vào 1 trong 5 scope và propose đúng MỘT edit trong scope đó; backbone-independent guards (rào chắn không phụ thuộc backbone) giữ mọi accepted edit scoped, incremental (tăng dần), bounded.
- Số liệu: best overall trên EVERY benchmark (KramaBench, AppWorld, BBEH) với 5 backbones, 4 baselines; lên tới +32.5% over strongest baseline; first 17/20 settings; 17–38% fewer training executions (chạy huấn luyện) hơn baseline hiệu quả nhất.

## Method (tóm tắt cốt lõi)
- Hierarchical episodic memory (bộ nhớ giai thoại phân cấp) 3 pools giảm dần generality (tổng quát): C — controller memory (rules decompose task, dispatch agent/skill, khi nào verify; entry có topic, summary, domain tags, generality label general/domain-specific/task-specific; controller đọc index tự chọn entry load — load none cũng hợp lệ vì memory irrelevant làm planning xấu đi); A — agent pool (sub-agent = system prompt + input/output contract + Python tool; khởi tạo 1 generalist a0, specialist tạo lúc training với prompt p̃_j = p_0 ∥ p_j (nối prompt) — general habit viết 1 lần vào p0 lan tới mọi specialist); S — skill pool (procedure ngắn cho class sub-problem: thuật toán, rule system, pitfall checklist (danh sách cạm bẫy), format convention; index 1 dòng "when to use", controller thấy index, sub-agent nhận full text).
- Step-wise synthesis với overflow decomposition (phân rã tràn): controller emit ordered plan (mỗi step: agent + subtask + skills), dispatch MỘT step mỗi lượt, đọc output, rồi continue/revise/terminate. Sub-agent nhận task + subtask + skills + controller-curated summary (tóm tắt) outputs trước → context nhỏ. Step exhaust (cạn) sub-agent (full context window hoặc hết rounds) → đọc là bằng chứng subtask specify quá thô, KHÔNG phải agent fail: controller dùng partial trace (dấu vết bộ phận) split step đó thành steps nhỏ hơn trên existing agents, splice vào plan, resume cùng vị trí, giữ completed work. Mọi overflow ghi làm evidence cho reflector.
- Training loop (attempt chain (chuỗi attempt)): mỗi task chạy fresh environment, gate (cổng) bằng correctness signal riêng task (LLM judge (trọng tài), unit tests, exact match). Correct → kết thúc chain. Incorrect → structured reflection 4 bước cố định: localize (định vị step sai) → classify vào 1/5 scope Table 1 (execution_slip (trượt thực thi — biết method, slip 1 lần); agent_behavior (behavior tác nhân — habit làm việc chung fail); procedure (quy trình — method cho class sub-problem sai/thiếu); missing_capability (thiếu năng lực — không agent nào làm được); routing (định tuyến — subtasks đúng nhưng decompose/dispatch sai)) → generalize (khái quát hóa: correction áp mọi task cùng loại, KHÔNG nêu entity/answer của task này) → minimize (edit nhỏ nhất trong scope). Ownership rules: execution_slip → plan directive (task này, REVISE_PLAN/NO_CHANGE — không bao giờ ghi memory bền); agent_behavior → agent prompt (REFINE_PROMPT, p0 nếu general); procedure → skill pool (REVISE_SKILL/CREATE_SKILL); missing_capability → skills rồi agents (CREATE_SKILL/CREATE_AGENT); routing → controller memory (MEMORY_NOTE/REVISE_PLAN, CREATE_AGENT khi overflow).
- Guarded update (5 guards programmatic, không phụ thuộc backbone): scope–action compatibility (action ∈ Act(z)); prompt preservation (giữ đa số prompt cũ, chỉ động agent đã chạy trong attempt fail); bounded memory growth (pools + entries trong fixed sizes; agent mới phải specialization thật, không duplicate/label); no leakage (không artifact nào chứa reference answer hay copy span task text); change of strategy (không edit memory level nào >2 lần liên tiếp fail; cùng step overflow 2 lần liên tiếp → action phải thay đổi cách chia việc). Refused proposal → trả reason cho reflector thử lại; persistent refusals → default no change. Skill/agent mới hoặc sửa được NÊM TÊN trong plan re-run → edit thực sự được exercise (thực hành).
- Re-run đến success hoặc hết revision budget; KHÔNG edit sau failure cuối (edit chưa re-run = untested memory). End-of-task chain-aware controller update ghi vài routing lessons. Một pass duy nhất over training set, fixed order; memory snapshot sau mỗi chain; freeze sau pass — 1 artifact/benchmark/backbone, no checkpoint selection. Inference: controller giữ memory selection, replanning, overflow decomposition; KHÔNG gọi reflector, KHÔNG write.

## Key Findings
- Benchmarks: KramaBench 28 train/76 held-out (6 scientific domains, macro accuracy); AppWorld 90 train/168 test_normal/417 test_challenge (9 applications qua API, challenge cần application chưa thấy lúc train; TGC (task-goal completion — hoàn thành mục tiêu task) + SGC (scenario-goal completion — mọi variant scenario phải pass) từ state-based unit tests); BBEH-mini 92 train/368 held-out (23 reasoning categories). Backbones: Claude Opus 5, Sonnet 5, GLM-5, DeepSeek v3.2, Kimi-K2.5 (controller/sub-agents/reflector cùng backbone). Baselines: ACE (playbook cho ReAct agent cố định), GEPA (prompt evolution), EvoMAS (tiến hóa whole configuration, reward = evaluator − cost term), ADAS (meta-agent search, budget matched GEPA).
- RQ1 effectiveness: EMMA best mean mọi benchmark — KramaBench 0.654 vs GEPA 0.584 (+7.0 điểm); BBEH-mini 0.663 vs 0.605 (+5.8); AppWorld normal +11.9 TGC/+17.4 SGC, challenge +6.4 TGC/+5.3 SGC (over ACE; EMMA mean normal 84.2/71.0, challenge 73.8/56.0; Opus 5 normal 96.4/94.6, challenge 89.2/83.5). First 17/20 benchmark–backbone settings, second 3 (KramaBench + AppWorld challenge trên Kimi-K2.5, BBEH trên Sonnet 5); runner-up thay đổi theo benchmark (GEPA, ACE) → advantage không dựa vào 1 baseline yếu. Largest gains AppWorld challenge open-weight: +16.6 TGC DeepSeek v3.2, +15.4 GLM-5.
- Consistency cross-family: (i) multi-agent search methods backbone-sensitive nhất — AppWorld challenge EvoMAS/ADAS 89.0/84.4 TGC với Opus 5 nhưng sụp 7.2 (EvoMAS, GLM-5) và 0.5 (ADAS, DeepSeek v3.2); ADAS không tìm program nào beat hand-written seed trên 2 open-weight backbones. (ii) EMMA weakest backbone mạnh hơn mọi baseline weakest backbone mọi benchmark (58.5 KramaBench, 61.2 TGC AppWorld challenge, 56.3 BBEH); trên KramaBench + AppWorld normal còn vượt five-backbone mean của mọi baseline. (iii) Margin EMMA lớn hơn trên open-weight: AppWorld +0.2 TGC Opus 5 vs +15.4 GLM-5, +16.6 DeepSeek v3.2; BBEH +2.4 Opus 5 vs +9.0 GLM-5, +10.9 Kimi-K2.5; KramaBench lead đều ~6 điểm trên 4/5 backbones.
- Update efficiency (Table 4, mean 5 backbones, càng ít càng tốt): training executions KB ACE 96.8 / GEPA 156.4 / EvoMAS 280.0 / ADAS 141.4 / EMMA 61.8; BBEH 192.6/222.8/385.1/200.0/159.6; AppWorld configuration 283.4/229.8/1098.0/206.0/127.8 → EMMA ít nhất mọi benchmark, 17–38% fewer executions than most efficient baseline (KB −36%, BBEH −17%, AppW −38%). Vì re-run chỉ failed tasks, mỗi re-run test đúng MỘT localized guarded edit.
- Ablation (KramaBench, Opus 4.5, full EMMA 0.647): memory levels — chỉ controller memory learned 0.506 → +skills 0.591 (gain lớn hơn — transferable knowledge chủ yếu là CÁCH giải class sub-problem) → +agents 0.647 (specialist capture knowledge skills đơn lẻ không có; controller memory contribution không isolated vì có mọi arm). Episodic vs test-time adaptation: DACode 0.443, Reflexion 0.476, DeepResearch 0.535, EvoMAS cross-task self-evolution trên test split (không ground truth) 0.532 — tất cả well below EMMA 0.647 → corrections từ verified training failures transfer tốt hơn adaptation thêm ở test.
- Case study: Sonnet 5 trên BBEH — 1 failed zebra puzzle sinh 3 artifacts đúng level (constraint-satisfaction skill, specialist agent từ overflow evidence, routing rule trong controller memory); zebra tasks sau solve attempt đầu tiên; held-out puzzle solve + verify unique trong 1 dispatched step.

## Actionable Insights
- Cấu hình multi-agent system chính là memory: thay vì fine-tune (tinh chỉnh) hay thuê expert thiết kế topology, hãy persist 3 pools (routing rules / agent prompts / procedural skills) dạng text, update từ verified failures — áp dụng ngay cho content pipeline đa kênh: mỗi channel là specialist agent kế thừa generalist prompt; bài viết fail → reflector gán scope (routing hay procedure) → 1 edit scoped. Ví dụ: hệ thống viết bài + đăng đa nền tảng, sau 28 task học được skill "kiểm tra factual claim trước đăng" + routing rule "data-heavy task → agent phân tích trước".
- Ownership table (bảng quyền sở hữu) 5 scope + 1 edit/scope + guards là discipline (kỷ luật) áp dụng NGAY cả khi không dùng EMMA nguyên: khi review failure của agent system tự build, hỏi "failure này thuộc scope nào (execution/behavior/procedure/capability/routing)" rồi chỉ sửa đúng layer đó — tránh ill-scoped evolution (Opus tích lũy skill, DeepSeek sinh agent vô tội vạ). Ví dụ: bot customer support fail vì thiếu tool → scope missing_capability → CREATE_SKILL trước, CREATE_AGENT chỉ khi skill không đủ.
- Guard "no edit sau failure cuối" + "re-run test mỗi edit" = quy tắc hygiene (vệ sinh) cho self-improving system: KHÔNG bao giờ persist lesson chưa được test lại. Ví dụ: pipeline tự học từ feedback khách hàng — mỗi rule mới phải được replay trên task fail trước khi lưu vào memory production.

## Assumptions & Limitations
- Điều kiện method work: task cần correctness signal tự động (LLM judge/unit tests/exact match) làm gate — domain không có verifier tự động thì loop không chạy; training chỉ 1 pass fixed order trên 28–90 tasks; memory freeze sau 1 pass, no checkpoint selection; controller/agents/reflector chia sẻ 1 backbone mỗi run.
- Paper thừa nhận: EMMA narrow nhưng KHÔNG loại bỏ gap giữa backbone families; pairing strong reflector với weaker executors là hướng khai thác tự nhiên (future work); accepted edits persist kể cả khi chain kết thúc unsolved — không thấy systematic degradation nhưng ineffective/harmful entries có thể còn; cross-verification trên mini-batches hoặc multi epochs có thể lọc chúng (future work).
- Limitation paper KHÔNG nói: generality label (general/domain/task-specific) gán bằng cách nào không rõ (likely LLM-assigned — error-prone); controller tự chọn memory entries ("loading none valid") → controller yếu có thể bỏ memory hữu ích (con dao 2 lưỡi); benchmarks đều agentic coding/data/API tasks — transfer sang content/business workflow chưa chứng minh (dù AppWorld API navigation gần); không report confidence intervals cho bảng chính; evo của memory theo thời gian dài (many tasks) với drift (trôi) chưa khảo sát.
