# [2610.29331] From Prompts to Posteriors: Can LLM Agents Perform Bayesian Inference in Context?

## Problem
- Các hệ thống AI scientist (nhà khoa học AI) dùng LLM (large language model — mô hình ngôn ngữ lớn) cần cập nhật niềm tin (belief) theo evidence (bằng chứng) tích lũy dần — Bayesian inference (suy luận Bayesian) là framework tự nhiên. Prior work (công trình trước) GIẢ ĐỊNH LLM không thể thực hiện Bayesian belief updating (cập nhật niềm tin theo định lý Bayes) có nguyên tắc trong context (ngữ cảnh hội thoại), nên xây dựng strict harness (khung ràng buộc chặt) như BED-LLM — cố định phần lớn probabilistic model (mô hình xác suất) bên ngoài model. Gap: giả định này chưa từng được đánh giá có nguyên tắc — LLM thật sự vi phạm Bayes rule (quy tắc Bayes) mức nào, và yếu tố nào (reasoning — suy luận có dây chuyền, code execution — thực thi code) có thể đóng gap?

## Contribution
- Evaluation framework (khung đánh giá) 3 trục tiến bộ: (1) probabilistic coherence (tính nhất quán xác suất) qua Dutch-Book construction (xây dựng bộ cược đảm bảo thua — equivalent vi phạm Kolmogorov axioms — tiên đề xác suất); (2) posterior fidelity (độ trung thực posterior — phân phối xác suất sau) đo bằng KL divergence (độ lệch Kullback-Leibler) so Bayesian oracle (bộ tính Bayes chuẩn); (3) downstream task performance (hiệu suất task hạ lưu) trong adaptive experimental design (thiết kế thí nghiệm thích ứng) để xem non-Bayesian drift (trôi dạt không theo Bayes) có hậu quả thực tiễn không.
- ProteinWorld: environment (môi trường) tổng hợp highly configurable mô phỏng discovery khoa học phân loại protein; procedural generation (sinh thủ tục) world mới mỗi instance với terminology hư cấu → strictly out-of-distribution (ngoài phân phối dữ liệu huấn luyện); 2 difficulty: simple (likelihood — hàm hợp lý — closed-form) và hard (analytically intractable — không giải được dạng đóng, cần Monte Carlo simulation).
- Bằng chứng: LLM vi phạm Bayes rule khi không có reasoning; reasoning model tính đúng posterior closed-form, nhất quán qua 10+ data points; với tools thì xấp xỉ đúng cả posterior intractable → strict harness hiện tại có thể không cần nữa.

## Method (tóm tắt cốt lõi)
- Bayes rule (Eq. 1): p_k(θ) := p(θ|h_1:k) ∝ p(y_k|θ,ξ_k)·p_{k-1}(θ) ∝ p_0(θ)·∏ p(y_i|θ,ξ_i). So sánh p^LLM (xác suất model phát biểu bằng verbalization hoặc token-logprob) với p^oracle.
- Dutch Book: tập cược đồng thời từ subjective probability (xác suất chủ quan) khai báo → guaranteed loss (thua chắc) dù outcome gì; ví dụ Θ={A,B}, q1=0.6, q2=0.5 → tổng 1.1 vi phạm normalization axiom. Kiểm tra 3 loại vi phạm: extensionality (E), normalization (N), monotonicity (M), mỗi loại 10 kịch bản ForecastBench (30 kịch bản), 2 thiết lập: independent chats (cross-conversation) vs single chat (within-dialogue).
- Sequential updating: 3 trajectory (quỹ đạo) — p^LLM (cập nhật niềm tin + chọn experiment), p^ora-pas (passive oracle — áp Eq.1 với prior p0 và kết quả experiment của run LLM), p^ora-act (active oracle — Bayes + tự chọn experiment tối ưu). Posterior fidelity dùng forward KL(p^ora-pas ∥ p^LLM) — cố ý dùng forward KL để discourage (ngăn) việc loại bỏ sớm hypothesis còn hiệu lực; clip p^LLM từ dưới 10^-6 rồi renormalize.
- Downstream: score trajectory bằng mass trên true hypothesis {p_k(θ*)}; posterior-mass gap (Eq. 4): p^ora-act(θ*) − p^LLM(θ*) — ít bị ảnh hưởng độ khó environment hơn absolute accuracy.
- 20Q: experiment = câu Yes/No bất kỳ, Θ = tất cả animal có thật (vô hạn); LLM duy trì dynamic subset Θ_k, compatibility đánh giá rồi normalize → induce uniform prior; oracle dùng chính likelihood đánh giá của LLM → test internal probabilistic consistency (nhất quán xác suất nội tại).
- ProteinWorld: Θ = 8 protein class, attribute vector (véctơ thuộc tính) latent 8 chiều với p(a|θ) random, 6 experiments; likelihood p(y|θ,ξ)=∫p(y|a,ξ)p(a|θ)da (Eq. 5). 5 worlds × 8 classes (mỗi class làm ground truth 1 lần) = 40 runs, T=6.
- Models: coherence — Gemini-2.5-Pro, Gemma-4-31B-it, Qwen-2.5-32B-Instruct; sequential — thêm Phi-4, Gemma-4-26B-A4B-it, Qwen-3.6-35B-A3B (3 model sau có reasoning mode); ProteinWorld-hard: Gemini-2.5-Pro + native Python code-execution tool.

## Key Findings
- Result 1 (coherence): cross-conversation Dutch-Bookable violation rate vượt 50% trên 30 scenarios cho hầu hết model-constraint combinations; within-dialogue giảm mạnh — còn 10% với Gemini, 1/30 scenarios với Gemma. Nguyên nhân: thiếu persistent common representation (biểu diễn chung bền vững), KHÔNG phải không biết áp dụng quy tắc xác suất.
- Result 2 (không reasoning): KL divergence lớn chỉ sau vài experiments ở cả 20Q và ProteinWorld-simple; downstream: LLM belief updates giảm final success rate ít nhất 30% so active oracle ở mọi model, cả 2 environment; 20Q model yếu collapse về ~0% final accuracy (catastrophic collapse); ProteinWorld: model hiện đại nhận đúng protein likely nhất nhưng gán sai mass (quá nhiều/quá ít), model yếu không khác random guessing.
- Result 3 (reasoning): 20Q — KL giảm mạnh cả 3 model, Gemma-4-31B-it nhất quán đến 10 experiments; ProteinWorld-simple — reasoning model đạt KL gần 0 mọi k; Gemma-4-31B-it match oracle cả quá trình discovery; lỗi là numerical slips (trượt số), KHÔNG phải conceptual failures (lỗi khái niệm); posterior đúng thường được re-verify qua hàng nghìn redundant tokens (token dư thừa).
- Result 4 (tools): ProteinWorld-hard — reasoning-only model nhận ra KHÔNG được prompt rằng marginalization Eq.5 intractable, nhưng vẫn tiến hành như thể chạy được Monte Carlo và report hallucinated simulation output (output mô phỏng bịa) hoặc xấp xỉ số quá thô → KL cao + suy giảm. Với code execution: viết được numerically stable Monte Carlo estimator, KL và performance gap về gần 0, match oracle.
- Result 5 (harness): với reasoning LLM hiện đại, structural harness của BED-LLM-style framework có thể không còn cần thiết — full belief update bởi chính LLM đạt downstream performance comparable.

## Actionable Insights
1. Elicit (khai thác) xác suất trong MỘT dialogue duy nhất: cross-conversation judgments Dutch-bookable >50%, within-dialogue chỉ 0–10%. Ví dụ: agent dự báo rủi ro khách hàng phải gom toàn bộ phán đoán xác suất liên quan vào 1 phiên hội thoại, không hỏi rải rác nhiều phiên rồi ghép.
2. Belief updating nhiều bước KHÔNG tin model không reasoning: giảm ≥30% success rate vs oracle. Ví dụ: workflow agent giám sát vận hành tích lũy evidence qua nhiều turn → bắt buộc bật reasoning mode + code execution tool cho bước tính posterior, không để model "tính nhẩm" phân phối.
3. Reasoning model biết khi nào cần simulation nhưng sẽ HALLUCINATE nếu không có tool: chúng tự nhận diện intractable posterior nhưng bịa output Monte Carlo. Ví dụ: khi agent phân tích rủi ro với likelihood phức tạp, phải cấp sandbox Python thực thi thật, đồng thời audit output code có estimator ổn định không.
4. Thay strict harness bằng explicit belief state (trạng thái niềm tin tường minh): BED-LLM-style ràng buộc ngoài có thể gỡ với reasoning model hiện đại — nhưng vẫn giữ belief state lưu trữ để nhất quán cross-conversation + human inspection (kiểm tra của người). Ví dụ: agent y tế sơ bộ lưu bảng posterior từng hypothesis vào DB, mỗi lần hội thoại đọc lại thay vì hỏi lại từ đầu.

## Assumptions & Limitations
- Điều kiện method work: prior p0 cố định từ ngoài (external), likelihood model xác định được (20Q: dùng chính đánh giá của LLM; ProteinWorld: specification toán học đầy đủ); 20Q phải deviate khỏi strict Bayesian (dynamic subset Θ_k, uniform prior induced) do hypothesis space vô hạn.
- Paper thừa nhận: 20Q oracle là internal consistency (dựa likelihood tự khai của LLM), không phải world truth; hướng future work: xây dựng concrete less-restrictive harness giữ explicit belief state.
- Mày thấy thêm: mọi environment là synthetic/procedural (ProteinWorld terminology hư cấu) — chưa validate trên real scientific discovery data; so sánh non-reasoning dùng fixed compute budget đúng token output probabilities (không cho phép model tự do compute); forward KL choice thiên về coverage mass (phủ khối lượng) hơn precision; chỉ test 5–6 model, kết quả "modern reasoning model" có thể không generalize đến model nhỏ yếu hơn.
