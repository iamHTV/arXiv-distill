# [2610.21375v1] MEMORILLA: Latent Semantic Memory for LLMs

## Problem
- Deployed LLMs need memory (accumulated knowledge: user preferences, long documents, KB facts), but both existing paradigms fail: (a) retrieval-based (RAG, Mem0, MemoRAG) — user preferences rarely share wording with the query, so similarity-based retrieval cannot find/combine the relevant information (weak personalization); multi-hop relational reasoning degrades when chains span multiple documents (RAG-50 on FactKG drops 78.73->51.75 as composed facts go 1->4); (b) full context — the prompt grows proportionally with the corpus, exploding cost/latency (19.9s vs 0.74s end-to-end), and "full context is not an upper bound" — it hurts more often than it helps. Prior latent-context compression (xRAG, ComMer) never delivered a persistent, query-conditioned memory with strong results across personalization, long-document QA, knowledge QA, and agent continual learning.

## Contribution
- MEMORILLA: a latent semantic memory system for frozen LLMs. It separates persistent knowledge storage from per-query context: a frozen document encoder embeds the corpus ONCE into a query-independent store ZD (computed once, persisted); a trainable memory module reads the store conditioned on the query and returns K query-conditioned soft memory tokens projected into the frozen LLM's embedding space, prepended before the query text. The LLM processes memory and text in the same input sequence — NO LLM layer or attention mechanism is changed. New documents can be added without updating the LLM.
- First combined system: supervised memory (answer-position NLL loss) + RL continual learning (GRPO on environment reward, training ONLY the memory module) for agent tasks.

## Method (core)
- Encoding: frozen Qwen3-Embedding-4B -> ZD in R^{N x he} (once); frozen query encoder -> zq. 4-stage memory module (194,123,776 trainable params, K=16 by default): (1) slot initialization — learned Q0 shared across collections/queries; (2) query conditioning Qc = LayerNorm(Q0 + CrossAttn(Q=Q0, K=zq, V=zq)); (3) document retrieval — L_ref Perceiver-style cross-attention blocks attend over ALL N stored embeddings (a continuous query-conditioned read, NOT discrete top-k selection); (4) projection Wproj (he -> hL) -> M = [m1..mK].
- Injection: X_LLM = [m1..mK ; Pq]; standard RoPE over the combined sequence; the frozen LLM (Qwen3-8B default) attends to memory via existing self-attention. Loss = NLL on answer positions only (not prompt/memory positions).
- Training 3-stage curriculum: Stage 1 — 1.98M English Wikipedia paraphrase reconstruction; Stage 2 — 1.34M examples from 10 datasets (reading comprehension, open-domain QA, summarization); Stage 3 — unified mixture of train splits from all 8 evaluation benchmarks (one multi-task checkpoint for 6; PMv2/PV4 get benchmark-specific fine-tuning).
- Baselines: RAG-50 (top-50 cosine), Mem0, MemoRAG (both additionally use frozen Qwen3-4B-Instruct-2507 to build memories), xRAG, ComMer (via reported results), LLMLingua-2 (task-agnostic prompt compression) — all with frozen Qwen3-Embedding-4B + Qwen3-8B decoder; 32,768-token decoder context with YaRN when full-context exceeds it.
- TextWorld continual learning: frozen Qwen3-4B-Instruct-2507 agent + memory K=8; each turn stored as a new document; memory module from RANDOM initialization trained with GRPO (sparse reward, G=16 rollouts); the same input budget as the ICL baseline (16,000 tokens training / 4,096 evaluation), so improvement reflects memory content, not information access.

## Key Findings
- 8 benchmarks (PMv2, LaMP-4, LaMP-7, PersonalizationV4, NarrativeQA, TriviaQA, FactKG, PubMedQA): MEMORILLA outperforms all baselines on average (49.68 vs xRAG 41.92, LLMLingua-2 40.75, Mem0 38.02); on the Pareto frontier of EVERY benchmark, leading 5 and second on 2 (NarrativeQA, PV4); 394x/113x/49x fewer document tokens than full context/RAG-50/MemoRAG (geometric mean); range 20x-4,212x; over 4,000x context compression.
- FactKG (claim verification against KB): 84.33% vs full-context 80.43%, MemoRAG 80.38%, xRAG 78.98% — with 108x fewer tokens than full context and 36x fewer than MemoRAG; advantage grows monotonically with entity count (+4.23pp at 1 entity -> +7.59pp at 4+); MEMORILLA stays in the 80-89 range across composition depths while RAG-50 drops 78.73->51.75 (facts 1->4); 73.5% of FactKG claims have >50 chunks.
- TriviaQA EM 57.00 (MemoRAG 56.60, full context 52.60) with 743x fewer tokens than full context and 19x fewer than MemoRAG. PMv2 short-answer 44.60% vs xRAG 30.90% (strongest baseline) — every other baseline including full context stays within ~3 points of closed-book 25.64% while using 1,974x more document tokens than MEMORILLA. LaMP-7 ROUGE-L 43.13->48.37 (closed book ~43); all baselines except xRAG (46.84) within one point of closed-book. LaMP-4 ROUGE-L 18.15 vs full-context 14.21, 474x fewer tokens.
- End-to-end latency 0.74s (MEMORILLA) vs 19.9s full-context answer generation.
- Where memory does NOT help: MemoRAG leads NarrativeQA ROUGE-1/L 21.80/20.51 vs 19.68/19.31 and PV4 67.88% vs 66.65% (needing 50x/690x more tokens — verbatim access wins); PubMedQA (four abstracts totaling 324 tokens): LLMLingua-2 69.00%, four baselines 67.00%, MEMORILLA 59.00% — small collections do not benefit.
- Full context trails MEMORILLA on every benchmark except PubMedQA and on 20 of 21 metrics; RAG-50 exceeds full context on 15.
- Analysis: NarrativeQA question types — MEMORILLA +4.91 ROUGE-L on "why" and +7.02 on "how" (conceptual/causal reasoning); RAG-50 +3.45 on "who" and +2.93 on "which" (verbatim entity recall) — compression preserves global structure but loses exact surface tokens. Complementarity on FactKG: 15.9% MEMORILLA-only vs 10.0% RAG-50-only; PMv2 27.1% vs 9.2%; the union (oracle) exceeds either method on every benchmark -> hybrid memory+retrieval is future work. Joint-error analysis: PV4 errors require linking facts that each appear somewhere (combining failure, not finding failure); on FactKG both methods are biased toward judging claims false — true claims are 89.5% of joint errors but only 28.7% of joint-correct -> a miscalibrated decision threshold, not missing evidence.
- Personalization case (PMv2): MEMORILLA personalizes a generic query using remembered iron-deficiency anemia history despite NO lexical overlap between question and conversation history.
- TextWorld: avg@3 0.186->0.242, pass@3 0.250->0.375 vs full-history in-context learning (ICL); untrained memory is WORSE than ICL (0.153/0.225), so the gain comes from learning; the agent completes 37.5% of held-out games in >=1 of 3 attempts vs 25.0%; ICL exhausts the 4,096-token budget on 71% of rollouts vs 58% for MEMORILLA; trained memory helps escape navigation loops and execute keyed action sequences (unlock then open a container); remaining failures concentrate in the longest games (50-turn backtracking).

## Actionable Insights
- Replace full-context feeding with a trained latent memory module for LLM assistants holding accumulated history: 394x token reduction (geometric mean), 0.74s vs 19.9s latency, and quality RISES rather than drops (49.68 vs baselines <=41.92; FactKG 84.33 vs full-context 80.43). E.g. a customer-support assistant with 5,000 past conversations — embed once, 16 soft tokens per query, personalized answers without re-sending history every query.
- Memory beats retrieval when query wording differs from stored wording (preference recall, cross-document relations): PMv2 44.6 vs 30.9; multi-entity fact-checking stays in the 80-89 range while RAG falls to 51.75. E.g. recommend products to a returning user — memory captures preferences semantically while RAG misses because the user never repeats old wording.
- Use hybrid memory + RAG for exact entity recall: MEMORILLA wins conceptual questions ("why/how" +4.91/+7.02), RAG wins verbatim recall ("who/which" +3.45/+2.93), and the union oracle beats either on every benchmark. E.g. a knowledge assistant — memory tokens for reasoning plus retrieved tokens for names/IDs/numbers, combined before generation.

## Assumptions & Limitations
- Conditions: corpus must be embeddable (frozen encoder); the memory module must be trained (3-stage curriculum, ~3.3M examples, 194M params) — NOT drop-in; encoder+decoder pairing tested on Qwen3 only; fixed K memory budget.
- Authors admit: loses fine-grained factual details (document encoder never trained for memory compression); cross-model-family transfer untested (Qwen encoder+decoder pairing); may not carry to coding domains; LLM decoding dominates latency, so efficiency gains show mainly for LARGE collections; privacy — stored embeddings encode sensitive information (consent needed; but deletable on request / keepable on device since memory is external to the LLM).
- Not stated: PersonalizationV4 is fully synthetic (GPT-5 personas) — real-user generalization untested; TextWorld is a toy text-game environment, production agent tasks untested; PMv2/PV4 evaluation uses cosine-nearest-neighbor among predefined answer choices (not free-form); training is heavy (2 frozen models 4B+8B + 194M trainable + curriculum) vs pure RAG; compression is intrinsically lossy — exact recall needs the RAG hybrid; claim-verification threshold miscalibration needs post-hoc calibration; the "20x-4,212x" range includes best-case savings (actual per-benchmark savings vary 19x-1,974x); ComMer baseline only via reported results (not re-run).
