# [2610.11963v1] Can LLMs Fix It Without Code? Toward Automated Verification of No-Code Bug Fixes

## Problem
- Bug reports not requiring source-code change ("invalid reports": user misconfiguration, outdated version, conflicting extension, misunderstanding) chiếm substantial share: manual inspection 7,000+ reports 5 open-source projects → 33.8% bug-labeled reports misclassified (Herzig et al.); industrial case study: 14–17% submitted reports invalid nhưng vẫn mất 16–18 calendar days to resolve — bằng valid reports dù KHÔNG cần code change (Laiq et al.). Prior evaluation of LLM-generated "no-code fixes" (direct user to change setting / update version / adjust workflow) chỉ dùng text similarity (BERTScore 0.81–0.82 hẹp mọi model) + LLM judge — KHÔNG show fix có work khi user follow không; LLM judge inherits documented biases. Gap: execution-based verification cho no-code fixes — apply fix in real environment, check symptom persists or disappears (tương tự SWE-bench cho code patches, nhưng chưa ai làm cho no-code, và chưa ai treat executor choice as experimental variable).

## Contribution
- Rollback-based, execution-driven pipeline (pipeline rollback-based, execution-driven): mỗi bug report → (1) apply maintainer ground-truth fix, (2) scripted sanity gate #1 (bug ABSENT on fixed state), (3) scripted rollback → buggy state, (4) scripted sanity gate #2 (bug PRESENT on buggy state), (5) apply candidate LLM fix bằng executor agent qua browser GUI, (6) deterministic issue-specific checker đọc browser state quyết định bug còn không. Hai sanity gates SCRIPTED (không agent) → environment validity independent of executors under study. Executor's own success claim recorded but NEVER used as verdict.
- Treat executor choice as first-order experimental variable: 3 executors khác providers (2 CUAs + 1 multimodal agentic LLM), validate vs double-blinded human execution (RQ3).
- Evaluate 322 fixes (12 LLM configurations × 3 runs × 9 reproducible issues; Agentic-Kimi 25 fixes — 2 runs missing issues 25057/45912).

## Method (tóm tắt cốt lõi)
- Benchmark: Gön et al. invalid Brave browser reports (302 annotated → 51 candidates subclass Faulty Configuration & Environment Setup / Wrong Version (Already Fixed) / External System & Dependency — 3 subclasses có resolution là executable action → 38 không setup được trong Linux container (platform khác, live backend, thiếu info), 4 không exhibit bug → 9 issues effective (17.6%). Subclass sizes: Faulty Config 5 issues/178 fixes, Wrong Version 1/36, External 3/108.
- 12 configurations = 4 pipelines × 6 backbones: Vanilla (Gemini 3.1 Pro Preview, GPT-5.4, Claude Opus 4.6, GLM-5, MiniMax M2.7, Kimi K2.5); Ablation No-Prior (Gemini, Kimi); RAG (Brave wiki + historical invalid reports, Zembed-1 embeddings LanceDB, top-20 NN/corpus, chronological filtering chống data leakage, Zerank-24 cross-encoder rerank → top-5 contexts; Gemini, Kimi); Agentic Web Search (WebThinker Think-Search-and-Draft, Serper API, exclude canonical original-issue page chống leakage; Gemini + Gemini 2.5 Flash search loop, Kimi).
- Pipeline mechanics: GT fix classified version-type (Docker container chạy newer fixed Brave release) vs GUI-type (container reported version + apply maintainer fix qua GUI). Per-fix episode: fresh container, buggy value pre-seeded 3 issues; executor apply fix ≤20 steps qua shared action interface; version-type: khi executor mở brave://settings/help, harness switch container sang fixed build (resolution rate trên issues này phụ thuộc executor có perform update không).
- Executors: OpenCUA-72B (open-weight CUA, greedy T=0), Claude Sonnet 5 computer-use (default sampling), Meta Muse Glimmer-30B (open-weight agentic, custom function-calling schema vì no official computer-use harness, T=1.0 top-p 0.95). Task prompt identical (bug report + fix text).
- Checker: deterministic, issue-specific, đọc browser state (preference files qua Chrome DevTools Protocol, rendered page property) tied to reported symptom → actual result still present? Only issue-specific code trong pipeline (replication package).
- Aggregation: fix resolved if checker reports bug absent ≥1 of 3 runs (episodes stochastic; failure 1 run có thể executor error); non-applicable if executor declared BLOCKED ≥2/3 runs. 3 runs/fix × 3 executors.
- Human validation (RQ3): 75/322 random sample (fixed seed, 95% ±10% Cochran finite-population p=0.5); 2 author-executors double-blinded (không thấy config tạo fix, không thấy agent outcomes); execute fix "literally" (không judge correctness) trên identical buggy starting state; compare executor resolved verdict vs human outcome, Wilson intervals, Cohen's κ.

## Key Findings
- RQ1 overall (322 fixes): resolution rate 49.7% (Sonnet 5, 160), 45.7% (OpenCUA-72B, 147), 14.6% (Muse Glimmer, 47); applicability 66.1%/99.1%/70.5% (213/319/227); resolution among applicable fixes 69.5%/45.8%/18.1% (148/146/41).
- V-Claude (Claude Opus 4.6 Vanilla) strongest under Sonnet 5: 74.1% (applicability cao nhất 88.9%) — nhưng KHÔNG stable: 3rd under OpenCUA (51.9%, tied V-Gemini), 2nd under Muse Glimmer (25.9%). Under OC: RAG-Kimi + Agentic-Gemini tied first 55.6%; under MG: Agentic-Kimi led 28.0%. Lowest per executor: 25.9% V-MiniMax (S5), 33.3% V-Kimi (OC), 0.0% V-Kimi (MG).
- Pipeline comparison backbone-fixed: Gemini — Agentic highest cả S5 (63.0%) và OC (55.6%); Kimi — Agentic highest S5 (56.0%), RAG highest OC (55.6%). RAG-Kimi vs V-Kimi OC: 55.6% vs 33.3% (+22.3pp) nhưng EQUAL dưới S5 → pipeline enhancement benefit EXECUTOR-DEPENDENT.
- Per subclass: Faulty Configuration best under OC 65.7% (S5 43.8%, MG 13.5%); External System best under S5 59.3% (OC 25.0%, MG 21.3%); Wrong Version single issue: S5 50.0%, OC 8.3%, MG 0.0% (Sonnet completes update + gradient selection issue requires).
- RQ2 executor sensitivity: within-executor run spread ≤3.4 points (S5 38.8%–42.2%) — differences between executors EXCEED run-to-run variation (systematic, not noise); single configuration resolution rate differs across executors 38.8% average (range 25.9–48.1, 95% bootstrap 31.2–52.1); all three executors same verdict only 46.9% fixes; pairwise agreement 62.4%/64.3%/67.1% (κ=0.25/0.28/0.30); config rankings Kendall τb 0.13 (S5-OC), 0.45 (S5-MG), 0.05 (OC-MG) — nearly unrelated; excluding 3 version-dependent issues agreement DROPS further (κ 0.22/0.24/0.17, all-agree 40.7%).
- Run-level: all-3-runs same verdict 82.3% (S5)/73.9% (OC)/92.2% (MG); any-run aggregation adds fixes 160 vs 136 (S5), 147 vs 109 (OC — least stable executor, +38), 47 vs 35 (MG +12); majority vote 39.8%/30.7%/9.9% — ordering unchanged.
- Per-issue extremes: 37372 OC resolved ALL 36 fixes (checker lenient: expected value = browser default not stored explicitly → checker accepts absence of preference → general settings reset counts as resolution) vs S5 20, MG 12; 24747 S5 19 vs OC 0, MG 0; version-dependent issues S5 resolved most (16/18/29 for 22252/25379/31108); 25379 OC 3 (update alone insufficient — gradient must be chosen after), MG 0; MG resolved ZERO fixes on 24747, 25057, 25379, 45912.
- Termination signals ≠ verdict: explicit verdict episodes S5 83.0% (50.2% DONE, 32.8% BLOCKED), OC 59.7% (55.1% DONE, 4.7% BLOCKED), MG 44.9% (13.4% DONE, 31.6% BLOCKED); step-budget exhaustion 16.3%/40.2%/55.1%. Checker found bug resolved in 621/1,146 DONE episodes (54.2%), 162/1,077 budget-exhausted (15.0%), 18/667 BLOCKED (2.7%) — DONE episodes fail 45.8%, exhausted episodes resolve 15%. Version-dependent issues: S5/OC/MG said DONE while checker failed 7/121/1 of 324 episodes; checker passed without DONE 54/38/26. Agent's own completion signal would BOTH inflate AND deflate.
- RQ3 humans: 2 authors agree 78.7% (59/75, κ=0.54), human 2 resolved more (29 vs 25). Executor consensus agreement: Sonnet 5 88.1% (κ=0.74), Muse Glimmer 79.7% (κ=0.48), OpenCUA-72B 66.1% (κ=0.28). Mismatch direction: OC 20 mismatches → 13 FALSE POSITIVES (counted resolved, humans didn't); MG 12 mismatches → 10 FALSE NEGATIVES (didn't resolve although humans did — consistent 55.1% budget exhaustion); S5 both directions (5 FP, 2 FN). Sample resolution counts S5 33, OC 33 vs humans 25/29 — S5 + OC OVERSTATE, MG UNDERSTATES. Majority vote: 86.4%/72.9%/81.4% (ordering unchanged, ≤6.8% change).
- BERTScore analysis (5.2): 108 fixes failing ALL 9 attempts got BERTScore F1 0.757–0.867 (median 0.831) — within/above Gön et al.'s 0.81–0.82 all-fix range; 214 fixes ≥1 executor resolved scored SAME (median 0.832, mean 0.824 vs 0.823); scores vary more between issues than within (issue 25379 avg 0.762 vs 0.818–0.846 others) → similarity reflects reference wording, not fix correctness; single threshold cannot separate working from failing fixes.
- Scarcity finding (5.4): 302 annotated → 51 candidates → 9 executable — no-code fixes frequently entangled with state the report does NOT capture (accumulated user profile, OS/hardware config, third-party service behavior at report time, server-side change local rollback can't undo); issue trackers leave NO structural trace (invalid reports unlabeled, resolutions unlinked to commits) → dataset construction is a research problem (automate recognition of no-code resolutions in maintainer comments).

## Actionable Insights
- Đừng gửi LLM-generated no-code fix cho user KHÔNG verify: ngay cả best executor (Sonnet 5) chỉ 49.7% fixes resolve bug (39.8% majority vote); best config 74.1%. Ví dụ: support bot trả "update Brave lên version mới + chọn gradient X" cho user báo lỗi — execution pipeline trong Docker pinned build verify trước khi gửi; chỉ gửi fixes checker-confirmed.
- Chạy execution-based evaluation với ≥2 executors + calibrate vs human: executor choice shift 38.8% average, rankings τb 0.05–0.45 (nearly unrelated), all-agree chỉ 46.9% — 1 executor ≠ neutral instrument. Ví dụ: đánh giá agent QA tool của bạn với Claude computer-use VÀ open-weight CUA; nếu OpenCUA-style executor agreement 66.1% (overstate false positives 13/20) → dùng Sonnet-class executor (88.1%, κ=0.74) làm primary, calibrate bằng 75-fix human double-blind sample.
- Tách executor signal khỏi deterministic checker: agent DONE ≠ bug gone (45.8% DONE episodes fail, 15% budget-exhausted resolve) — NEVER dùng agent's own completion claim làm verdict. Ví dụ: pipeline verify fix retail-app của bạn: checker đọc app state qua debug protocol, agent chỉ apply; đồng thời dựng 2 scripted sanity gates (bug absent on GT-fixed state, present on rolled-back state) trước khi thử fix candidates.

## Assumptions & Limitations
- Điều kiện: bug phải re-establishable trong controlled Linux browser environment (chỉ 17.6% candidates qua gates — version-type hoặc GUI-type fixes trên pinned builds); cần deterministic issue-specific checker per report (only issue-specific code); double-blinded human time cho calibration.
- Paper thừa nhận (threats): executor có thể misapply/partial/unrelated state change; 20-step budget cut off episodes có thể đã thành (MG 55.1%); harnesses KHÔNG identical (S5 native computer-use, OC own action format + screenshot history, MG custom function-calling schema → RQ2 = executor+harness comparison); sampling settings khác (OC greedy T=0; MG T=1.0 top-p 0.95 — high temp benefits more from any-run aggregation); checker validity (issues 25057/37372 lenient — general settings reset counts); applicability depends on executor judgment (OC only 4.7% BLOCKED); buggy-state fidelity (2 reports no version → nearby pinned build); human executors là authors (blinded but moderate agreement κ=0.54, consensus set 19 resolved fixes, intervals wide, NO significance tests); single application Brave + single benchmark + 17/51 platform-specific excluded; Wrong Version = SINGLE issue.
- Limitation paper KHÔNG nói: 9 issues total → subclass breakdown (5/1/3) underpowered (Faulty Config vs External comparisons descriptive only); Docker/Linux-only — Windows/macOS-specific invalid reports (17 excluded) hệ thống khác với evaluated; executor cost per episode (2×RTX-class GPUs for OpenCUA-72B 72B inference per 322 fixes × 3 runs × 3 executors ≈ 2,898 episodes) — real-world deployment cost measurement missing; fixes chỉ Brave product knowledge — generalization sang app khác unstudied (future work nêu rõ); no-code fix GENERATION quality improvement directions beyond pipeline variants chưa explored (RAG/Agentic gains inconsistent); human "execute literally" protocol — humans don't judge fix correctness, so ambiguous fixes admitting multiple readings inflate mismatch; 3-run any-run aggregation inflates less-stable-executor rates (+38 OC) — cross-executor comparisons under any-run rule biased toward volatile executors.
