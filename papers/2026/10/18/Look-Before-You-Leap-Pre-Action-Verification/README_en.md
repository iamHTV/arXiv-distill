# 2609.11957v1 Look Before You Leap: Pre-Action Verification for LLM Agents

## Problem
- LLM agents act through shell commands and code edits. A wrong action does not always fail loudly: it can fail silently — the action appears to succeed, raises no signal, and the error propagates into later steps, quietly invalidating everything after it. A model cannot reliably catch its own mistakes by introspection, and post-hoc repair only triggers once an error is observed — which a silent failure by definition never is. Prior work (agent benchmarks, tool-use, self-repair) measures end-to-end task success but does not isolate why an action fails, and repairs only after the error surfaces.

## Contribution
- A common pre-action verification framework: fix the action's correct effect by construction before any executor runs, making silent failure a measured quantity, with a success / clean failure (refused, recoverable) / silent failure (applied to wrong target, no signal) taxonomy plus abstention-based operating points.
- A shell-command benchmark: 9,930 commands over 482 real tools, with an anti-circular construction (invalid commands confirmed by behavioral oracles independent of the verifier: which, bash -n, flag sets extracted from --help/-h/man) — the verifier is not graded against its own assumptions.
- A code-edit benchmark: 640 edits over 224 real Python files isolating the apply step (post-edit target synthesized first, then rendered into a format and perturbed only on its location surface) — 23,040 trials, exposing a content-anchored vs location-anchored safety dichotomy.
- Two deployable guards: selective grounding (a two-tier gate) for commands and Robust-Apply (an anchor-and-verify meta-applier) for edits.

## Method
- Shell verifier: three checks — syntax (bash -n), binary existence (which), flag validity (membership in the flag set extracted from --help/-h/man); subcommand-aware (git commit flags treated separately from git flags); abstains when a tool yields no extractable flags (coverage 91.1%).
- Edit formats: content-anchored (search/replace exact, whitespace-normalized, fuzzy at threshold τ; unified diff via real GNU patch at fuzz 0/2) vs location-anchored (line range, whole-function-by-name); perturbations: reindentation and line shifts.
- Robust-Apply (Algorithm 1): require minimum anchor size Kmin → try exact, then whitespace-normalized match, apply if unique; otherwise take top-2 fuzzy matches and accept only when s1 ≥ τhi and s1 − s2 ≥ δ, committing through real patch; else refuse with a clean-fail signal. Params (Kmin, τhi, δ) = (2, 0.90, 0.20).
- Operating points: sweeping the abstention rule traces an (applicability, safety) frontier; the deployed guard maximizes applicability subject to a safety floor.

## Key Findings
- Shell: the full configuration detects 95.8% of invalid commands at a 10.0% false-positive rate (precision 0.975, F1 0.966); tool-clustered bootstrap 95% CIs: recall [0.944, 0.971], FPR [0.078, 0.122]; warm median 2.55 ms per command (p95 2.78 ms), one-time cold extraction p95 2.85 s, cached thereafter.
- Decomposition: syntax+binary checks are oracle-exact — zero false positives, recall 0.500 (nonexistent-binary and malformed-syntax caught perfectly, recall 1.000 each); the flag check supplies the remaining recall and accounts for ALL 198 false positives (all real flags the parser missed: 48.5% single-dash one-char, 29.8% single-dash multi-char, 21.7% double-dash; spread over 95 of 482 tools, at most 8 per tool); invalid long/short flags are caught at 0.916, bounded by the 91.1% extraction coverage, not the method.
- Selective grounding: abstain exactly on single-dash multi-character tokens (lossless by construction — no injected invalid error is in that class) → same 0.958 recall at 7.0% FPR, Pareto-dominating the naive policy. As a deployed gate: oracle-exact checks block (recall 0.500 at 0% FP) while flag suspicions become non-blocking warnings (7.0% warn-rate on valid commands).
- Edit dichotomy: content-anchored formats NEVER misapply silently (0.000) but trade applicability (SR-exact stress success 0.571, SR-fuzzy 0.977, CI [0.972, 0.981]); location-anchored formats fail silently: a one-line shift leaves line ranges applying nothing correctly while silently corrupting 99.1% of files, and whole-function edits hit the wrong same-named function 12.7% of the time even unperturbed (duplicate-name collisions).
- Policy matters too: a permissive first-match policy raises content-anchored silent rates from 0.000 to 0.020 (exact) / 0.023 (whitespace-normalized) — the format still dominates (2% vs 99%). Multi-hunk: fuzzy silent rate compounds to 39.3% and never abstains; unified diff stays 0.000. Replication on 55 edits from the requests library: SR-fuzzy silent 0.025, line ranges 1.000 — the effect is intrinsic to the formats.
- Robust-Apply: one silent misapplication in 8,320 trials (0.01%) across every format, perturbation, multi-hunk edit, and the third-party codebase, vs native rates as high as 99.1%; it converts 100% of aggressive fuzzy's silent misapplications into recoverable clean failures while preserving 60% of fuzzy's applies; applicability 0.51 vs 0.98 on perturbed single-hunk edits; silent ≤ 0.05% across τhi ∈ [0.85, 0.95], δ ∈ [0.10, 0.30]. The single silent case: GNU patch committed a hunk at a shifted location at nonzero fuzz (rate 0.0005) — constraining the fuzz factor removes it.

## Actionable Insights
- The action representation, not the model, decides catchability: express edits content-anchored (search/replace, diff) rather than by line number or function name — line ranges corrupt 99.1% of files under a one-line shift while search/replace is silent-free (0.000). Example: a coding agent should emit search/replace blocks, not "replace lines 40–52".
- Gate every action with an oracle-exact core plus an abstaining soft check: bash -n/which/exact-match block at 0% FP while catching half of all errors; flag checks and fuzzy matching become non-blocking warnings — 2.55 ms median cost, no model call. Example: wrap an agent's terminal with a syntax+binary check before running any command.
- Use a refuse-when-unsure policy (Robust-Apply Kmin=2, τhi=0.90, δ=0.20): 0.01% silent while still applying 60% of fuzzy cases; never combine aggressive fuzzy matching with no downstream check (tests/review) — the most dangerous combination.

## Assumptions & Limitations
- Conditions: non-adversarial environment (a buggy/hallucinating agent, not a malicious one), a faithful executor; the verifier sees the action text and local environment but NOT the intent — it guards realizability (can the action be executed validly and unambiguously), not semantic correctness.
- Limitations acknowledged: invalid commands and perturbed edits are synthetic and need not match the distribution of real model errors (though the failure mechanisms — extraction gaps, location drift — are intrinsic to the representations); the zero-FP claim carries deployment caveats (bash -n rejects incomplete fragments, which misses aliases, shell functions, session-updated PATH — treat these as abstentions); the real-model probe is light (42 commands and 9 edits from an Anthropic Claude model, version not recorded, all valid) so it speaks only to the false-positive side; one Linux host with Python/shell tooling — exact rates need not transfer to other languages.
- Not stated: the 91.1% flag-extraction coverage means ~9% of tools are always abstained (unguarded); the fuzzy τ sweeps were tested only on Python files; valid commands come from the tldr corpus, which may diverge from what agents actually emit; the 2.55 ms median is warm-cache — the cold path costs 2.85 s per new tool.
