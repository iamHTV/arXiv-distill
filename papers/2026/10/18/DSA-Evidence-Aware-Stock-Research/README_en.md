# 2608.26990v1 DSA: Evidence-Aware LLM-Agent Orchestration for Multi-Market Stock Research

## Problem
- LLMs can summarize financial information, but an operational stock-research system must first assemble heterogeneous evidence, expose unavailable data and model capabilities, and control how generated opinions affect a final report. Prior work (FinGPT, FinAgent, FinCon, TradingAgents) focuses on endpoints (trading, forecasting); no one isolates the systems problem: markets expose unequal fields, providers expose unequal structured-output and tool capabilities, and core role agents differ from optional extensions — these asymmetries should remain observable, not hidden behind a uniform conversational interface.

## Contribution
- A five-stage evidence-to-report architecture for repeatable LLM-based stock research across heterogeneous markets and data sources.
- Separates model routing from research logic; distinguishes configured core role agents from optional Strategy Skill extensions with different output-admission mechanisms.
- Profile-level control semantics for evidence state, capability admission, output validation, risk handling, and observable failure — without claiming one shared implementation for every profile.
- An open-source reference implementation plus a frozen, claim-mapped conformance evaluation whose boundary is software behavior, NOT analytical or financial effectiveness.

## Method
- Five stages: (1) evidence acquisition — market adapters retrieve quotes, bars, fundamentals, announcements, news, sentiment; a screening engine (deterministic filters, factor scores, risk constraints, optional LLM reranking) produces a bounded candidate set; (2) structured context construction — technical features, bounded evidence blocks, normalized availability/degradation states (available, missing, not_supported, fallback, stale, estimated, partial, fetch_failed), source/timestamp metadata retained; (3) model and capability routing — provider-specific request formats and model names resolved below the workflow (hosted, compatible endpoints, provider-specific routes, local models); capability admission is route-specific; (4) optional role reasoning + controlled synthesis — core role agents (technical, intelligence, risk, decision) via role-specific parsers; Strategy Skill opinions pass a signal-eligibility partition O_ext* = {o ∈ O_ext : valid_signal(o)}, invalid ones move to diagnostics; disagreement summary D = Disagreement(O_core ∪ O_ext*); decision d_0 = Synthesize(E, O_core, O_ext*, D); (5) report + optional context and diagnostics.
- Two execution profiles: default report profile (bounded context → generation model → validation → safeguards → render; batch/scheduled, fewer model calls) and agentic profile (adds role agents, Strategy Skills, disagreement-aware synthesis, post-synthesis risk override RiskGuard). RiskGuard three-state: veto buy→hold; configured downgrade buy→hold/sell, hold→sell; never upgrades.
- Six regional market paths: mainland China, Hong Kong, US, Japan, South Korea, Taiwan; 15 bundled Strategy Skills (moving-average signals, trend following, volume breakouts, event-driven analysis, growth quality, expectation repricing, market themes, Chan theory, wave theory); surfaces: CLI, API, browser, desktop, scheduled jobs, messaging adapters.
- Evaluation: frozen Git revision 0ca56cbee2dff5cf23b1fc59c16e2d48e61ba85c (26 Aug 2026), Python 3.10.9, pytest 7.1.2, LiteLLM 1.89.3; manifest of 1,458 cases, one deselected (native-Windows route), 1,457 executed with zero failures/errors/skips in 102.532s; 596 cases retrospectively mapped to 6 contract families: evidence context 74, model backends/routing/config 194, agent orchestration/routing 85, runtime facts/disagreement/risk/guardrails 87, strategy registry/tool surface 60, strategy attribution/outcome lifecycle 96.

## Key Findings
- 1,457/1,457 portable backend contract tests pass (zero failures/errors/skips, 102.532s) — establishes implementation conformance for the tested software contracts.
- 596/596 cases in the 6 contract families mapped to the LLM-agent architecture all pass — evidence-state distinctions, unsupported-capability states, role sequencing, structured role outputs, disagreement entering synthesis, and conservative risk-override transitions are all exercised.
- [NO BENCHMARK] on report quality, forecasting accuracy, or investment returns — the paper explicitly disclaims: "This evidence establishes implementation conformance... not superior report quality, forecasting accuracy, or investment returns."
- Boundary probe: native-Windows route unsupported (Codex App Server), Unix-shell assumptions in Docker-entrypoint tests — portability is delimited.
- Dependency sensitivity: one prompt-cache test timed out under LiteLLM 1.98.0 → pinned to 1.89.3.

## Actionable Insights
- Evidence-state discipline: never let missing data become neutral evidence — tag every evidence block with a state (available/missing/fallback/stale/partial/fetch_failed) and project those states into the prompt. Example: a VN-stock research agent whose data source fails writes "capital-flow: fetch_failed" into context instead of leaving the field blank (blank = model treats it as a neutral signal).
- Two-profile architecture: keep a cheap default path (report profile, batch/scheduled, fewer calls) and an expensive agentic path (roles + skills + disagreement + risk override) — don't force multi-agent on every request; compare both profiles on the same tasks with blinded rubrics before claiming the agentic path is better.
- Gate extension opinions: optional skill/plugin outputs must pass a validity partition before entering the evidence chain, invalid ones go to diagnostics; disagreement must be an explicit input to the decision agent; the risk override can only downgrade (buy→hold→sell), never upgrade.

## Assumptions & Limitations
- Conditions: research-report endpoint, no order placement; external strategy packages are trusted inputs under the current permission model.
- Limitations acknowledged: analytical validity (conformance ≠ factual accuracy/forecast quality); temporal validity (providers change, no immutable point-in-time dataset, look-ahead leakage not eliminated); inspection/provenance (optional snapshots retain selected not complete context, no exact replay, no claim-level provenance); model/strategy validity (a valid schema ≠ a correct conclusion; several bundled technical-analysis perspectives are disputed financial heuristics); security (external news/model outputs/skill packages may contain prompt injection, poisoned content, unsafe tool requests, secrets); generalization (uneven market coverage, post-exploration selected manifest, pinned environment).
- Not stated: tests authored by contributors with overlapping assertions — not independent observations; mocked services don't establish semantic quality under live data; no ablation isolating role decomposition, evidence-state disclosure, Strategy Skills, disagreement handling, or risk control; no provider comparison on quality/latency/token/cost under a common protocol.
