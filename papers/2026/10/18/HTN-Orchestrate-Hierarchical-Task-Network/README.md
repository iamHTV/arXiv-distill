# 2610.22195v1 HTN-Orchestrate: A Hierarchical Task Network Framework for Multi-Agent Orchestration

## Problem
- Orchestrating nhiều agents trên complex task đòi hỏi reconcile local subtask execution với global task planning. Hai họ existing approaches mỗi họ sacrifice một bên: (1) structured workflows (AutoGen, MetaGPT, AFlow — manual hoặc auto-generated) impose clear global structure nhưng FIX decomposition trước khi execution bắt đầu → findings từ local execution không reshape được planning sau đó; (2) runtime delegation (Magentic-One, AOrchestra, Agent Team của Apodex/Kimi K2.5) cho central orchestrator determine subtasks và assign agents khi execution proceeds, nhưng COUPLE task decomposition, subtask dispatch, result synthesis trong MỘT orchestrator, KHÔNG model explicitly subtask hierarchies hoặc precedence dependencies giữa sibling subtasks. Dynamic decomposition methods (ADaPT, ReAcTree) cho plan evolve nhưng support hạn chế cho complex dependencies. Gap: tension giữa adaptive local execution và structured global planning chưa resolve.

## Contribution
- HTN-Orchestrate: two-layer orchestration framework decouple global task planning khỏi local subtask execution qua hierarchical task network (HTN) explicit represent subtask hierarchies và precedence dependencies. Upper layer: Planner incrementally expands task network khi prerequisite results available. Lower layer: mỗi executable leaf subtask delegated cho Orchestrator coordinate nhiều workers.
- Kết hợp 3 cơ chế: (1) result-informed planning — defers decomposition decisions cho dependent subtasks đến khi prerequisite findings available; (2) AND-semantic synthesis — results propagate upward qua task hierarchy (leaf trả result của Orchestrator, non-leaf synthesize sau khi TẤT CẢ children complete); (3) rebuilding mechanism — retains supported evidence từ completed work để construct revised task network khi current decomposition không resolve được task. Là system DUY NHẤT có đủ 5 features (STR+RES+DEC+RPL+EVC) so với Agent Team (STR+RES), Workforce (STR+RES+DEC), ADaPT (RES+RPL), FlowSearch (STR+RES+RPL), ChatHTN (STR+RPL).
- Evaluation trên 5 benchmarks (web research, scientific reasoning, research workflows): outperform ReAct, Agent Team, DeepSeek Harness cùng backbone model — BrowseComp 89.73% (+2.45pp vs Agent Team, +15.80pp vs ReAct), SUPERChem 73.44% (+4.69pp, +8.21pp), FSR 43.33% (+3.33pp), FSO 79.00% (+4.00pp), PRL-Bench 46.00 (+10.19pp — gain lớn nhất).

## Method
- Task network T = (V, Eh, Ed): hierarchy edges Eh tạo rooted tree (parent decomposed thành children jointly address task); dependency edges Ed impose acyclic precedence constraints GIỮA SIBLINGS ((u,v) nghĩa là v cần result của u). Khác classical HTN planners (predefined library decomposition rules), Planner dùng LLM generate decompositions trong execution → network grow incrementally.
- Ready(v) ⇔ Ch(v) = ∅ ∧ v pending ∧ mọi u ∈ Pred(v) completed. Completed status bao gồm cả resolved lẫn open outcomes — downstream proceeds với whatever evidence prerequisite produced (resolved-or-open distinction chỉ feed synthesis và replanning).
- Planner (Algorithm 1): loop qua epochs; mỗi epoch: InitializeRoot(q, M) với M = evidence summary; PlanOrExecute mỗi ready planning leaf (xem original goal, task description, ancestors, summaries of relevant prerequisite results → mark direct execution HOẶC expand với children + sibling dependencies; validate coverage của parent task + acyclicity, revise nếu fail; depth/branching limits); dispatch ready executable leaves đến Orchestrators song song (wave); PropagateResults (record leaf results, recursively synthesize mỗi parent whose children all returned); settle wave hoặc stop for replanning; nếu root resolved → return synthesis; nếu không → e+1, CollectEvidence extract supported findings từ completed VÀ partial reports thành M (condition new network, planning context chứ KHÔNG auto-mark subtask completed); rebuild limit B, budgets exhausted → synthesize evidence đến giờ + report unresolved requirements (output phản ánh sufficiency of evidence, KHÔNG treat stopping condition như success).
- Orchestrator (Algorithm 2): mỗi leaf nhận stable context C_v (original task, leaf objective, ancestor descriptions, prerequisite result summaries); maintain reports R_v + active assignments A_v; decision loop chọn dispatch / wait / finish. Dispatch: select worker roles + generate task-specific instructions based on current evidence — initial investigation có thể followed bởi focused search hoặc verification khi report reveal gap/disputed claim. Progressive collection: follow-up work scheduled while other assignments active. Limits: concurrency, dispatch rounds, execution time. Finish: stop unneeded work, SynthesizeLeaf (summary, resolved/unresolved outcome, evidence references). Outcome phản ánh sufficiency of evidence chứ không phải workers stopped hay verifier invoked.
- Setup: backbone DeepSeek-V4.1-Flash (high reasoning effort cho orchestration agents, LOW cho workers). Workers 2 roles: research + verification. Tools: web search, webpage retrieval, scholarly search, Python execution, file reading, report submission (search/retrieval disabled cho FSR/FSO/SUPERChem/PRL-Bench). Config: max task-network depth 2 (root depth 0), ≤4 children/node, ≤3 concurrent workers, ≤12 orchestration rounds/epoch, rebuild tối đa 1 lần.
- Benchmarks: BrowseComp (hard-to-find info qua persistent web browsing, accuracy), FrontierScience-Research (FSR, open-ended research subproblems, success rate = ≥7/10 rubric points), FrontierScience-Olympiad (FSO, olympiad physics/chemistry/biology, accuracy), SUPERChem text-only 256 questions (multistep chemistry, accuracy), PRL-Bench (theoretical/computational physics research tasks từ published papers, mean % satisfied rubric criteria 0–100). Baselines: ReAct + Agent Team (FrontierAgent), DeepSeek Harness (Minimal Mode, single-agent persistent shell + file editor, +web search cho BC).

## Key Findings
- Main results: BC 89.73% (ReAct 73.93%, Agent Team 87.28%, DSH 80.33%; chỉ GPT-6 Astra 91.50%, Kimi K3 91.20%, GPT-5.6 Sol 90.40% cao hơn — đều frontier-scale models). FSR 43.33% (Agent Team 40.00%, Meta Muse Spark 38.00%, GPT-5.5 33.90%, ReAct 25.00% — margin +18.33pp vs ReAct, +3.33pp vs Agent Team). PRL-Bench 46.00 (Gemini 3.1 Pro 44.27, +1.73; Agent Team 35.81, +10.19 — largest gain on any benchmark; DSH 39.89). FSO 79.00% (= Gemini 3.1 Pro; Agent Team 75.00% +4.00pp, DSH 76.00% +3.00pp). SUPERChem 73.44% (GPT-5.6 Sol 73.60% — chỉ thua 0.16pp; Agent Team 68.75% +4.69pp, ReAct 65.23% +8.21pp). Gains over Agent Team 2.45–10.19pp, largest ở tasks reward structured decomposition và iterative refinement.
- DSH (single-agent runtime) beat Agent Team trên PRL-Bench (39.89 vs 35.81) và match FSO (76.00 vs 75.00) — focused single agent competitive trên sustained-reasoning benchmarks; HTN-Orchestrate beat cả hai trên cả 5 benchmarks với open-weight model.
- Execution analysis (200-question BC subset): 165 shared successes với Agent Team — HTN finishes faster trên 112 (67.9%), median completion-time ratio 0.699. vs ReAct: HTN slower trên shared successes nhưng answer đúng 38 questions ReAct miss, miss 12 ReAct đúng (net +26). Average worker concurrency 2.47 vs 1.70 Agent Team (shared successes 2.42 vs 1.82); HTN spend 24.6% time với ≥4 active workers vs 11.8%; cũng spend more time với no active workers (planning/coordination/synthesis vẫn proceed).
- Internal statistics (correct n=184 vs incorrect n=16): tree depth 1.23 vs 1.19, leaves 3.95 vs 4.00 (tương tự), nhưng executed leaf instances 4.52 vs 6.31, worker invocations 21.04 vs 47.50, orchestrator rounds 20.21 vs 44.62, rebuild 14.7% vs 50.0% — similar final structures, substantially different execution histories.
- Dynamic decomposition + recovery: Planner tạo child subtasks tại nodes with prerequisite dependencies 79 lần trên 57/200 questions (result-informed planning xảy ra thường xuyên); rebuilding trên 35 questions, 27 ultimately correct.
- Ablations (200-question BC subset): HTN 92.0%; Upfront decomposition 90.5% (−1.5pp) — worker invocations 14→16, rounds 14→17, rebuild 17.5%→22.5%, median completion 25.23→30.02 phút (full system higher accuracy với LESS coordination và lower latency); Single-agent leaf execution 89.5% (−2.5pp) — leaf instances 4.67→6.15, rebuild 17.5%→32.0% (less effective research shifts burden sang Planner); No rebuilding 89.5% (−2.5pp) — leaf instances 4.67→4.12, worker invocations 23.16→19.01 (higher accuracy đi kèm additional research mà rebuilding enable).
- Case studies: Q193 (trace author of 1993 RPG supplement → 2015 children's book → father's radio program → station first broadcast year): result-informed plan narrow downstream search to returned author list, execute 4 leaves thay vì 5. Q501 (third song in 24-song blog list Dec 27, weekly-feature clue + 21st song's album): initial search fail → retain candidate albums, weekday features, rejected posts → rebuild với feature-based search + album-to-list matching → "Serial Killer" by Tobin Sprout (No rebuilding trả "Silent Night" — sai).

## Actionable Insights
- Hai lớp Planner/Orchestrator: Planner giữ hierarchy + dependencies và DEFER decomposition của dependent subtasks đến khi prerequisite results trả về; mỗi leaf có Orchestrator riêng coordinate workers. Ví dụ: research agent — đừng pre-plan cả tree; expand "phân tích X" chỉ sau khi "tìm X" trả kết quả (narrow downstream search to actual findings).
- Rebuild với evidence carryover, không phải restart: khi plan fail, extract supported findings từ completed VÀ partial reports thành evidence summary condition new network (không auto-mark completed). Ví dụ: web research找不到 target post → giữ candidate lists + rejected leads, rebuild với search strategy mới (Q501: đúng "Serial Killer" vs sai "Silent Night").
- Result-informed planning vừa chính xác hơn vừa rẻ hơn: upfront decomposition mất −1.5pp accuracy, +4.79 phút median, nhiều worker invocations hơn. Ví dụ: decompose sau evidence beat decompose upfront trên cùng task — apply cho mọi multi-step research pipeline.

## Assumptions & Limitations
- Điều kiện: method work khi task decomposable thành hierarchy với sibling dependencies; decomposition validated coverage + acyclicity; budgets bound network growth (depth 2, ≤4 children, 1 rebuild); workers cần tools phù hợp task (web search cho BC, disabled cho science benchmarks).
- Limitation paper thừa nhận (future work): scaling task-network depth cho problems yêu cầu deeper decomposition hierarchies; evaluating framework across additional backbone models (hiện chỉ DeepSeek-V4.1-Flash).
- Limitation CHƯA nói: tất cả experiments 1 backbone model — không biết gains có transfer sang model khác (đặc biệt smaller models); depth-2 cap nhân tạo giới hạn hierarchy complexity thực tế; rebuild limit 1 lần — tasks cần nhiều recovery cycles chưa test; BrowseComp ablation subset (200 questions) accuracy 92.0% khác full-set 89.73% (subset dễ hơn); FSR/FSO/SUPERChem/PRL-Bench disable search tools — result-informed planning ít material hơn trên science benchmarks; no cost/token accounting (worker invocations count nhưng không quy ra $); no statistical significance tests reported cho benchmark deltas.
