# 2610.37657v1 Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness

## Core Value (1 sentence)
HoS (Heads of Security) defends against prompt injection by training just 46,080 gate scalars (0.00007% of Llama-3.3-70B's weights) — per-head biases added to pre-softmax attention logits so each attention head learns to shift attention away from untrusted tokens — reaching 1-10% ASR against black-box RL-Hammer attacks while utility stays near base-model levels on every few-shot/multi-turn benchmark, whereas behavioral DPO defenses (SecAlign) collapse to 2.0% on GSM8K 1-shot.

## Problem
Indirect prompt injection (Greshake et al., 2023) occurs when a model mistakes attacker-planted instructions in external content (webpages, tool outputs, emails) for authorized commands. Prompt injection remains largely unsolved even on extensively evaluated systems (UK AI Security Institute 2025; Nasr et al., 2026), and is worse for open-weight models: comparable red-teaming shows Claude and GPT are substantially more robust than leading open-weight models (Dziemian et al., 2026). Prior defenses: (a) finetuning-based — SecAlign++ (Meta-SecAlign-70B, DPO on single-turn Alpaca data) — partly robust but degrades heavily on few-shot/multi-turn inputs; (b) architectural — ASIDE rotates data-token embeddings by a fixed π/2 angle — but breaks tool use, with only 10% utility on AgentDojo and near-zero on three other benchmarks. Gap: no architectural defense enforces instruction-data separation without fine-tuning the whole model — i.e., robustness without utility loss.

## Contribution
1. HoS: instruction-data separation via learned per-head attention gates — a channel-conditioned bias log σ(g) added to pre-softmax attention logits, training only L·C²·h scalars (Llama-3.3-70B: 46,080; GPT-OSS-20B: 18,432 including the sink channel) versus 349M (SecAlign) or 70B (full fine-tuning / ASIDE).
2. Stronger robustness to adaptive attacks than even GPT-5.6-Luna: an RL-Hammer attacker trained against HoS achieves only 3.2% training ASR vs 80.2% when trained against SecAlign (sparse reward signal).
3. Utility preserved where ASIDE and SecAlign break: near base-model accuracy on ARC-C, GSM8K, MMLU, MMLU-Pro in both 0-shot and few-shot settings, and ~100% instruction-completion rate on multi-turn AlpacaFarm — both baselines collapse.
4. Mechanistic analysis: causal head ablations + role-confusion probes show most heads ("red") shift attention away from untrusted content, while a minority ("blue") increase attention toward it to detect injections — detection rate 28.20% (blue-only) vs 11.03% base.

## Method
The HoS pipeline has 4 steps:
1. Token channeling: every token is assigned a channel from C = {TRUSTED, UNTRUSTED, TEMPLATE} — TRUSTED = system + user prompts + the model's own generation; UNTRUSTED = tool outputs; TEMPLATE = chat-template tokens including the BOS attention sink. Assignment is flexible (untrusted spans inside the user prompt, trusted tools); on the WASP benchmark all user-generated content is untrusted while non-modifiable web-UI elements are trusted.
2. Gate tables: each head k of layer ℓ has a table g(ℓ,k) ∈ R^{C×C} (GPT-OSS: C×(C+1) for its explicit attention-sink key-only channel). Gated attention: ã = softmax(qKᵀ/√dₕ + log σ(g)), where σ is the logistic sigmoid ∈ (0,1) — adding log σ(g) to a logit multiplies the unnormalized attention weight by σ(g), so near 1 = attend normally, near 0 = gate closed. Same mechanism as causal masking; a common shift is cancelled by softmax, so inputs whose tokens all share one channel are processed exactly like the base model.
3. Training: optimize only θ_gate = {g(ℓ,k)} following the SecAlign++ recipe — DPO objective + adapted Cleaned-Alpaca dataset: each preference pair combines a user instruction with an injected instruction in the untrusted segment; the preferred response follows the user instruction, the rejected response follows the injection. Same dataset as SecAlign isolates the training algorithm's effect.
4. Evaluation: (a) RL-Hammer black-box — Llama-3.1-8B-Instruct attacker trained with GRPO to rewrite attacker goals into injections, paired with an easy target in the same family; (b) white-box Claudini strengthened via an autoresearch loop (GPT-5.6-Sol, 50 iterations, 120-token suffix, 10¹⁷ FLOP budget); (c) utility on ARC-C/GSM8K/MMLU/MMLU-Pro at 0-shot and few-shot; (d) multi-turn AlpacaFarm (100 three-turn conversations); (e) agentic benchmarks AgentDojo, AgentDyn, LLMail-Inject, WASP; (f) role probes per Ye et al. (2026).

## KNOWLEDGE — Data & Concepts
- RL-Hammer on InjecAgent (black-box, ASR %): GPT-OSS-20B — undefended 97%, SecAlign 85%, HoS 10%, GPT-5.6-Luna 36% (attacker trained on Luna); Llama-3.3-70B — undefended 99%, SecAlign 82%, HoS 1%. HoS-trained attacker training ASR only 3.2% vs 80.2% for the SecAlign-trained one.
- White-box V38 attack (trained specifically against HoS): needs ~6×10¹⁶ FLOPs to reach 50% ASR on HoS vs 2.2–2.3×10¹⁶ on baselines (AgentDojo — 2.6–2.7× more compute); InjecAgent 3.0×10¹⁶ vs 8.5–9.5×10¹⁵ (3.2–3.6×), over 100 examples per benchmark.
- Utility on all-trusted prompts (GPT-OSS-20B, 5-shot): MMLU-Pro base 68.3% → SecAlign 59.4% → ASIDE 52.1% → HoS 67.2%; MMLU 5-shot base 82.3% → ASIDE 74.1%; GSM8K 1-shot base 93.6% → SecAlign 70.9%. Llama-3.3-70B 5-shot MMLU-Pro: base 56.3% → HoS 54.8%, SecAlign 16.1%; SecAlign catastrophes: GSM8K 1-shot 2.0%, MMLU 5-shot 28.4%, MMLU-Pro 5-shot 16.1% — manual inspection shows it answers the demonstration instead of the final question.
- Multi-turn AlpacaFarm (Llama-3.3-70B, 100 conversations): base 97–100% across turns; HoS ~100%; SecAlign drops to 43% when untrusted input appears at turn 2, 75% at turn 3, and stays degraded at 71%/82% on later fully-trusted turns (input at turn 1).
- Agentic benchmarks, Llama-3.3-70B (utility / utility-under-attack / ASR), AgentDojo: base 53.7/36.2/23.1% → SecAlign 67.0/63.9/2.1% (+13.3/+27.7/−21.0 pp) → HoS 58.5/52.4/0.9% (+4.8/+16.2/−22.2 pp). AgentDyn: base 33.7/30.9/18.5% → HoS 41.7/38.3/5.4% (+8.0/+7.4/−13.1 pp). WASP + LLMail: HoS Pareto-dominates on AgentDojo and WASP, Pareto-matches on AgentDyn and LLMail; per prose, HoS retains base utility on all benchmarks except AgentDyn and pushes ASR to near zero. (Table 3 extraction was partially mangled — WASP/LLMail rows use prose-level claims; per-cell values were not guessed.)
- ASIDE tool-use collapse: utility ~10% on AgentDojo, near-zero on the other three benchmarks — it loses the ability to call tools.
- LLMail-Inject detection (GPT-OSS-20B): send rate ≤1% in all configurations; detection rate base 11.03% → blue-gates-only 28.20% (~2.5×) → red-only 3.60% → full HoS 3.11%.
- Role confusion (role probes, Ye et al. 2026): HoS improves Tool-role recognition accuracy on clean AgentDojo and lowers the Userness (how much the span is perceived as coming from the user) of injection tokens — Userness correlates strongly with ASR.
- SecAlign pathology on LLMail: it interprets the system prompt's tool-use instructions as encouragement → tool calls in 29.95% of generations with fabricated recipients/bodies, yielding high ASR.

## INSIGHT — Mechanisms & Why
- [Constraining the parameterization prevents shortcuts] happens BECAUSE DPO-updating 349M parameters on narrow single-turn data learns spurious correlations with the training format → out-of-distribution collapse on few-shot/multi-turn inputs, while 46K gate scalars lack the capacity to learn format shortcuts. This means limiting the learning mechanism matters more than adding data when you want safety without utility loss.
- [Per-head specialization beats uniform suppression] happens BECAUSE gates are learned independently per head according to each head's role (instruction-following heads close the untrusted gate; other heads keep processing content so the model can still reason over it) — Appendix C's test of uniform suppression across all heads performs worse. This means segregation by head function is the condition for blocking injections while still comprehending data.
- [Blue heads exist because agents should detect injections, not only resist them] happens BECAUSE a minority of heads increase attention toward untrusted content, and the blue-only variant raises detection from 11.03% to 28.20% — supporting Abdelnabi & Bagdasarian's (2026) thesis that agents must both resist and recognize injection attempts. This means a good defense may need some heads oriented toward the attacker for warning.

## IDEA — What to Apply
1. For any agent workflow handling untrusted content (customer emails, web scrapes, tool outputs): tag token channels {TRUSTED, UNTRUSTED, TEMPLATE} in preprocessing before feeding an open-weight model — first step: write middleware that attaches channel tags by source (user input = TRUSTED, fetched content = UNTRUSTED); works for cloud and local models alike.
2. Harden an open-weight model for production: instead of full DPO (SecAlign) which risks utility collapse, add gate tables of L·C²·h scalars (pattern: 46,080 for Llama-3.3-70B) + DPO on injection preference pairs — first step: clone imperial-aisp/heads_of_security and load imperial-cpg/heads-of-security to test on your own AgentDojo-like scenario.
3. Measure "Userness" of injected content as an internal security metric: train a linear probe on hidden activations with role-tagged benign text; first step: for an agent that reads customer email, probe whether attacker spans are perceived as user — high Userness ≈ high ASR, block before action.
4. Budget attack-defense evaluation by FLOPs instead of binary ASR: report "compute needed to reach 50% ASR" (pattern: 6×10¹⁶ vs 2.2×10¹⁶ FLOPs) — first step: for internal red-teaming, fix a 10¹⁶-FLOP budget and compare ASR across candidate defenses instead of comparing single-shot ASR.

## WISDOM — General Principles
- Principle: "Constrain the mechanism, not the behavior" — restricting the trained module's parameterization (46K gates) prevents shortcuts from narrow data, while fine-tuning model behavior at scale (349M-70B params) brings collateral corruption on out-of-distribution inputs.
- Use when: hardening open-weight models for agents that process untrusted data while preserving few-shot/multi-turn/tool-use utility.
- Do NOT use with: closed frontier models (Claude/GPT already much more robust than open-weight); linear-attention architectures (no explicit per-key attention coefficient → the gate mechanism doesn't transfer directly); tasks that legitimately require following external instructions (e.g., installing a package from external docs).

## Assumptions & Limitations
- Conditions that must hold: the trust boundary must be supplied externally (you must know in advance which tokens are untrusted — tool outputs, fetched web); the model must use standard dense attention (explicit per-key attention coefficients); the preference dataset must contain injected instructions in untrusted segments.
- Limitations the paper acknowledges: (a) not an end-to-end defense — HoS doesn't decide which sources are trusted or what the user authorized; it only enforces the boundary when content is intended as data; (b) fixed training data (Cleaned-Alpaca, single-turn) — multi-turn/multi-instruction data would likely improve both HoS and SecAlign; SecAlign's failures are not claimed inevitable; (c) the attacker moves second — no finite evaluation proves absolute security; (d) not directly compatible with linear attention (Yang et al., 2024; 2025a) — a different gating mechanism would be needed.
- Limitations the paper does NOT state: (a) inference cost/latency of gate tables is never quantified (the FLOPs figures are attack budgets, not defense overhead); (b) evaluation covers only 2 model families (Llama-3.3-70B, GPT-OSS-20B) — unclear on sub-20B models that solopreneurs typically run; (c) the HoS-trained attacker's 3.2% training ASR is the basis for the robustness claim, but the sparse-reward explanation is speculation — weaker attacker optimization could be a training-loop artifact rather than proof of defense strength; (d) the blue-head detection benefit is measured on one benchmark subset (LLMail-Inject) via blue-only ablation — full HoS has not been shown to improve detection (full-HoS detection 3.11% is even below the 11.03% base).
