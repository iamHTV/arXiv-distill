# 2610.37657v1 Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness

## Giá trị cốt lõi (1 câu)
HoS (Heads of Security) chống prompt injection (tiêm lệnh qua dữ liệu) bằng cách huấn luyện 46,080 gate scalars (tham số cổng) — tức 0.00007% trọng số của Llama-3.3-70B — thêm vào attention logits (logit attention) tiền-softmax để mỗi attention head (đầu attention) tự học cách dời attention khỏi untrusted tokens (token không tin cậy), đạt ASR (attack success rate — tỷ lệ tấn công thành) 1-10% trước attack RL-Hammer black-box trong khi utility (hiệu dụng) gần như không đổi trên mọi benchmark few-shot/multi-turn — defense (biện pháp phòng thủ) hành vi bằng DPO (Direct Preference Optimization) lại sụp utility tới 2.0% trên GSM8K 1-shot.

## Problem
Indirect prompt injection (tiêm lệnh gián tiếp — Greshake et al., 2023) xảy ra khi model nhầm attacker-planted instructions (lệnh kẻ tấn công cài) trong external content (nội dung bên ngoài: webpage, tool output, email) thành authorized commands (lệnh được ủy quyền). Prompt injection vẫn largely unsolved (chưa giải quyết ngay cả trên hệ thống được đánh giá kỹ — UK AI Security Institute 2025, Nasr et al., 2026), và nghiêm trọng hơn với open-weight models (model weights công khai): red-teaming (đội tấn công thử) tương đương cho thấy Claude và GPT robust (chịu đựng) hơn nhiều so với leading open-weight models (Dziemian et al., 2026). Prior defenses (biện pháp phòng thủ trước): (a) finetuning-based như SecAlign++ (Meta-SecAlign-70B, DPO trên dữ liệu single-turn Alpaca) — robust một phần nhưng degrade (suy giảm) nặng trên few-shot/multi-turn; (b) architectural như ASIDE — xoay embedding (biểu diễn nhúng) của data token một góc cố định π/2 — nhưng phá vỡ tool use (gọi công cụ), utility chỉ 10% trên AgentDojo và near-zero trên 3 benchmark khác. Gap (khoảng trống): chưa có defense architecture nào enforce instruction–data separation (tách lệnh–dữ liệu) mà KHÔNG phải fine-tuning toàn bộ model → vừa robust vừa giữ utility.

## Contribution
1. HoS: instruction–data separation qua learned per-head attention gates (cổng attention học được theo từng head) — channel-conditioned bias (thiên lệch điều kiện kênh) log σ(g) cộng vào attention logits tiền-softmax, chỉ huấn luyện L·C²·h scalars (Llama-3.3-70B: 46,080; GPT-OSS-20B: 18,432 kể cả sink channel) so với 349M (SecAlign) hay 70B (full fine-tuning, ASIDE).
2. Robustness trước adaptive attacks (tấn công thích ứng) mạnh hơn cả GPT-5.6-Luna: RL-Hampler attacker đào chống HoS chỉ đạt training ASR 3.2% vs 80.2% khi đào chống SecAlign (sparse reward signal — tín hiệu phần thưởng thưa).
3. Utility preserved (được bảo toàn) trên ASIDE-broken và SecAlign-broken regimes: near base-model accuracy trên ARC-C, GSM8K, MMLU, MMLU-Pro cả 0-shot lẫn few-shot, và ~100% instruction-completion rate (tỷ lệ hoàn thành lệnh) trên multi-turn AlpacaFarm — trong khi hai baseline sụp.
4. Mechanistic analysis (phân tích cơ chế): causal head ablations (loại bỏ nhân quả từng head) + role-confusion probes (dò confusion vai trò) cho thấy majority heads "red" dời attention khỏi untrusted, minority heads "blue" tăng attention tới untrusted để detect injection — detection rate 28.20% (blue-only) vs 11.03% base.

## Method
Pipeline (quy trình) HoS gồm 4 bước:
1. Kênh hóa token: mỗi token assigned 1 channel từ C = {TRUSTED, UNTRUSTED, TEMPLATE} — TRUSTED = system prompt + user prompt + generation của model; UNTRUSTED = tool outputs (output công cụ); TEMPLATE = chat-template tokens gồm BOS token (attention sink — bộ hút attention). Assignment linh hoạt: untrusted spans trong user prompt, trusted tools; WASP benchmark: mọi user-generated content là untrusted, web UI elements không user sửa được là trusted.
2. Gate table: mỗi head k của layer ℓ có table g(ℓ,k) ∈ R^{C×C} (GPT-OSS: C×(C+1) vì explicit attention sink key-only channel). Attention gated: ã = softmax(qKᵀ/√dₕ + log σ(g)), trong đó σ = logistic sigmoid ∈ (0,1) — vì thêm log σ(g) vào logit tương đương nhân unnormalized attention weight với σ(g), nên near 1 = head attend bình thường, near 0 = gate đóng. Dùng cùng mechanism với causal masking; common shift (thiên lệch chung) bị softmax cancel → input toàn cùng 1 channel xử lý y hệt base model.
3. Training: chỉ tối ưu θ_gate = {g(ℓ,k)} theo SecAlign++ recipe — DPO objective + adapted Cleaned-Alpaca dataset: mỗi preference pair (cặp ưu tiên) = user instruction + injected instruction trong untrusted segment; preferred response (phản hồi ưu tiên) follow user instruction, rejected response (bị loại) follow injection. Cùng dataset với SecAlign → isolate effect của training algorithm.
4. Evaluation: (a) RL-Hammer black-box — attacker Llama-3.1-8B-Instruct huấn bằng GRPO (Group Relative Policy Optimization) rewrite attacker goal thành injection, paired easy target cùng họ; (b) white-box Claudini strengthened qua autoresearch loop (GPT-5.6-Sol, 50 iterations, suffix 120 token, budget 10¹⁷ FLOPs — phép tính dấu phẩy động); (c) utility trên ARC-C/GSM8K/MMLU/MMLU-Pro 0-shot + few-shot; (d) multi-turn AlpacaFarm 100 conversation 3-turn; (e) agentic benchmarks AgentDojo, AgentDyn, LLMail-Inject, WASP; (f) role probes theo Ye et al. (2026).

## KNOWLEDGE — Số liệu & khái niệm
- RL-Hammer on InjecAgent (black-box, ASR %): GPT-OSS-20B — undefended 97%, SecAlign 85%, HoS 10%, GPT-5.6-Luna 36% (attacker đào trên Luna); Llama-3.3-70B — undefended 99%, SecAlign 82%, HoS 1%. HoS-trained attacker training ASR chỉ 3.2% vs 80.2% SecAlign-trained.
- White-box V38 attack (đào riêng chống HoS): cần ~6×10¹⁶ FLOPs để đạt 50% ASR trên HoS vs 2.2–2.3×10¹⁶ trên baselines (AgentDojo, 2.6–2.7× compute); InjecAgent 3.0×10¹⁶ vs 8.5–9.5×10¹⁵ (3.2–3.6×), trên 100 examples mỗi benchmark.
- Utility all-trusted (GPT-OSS-20B, 5-shot): MMLU-Pro base 68.3% → SecAlign 59.4% → ASIDE 52.1% → HoS 67.2%; MMLU 5-shot base 82.3% → ASIDE 74.1%; GSM8K 1-shot base 93.6% → SecAlign 70.9%. Llama-3.3-70B 5-shot MMLU-Pro: base 56.3% → HoS 54.8%, SecAlign 16.1%; SecAlign catastrophic: GSM8K 1-shot 2.0%, MMLU 5-shot 28.4%, MMLU-Pro 5-shot 16.1% — manual inspection: model trả lời demonstration thay vì câu hỏi cuối.
- Multi-turn AlpacaFarm (Llama-3.3-70B, 100 conversations): base 97–100% mọi turn; HoS ~100%; SecAlign drop 43% khi untrusted input ở turn 2, 75% ở turn 3, và vẫn degraded 71%/82% trên các turn trusted sau đó (input ở turn 1).
- Agentic benchmark Llama-3.3-70B (Utility / Utility-under-attack / ASR), AgentDojo: base 53.7/36.2/23.1% → SecAlign 67.0/63.9/2.1% (+13.3/+27.7/−21.0pp) → HoS 58.5/52.4/0.9% (+4.8/+16.2/−22.2pp). AgentDyn: base 33.7/30.9/18.5% → HoS 41.7/38.3/5.4% (+8.0/+7.4/−13.1pp). WASP + LLMail: HoS Pareto-dominate (AgentDojo, WASP), Pareto-match (AgentDyn, LLMail); prose: HoS giữ utility base trên mọi benchmark trừ AgentDyn và đẩy ASR về near zero. - ASIDE tool-use collapse: utility ~10% AgentDojo, near-zero 3 benchmark còn lại — mất ability call tools.
- LLMail-Inject detection (GPT-OSS-20B): send rate ≤1% mọi cấu hình; detection rate base 11.03% → blue-gates-only 28.20% (~2.5×) → red-only 3.60% → HoS full 3.11%.
- Role confusion (role probes Ye et al. 2026): HoS cải thiện accuracy nhận diện role Tool trên clean AgentDojo và giảm Userness (mức perceived như đến từ user) của injection tokens — Userness correlate cao với ASR.
- SecAlign pathology trên LLMail: interpret tool-use instruction trong system prompt như encouragement → tool calls trong 29.95% generations với fabricated recipients/bodies, ASR cao.

## INSIGHT — Cơ chế & tại sao
- [Constraint parameterization prevents shortcut] xảy ra VÌ DPO-update 349M parameters trên dữ liệu single-turn hẹp học spurious correlations (tương quan giả) với format training → out-of-distribution collapse (sụp ngoài phân phối) trên few-shot/multi-turn, trong khi 46K gate scalars không có capacity để học shortcut format. Nghĩa là hạn chế cơ chế học > tăng dữ liệu khi muốn safety mà không mất utility.
- [Per-head specialization beats uniform suppression] xảy ra VÌ gates học độc lập per head theo role của head (instruction-following head đóng gate untrusted; heads khác giữ nguyên để vẫn reason over content) — Appendix C test uniform suppression mọi head cho kết quả tồi hơn. Nghĩa là segregation (phân tách) theo chức năng head là điều kiện để vừa chặn injection vừa đọc hiểu dữ liệu.
- [Blue heads exist vì agents nên detect injection chứ không chỉ resist] xảy ra VÌ minority heads tăng attention tới untrusted content, và blue-only variant nâng detection 11.03%→28.20% — hỗ trợ luận điểm Abdelnabi & Bagdasarian (2026): agent phải vừa chống vừa nhận diện lời tiêm lệnh. Nghĩa là một defense tốt có thể cần một phần heads "hướng về kẻ thù" để cảnh báo.

## IDEA — Áp dụng được gì
1. Cho mọi agent workflow xử lý untrusted content (email khách hàng, web scrape, tool output): đánh dấu token channels {TRUSTED, UNTRUSTED, TEMPLATE} trong preprocessing (tiền xử lý) trước khi đưa vào open-weight model — bước đầu: viết middleware gắn channel tag theo nguồn (user input = TRUSTED, fetched content = UNTRUSTED), dùng cho cả model cloud lẫn local.
2. Hardening open-weight model dùng cho production: thay vì DPO-full (SecAlign) làm risk utility collapse, thêm gate table L·C²·h scalars (pattern 46,080 cho Llama-3.3-70B) + DPO trên preference pairs injection — bước đầu: clone repo imperial-aisp/heads_of_security + load model imperial-cpg/heads-of-security để test trên AgentDojo-like scenario riêng.
3. Đo "Userness" của injection content như metric an ninh nội bộ: train linear probe trên hidden activations (ẩn kích hoạt) với role-tagged benign text; bước đầu: với agent đọc email khách hàng, probe xem span attacker có bị perceived như user không — Userness cao = ASR cao, cần chặn trước khi action.
4. Budget attack-defense evaluation theo FLOPs thay vì ASR nhị phân: report "compute cần để đạt 50% ASR" (pattern 6×10¹⁶ vs 2.2×10¹⁶ FLOPs) — bước đầu: với internal red-team, fix budget 10¹⁶ FLOPs và so ASR giữa các candidate defense thay vì chỉ so ASR 1-shot.

## WISDOM — Nguyên tắc tổng quát
- Nguyên tắc: "Constrain the mechanism, not the behavior" (ràng buộc cơ chế, không ràng buộc hành vi) — giới hạn parameterization của module được huấn luyện (46K gates) ngăn shortcut từ dữ liệu hẹp, trong khi fine-tuning hành vi toàn model (349M-70B params) mang theo collateral corruption (hỏng kèm) trên out-of-distribution inputs.
- Khi nào dùng: hardening open-weight model cho agent xử lý untrusted data mà phải giữ few-shot/multi-turn/tool-use utility.
- Khi nào KHÔNG dùng: closed frontier models (Claude/GPT đã robust hơn open-weight rõ rệt); linear attention architectures (không có attention coefficient riêng per key → gate mechanism không áp dụng trực tiếp); tasks legitimately cần follow external instructions (ví dụ cài software package theo hướng dẫn bên ngoài).

## Assumptions & Limitations
- Điều kiện phải đúng: trust boundary phải supplied externally (biết trước token nào untrusted — tool output, fetched web); model phải standard dense attention (có attention coefficient tường minh per key); preference dataset phải chứa injected instruction trong untrusted segment.
- Limitation paper thừa nhận: (a) không end-to-end defense — HoS không decide nguồn nào trusted hay user authorized lệnh gì, chỉ enforce boundary khi content intended as data; (b) training data fixed (Cleaned-Alpaca single-turn) — multi-turn/multi-instruction data có thể cải thiện cả HoS lẫn SecAlign, các failure của SecAlign không phải tất yếu; (c) attacker moves second — không evaluation hữu hạn nào chứng minh security tuyệt đối; (d) không compatible trực tiếp với linear attention (Yang et al., 2024; 2025a) — cần gating mechanism khác.
- Limitation paper KHÔNG nói: (a) cost/latency inference of gate tables chưa lượng hóa (dùng FLOPs for attack không phải inference overhead của defense); (b) evaluation trên 2 model families (Llama-3.3-70B, GPT-OSS-20B) — chưa rõ trên model <20B mà solopreneur thường chạy; (c) HoS-trained attacker chỉ đạt 3.2% training ASR → paper kết luận robust hơn, nhưng sparse-reward explanation là suy đoán — attacker optimization yếu có thể là artifact của training loop chứ không phải proof defense mạnh; (d) blue-head detection benefit đo trên 1 benchmark con (LLMail-Inject subset) với blue-only ablation — chưa chứng minh full-HoS cải thiện detection (full-HoS detection 3.11% thậm chí thấp hơn base 11.03%).
