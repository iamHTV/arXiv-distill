# 2608.04270v2 CURATE: Leveraging LLM Agents to Compose, Catalog, and Deploy Reproducible Workflows

## Problem
- Agentic code generation (sinh mã bằng agent) có thể accelerate (tăng tốc) development of computational workflows, nhưng coding agents (Claude Code, Codex) focus vào code generation mà KHÔNG address entire workflow lifecycle (vòng đời workflow) bao gồm deployment (triển khai) và sharing (chia sẻ) → users phải tự develop, stitch modules và manage deployment infrastructure.
- Prior work: LLM4Workflow compose multi-step workflows nhưng không có reuse; Thareja et al. apply skills cho workflow generation nhưng không có catalog storage/retrieval; Lee et al. dùng HITL + module reuse qua RAG nhưng chỉ target Excel/CSV data-cleaning; WorkflowHub/CWL cung cấp registry/language nhưng không tự động reuse components khi composing.

## Contribution
- CURATE (Composition, User-in-the-loop, Reuse, and Automated Task Execution): human-in-the-loop (HITL — con người trong vòng lặp) multi-agent system dùng LLM agents quản lý và develop composable workflows suốt entire lifecycle, từ composition đến deployment và reuse.
- Catalog: storage và reuse của modules across workflows — entries gồm ID, name, natural-language description, inputs/outputs, PyPI dependencies, secret names (không values), rank, keywords, provenance (workflow nguồn), usage count; index BM25 (Best Match 25 — thuật toán tìm kiếm văn bản) trên keywords, query = tokenized description từ WCA skeleton; foundation để mở rộng hỗ trợ FAIR principles (Findable, Accessible, Interoperable, Reusable).
- Feasibility demo: open-source prototype 6,700 lines Python (LangGraph coordination, Claude Opus 4.8, MGA dùng Claude Agent SDK) + 6 experiments (4 từ SeBS-Flow serverless benchmark suite + 2 real-world PyADM1 anaerobic digestion simulation).

## Method
- Workflow model: nodes (computational tasks) + edges (control dependencies); task precedence phải là DAG (directed acyclic graph — đồ thị có hướng không chu trình) và known ahead of runtime scheduling; modules implemented as Python functions (function-granularity, task-driven, file-transported).
- 4 agents: WCA (Workflow Composition Agent — controls structure, generates high-level skeleton bằng natural language, delegates source resolution, resolves precedence edges với concrete inputs/outputs); MCA (Module Candidate Agent — resolves source cho mỗi skeleton task: 1) catalog match, 2) user-provided module, 3) previous workflow iteration, 4) generate mới bởi MGA; dùng LLM call với context gồm user request, WMS description, previous revisions); MGA (Module Generation Agent — coding agent generate/adapt modules, test locally trong scratch directory, skip nodes reused từ catalog/previous revisions, đảm bảo I/O match skeleton); WDA (Workflow Deployment Agent — deploy + continually monitor artifacts, spawn post-run chatbot agent cung cấp NL summary, chat hỏi đáp qua MCP (Model Context Protocol) tools download artifacts/view logs, suggest revisions).
- 9-stage LangGraph pipeline, 5 HITL gates: Gate 1 Skeleton (WCA sketch; user provide modules + context PDF/example I/O/markdown); Gate 2 Resolution (WCA fill edge descriptions → MCA resolve sources → WCA fill concrete dataflow file names + likely PyPI dependencies; user approve); Gate 3 Generation (MGA topological sort, sequential traversal, mỗi function trong scratch directory riêng với CONTEXT.md — shared context: user prompt, data integrity requirements, FaaSr testing stubs — + per-function file: description, signature, I/O files/dataflow, dependencies, secret names; single coding-agent session, one function per turn, validate against local stubs trước khi sang function kế; user scroll code + workflow file); Gate 4 Deploy (FaaSr → GitHub Actions; trivial để target AWS Lambda, OpenWhisk, SLURM, GCP, Kubernetes); Gate 5 Post-run (WDA chatbot: NL summary, hỏi đáp, revise, commit functions vào catalog, save workflow; failure → review artifacts/logs, advise adaptation).
- Function labels: [New], [Catalog], [Cache] (implemented ở revision cycle trước), [User Provided Module], optional [Adapt] (dùng existing function làm context nhưng adapt). [Catalog]/[Cache] bị MGA skip trừ khi [Adapt]. [User Provided Module] không [Adapt]: MGA wrap với FaaSr I/O stubs cho S3 retrieval/storage KHÔNG đổi code module, construct synthetic data, local parity checks. MGA instructed: KHÔNG return implementation cho đến khi tested với real data (nếu có) / public API data / local synthetic data. FaaSr workflow JSON được tạo deterministic bởi tool (không phải agent) translate skeleton → schema; dependencies extra → manifest → merge vào workflow config.
- Revision: LLM classify structural (modify DAG → loop về skeleton step) vs functional (modify functions đã có trong skeleton → loop về resolution step).
- Deployment target: FaaSr serverless FaaS WMS (originally R, extended Python) — schema-defined task-driven function-granularity DAG, only dynamicity là conditional branches; serverless simplify deployment; containerized isolation. Resource isolation: sandboxed containers/VMs; care với state isolation ở centralized storage để tránh side effects qua file I/O.

## Key Findings
- E1 Machine Learning (SeBS-Flow): gen dataset (N=500, M=1024, make_classification weights [0.9,0.1], flip_y=0.1, random_state=123), preprocess (StandardScaler, train_test_split test_size=0.4), train K=2 classifiers concurrent (SVM SVC kernel=linear C=0.025; RF max_depth=5 n_estimators=10 unseeded). Gate 1 revision: split train_classifier thành 2 concurrent functions. SVM accuracy identical; generated RF 0.850 ± 0.002 vs original 0.851 ± 0.006 (60 invocations mỗi bên). Baseline ✓ 3/3.
- E2 MapReduce: words từ [cat, dog, bird, horse, pig] evenly distributed + shuffled; Split → Map → Shuffle → Reduce; word counts matched SeBS-Flow ground truth verbatim. Baseline ✓ 1/3.
- E3 Video Analysis: Faster R-CNN ResNet-50 COCO (cv2.dnn), 3 external inputs, output {label, class, score} score>0.5, COCO 80 classes zero-indexed; correctly identified cars (ground truth tất cả frames = car), no runtime errors. Baseline ✗ 0/3.
- E4 PDF + MapReduce + Visualize: reuse 4 functions (split/map/shuffle/reduce verbatim, original rank theo Gate 2 revision) + 2 new (extract words từ words.pdf, visualize); 5 words random 100–1500 occurrences; expected word counts matched actual; histogram well formatted. Baseline ✓ 1/3.
- E5 PyADM1 (real-world): 7-step workflow clean raw digester influent: convert-units (Q MGD→m³/d, T °F→°C kèm rename, chia ALL 22 COD columns cho 1000, giữ nguyên S_IC/S_IN/S_cation/S_anion), fill-gaps (forward-fill S_cation/S_anion), remove-spikes (replace isolated spikes trong Q và T bằng local median), interpolate (26 weekly lab columns → 15-min), validate (validation_report.csv), pyadm1 (dynamic_out.csv), visualize (simulation_plots.png). Synthetic raw data: unit conversions + weekly holds 26 lab features + gaps 3–7 ngày ở 3 chỗ (S_cation, S_anion) + implausible spikes T và Q ở 4 chỗ mỗi loại. Kết quả: address được hầu hết NGOẠI TRỪ T spikes — T hard-coded trong PyADM1 nên MGA skip T spike fixes; WDA bắt được và suggest sửa T spikes + modify PyADM1, authors forgo revision để giữ model unmodified. Baseline ✓ 1/3.
- E6 PyADM1 + concurrency: vary-inputs tạo 20 inputs từ digester_initial varying SRT (solids retention time — thời gian giữ chất rắn); pyadm1 chạy 20× concurrent. Gate 5 revision (WDA suggestion): q_ad hard-coded (178.4674) → set q_ad = V_liq / SRT để 20 ranked runs tạo distinct steady states trên sweep 10–60 ngày; HITL approved → correct results. Baseline ✓ 3/3.
- Token usage: CURATE cao hơn baseline ở một số cases (multi-agent overhead), nhưng baseline có significant non-determinism trong output correctness — nhiều case không có correct run nào và cần manual revisions (map action names thành dependencies thay vì function names, split action code thành nhiều files, 1 FaaSr S3 API operation có argument name document sai); CURATE KHÔNG cần revisions ngoài NL HITL feedback. E5→E6 token usage nearly halved dù workflow complexity tăng (catalog reuse payoff) và cần ít HITL oversight hơn.

## Actionable Insights
1. Catalog module reuse làm token usage nearly halved (E5→E6) đồng thời tăng reliability (reuse verified modules thay vì regenerate). Áp dụng: build personal module catalog cho các workflow content lặp lại (data cleaning, formatting, publishing); mỗi workflow hoàn thành → commit functions vào catalog với description + keywords; workflow mới query catalog trước khi generate.
2. 5 HITL gates bắt lỗi sớm: Gate 1 catch decomposition errors TRƯỚC code generation (E1: WCA gộp 2 training functions thành 1 → user split tại Gate 1). Áp dụng: đừng để agent gen code luôn — yêu cầu skeleton bằng ngôn ngữ tự nhiên trước, approve cấu trúc, rồi mới generate.
3. WDA post-run agent catch được bug mà MGA missed (E5: T spikes hard-coded; E6: q_ad hard-code khiến SRT sweep vô nghĩa) — multi-agent separation of duties (phân tách nhiệm vụ) phát hiện lỗi mà single agent không thấy. Áp dụng: sau khi workflow chạy, dùng 1 agent riêng review logs/artifacts và suggest revision, KHÔNG để chính agent đã viết code tự review.

## Assumptions & Limitations
- Điều kiện: task precedence phải là DAG known ahead of runtime (không dynamic scheduling); modules expressible as functions với defined I/O; cần WMS tương thích (prototype target FaaSr; extensible AWS Lambda/OpenWhisk/SLURM/GCP/Kubernetes).
- Limitation paper thừa nhận: baseline KHÔNG có HITL revision ở mỗi step (vì Claude Code không có built-in workflow creation, không follow sketch→reify→test) — so sánh không hoàn toàn công bằng; SeBS-Flow là performance benchmark chứ không phải scientific workflow suite; ADM1 workflow giới hạn initial data preparation (full end-to-end còn mass balance preprocessing, feature engineering, sensitivity analysis, validation); catalog là minimal implementation (passive storage, BM25 keyword search — chưa semantic match, chưa FAIR compliance); prototype feasibility-focused.
- Limitation paper KHÔNG nói: token overhead multi-agent chưa quantified (chỉ Figure 3 bars, không có số); catalog reuse accuracy (BM25 keyword match có thể retrieve sai module) chưa measured; single LLM (Opus 4.8) — behavior với model khác chưa biết; catalog growth → search degradation chưa test.
