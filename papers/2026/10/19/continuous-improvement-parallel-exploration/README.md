# 2608.04341v1 Continuous Improvement and Parallel Autonomous Exploration: An LLM-Agent Framework for Searching Large Solution Spaces

## Problem
- Nhiều bài toán tối ưu thực tế có solution space (không gian nghiệm) lớn, cần chiến lược task-specific (riếu theo tác vụ); prior work (công trình trước) hoặc đánh giá capability từng agent riêng lẻ (MLAgentBench, SWE-bench), hoặc dùng multi-agent collaborative architecture (MetaGPT, ChatDev, CAMEL) giao tiếp nhiều — chưa trả lời: làm sao để nhiều agent tự duyệt SONG SONG và TỰ CẢI THIỆN mà không có human in the loop (con người trong vòng lặp)?
- Agent-K dùng Kaggle leaderboard làm reward signal (tín hiệu phần thưởng) cho 1 agent; Co-Mind dùng local training-proxy reward (phần thưởng proxy huấn luyện cục bộ) — chưa ai extend withheld-test reward (phần thưởng từ dữ liệu giữ lại) sang parallel agents.

## Contribution
- Framework 2 cơ chế: (i) withheld-test leaderboard (bảng xếp hạng chấm trên dữ liệu giữ lại) làm reward signal — mỗi submission chấm trên data agent chưa từng thấy, score trả về驱动 agent refine qua repeated submissions, loop hoạt động cả với single agent; (ii) substrate chạy nhiều agent song song hoàn toàn tự động, no human in the loop: agent tự analyze, survey methods, hypothesize, implement, self-evaluate, submit, revise; moderator agent chỉ lo logistics (thời gian, GPU queue).
- Instantiate trên product-to-catalog matching (ánh xạ sản phẩm–danh mục) — core e-commerce retrieval (truy xuất) task trong marketplace C2C (consumer-to-consumer — người bán cá nhân) Nhật Bản, pose as selective prediction (dự đoán chọn lọc) với precision-coverage operating point (điểm vận hành độ chính xác–độ bao phủ).
- Case-study evidence: finding replicate across runs, independent of agent count — seeded single agent iterate hẹp trong paradigm (mô hình giải pháp) được seed, parallel agents escape ra phương pháp qualitatively different.

## Method
- Task: listing q = (title, description, metadata, category) → catalog SKU đúng trong catalog lên đến 33K SKU; mỗi prediction kèm confidence score (điểm tự tin), listings dưới threshold bị loại — trade coverage lấy precision. Qualification: ≥95% Precision@1 (P@1 — độ chính xác top-1) trên MỌI category độc lập; xếp hạng qualified submissions bằng average coverage tối đa.
- 3 categories Japanese C2C marketplace: Smartphone (base P@1 100.0%, base coverage 1.3%), Trading Card Others (94.5%, 58.6%), Trading Card Pokemon (97.3%, 39.9%); baseline BGE-M3 (embedding model — mô hình nhúng) cosine similarity: avg 97.3% P@1 nhưng chỉ 33.3% coverage → NOT qualified (Trading Card Others <95%).
- Infrastructure: LeaderboardAPI chấm submission vs withheld test ground truth (chân lý bị giữ), persistent JSON ledger; agents xem được scores + approach descriptions của mọi submission nhưng KHÔNG xem code; append-only chat log (nhật ký trò chuyện chỉ ghi thêm) là kênh liên lạc duy nhất; per-agent working directory + read-only shared resources (tài nguyên chỉ đọc) — attempts to reuse another agent's artifacts đã được quan sát và bị chặn cấu trúc; automated pre-run leak check (kiểm tra rò rỉ); organizer/shared/participant ownership boundary; GPU: two-level lock với 30-minute CLAIM/RELEASE protocol, system-level watchdog (bộ giám sát) terminate unauthorized GPU processes; liveness heartbeats + progress posts fixed cadence; moderator cảnh báo 30/5 phút và forcibly terminate tại deadline.
- Agents: Claude Sonnet 3.5, Python env với BGE-M3, Qwen3-Embedding, FAISS (thư viện chỉ mục láng giềng gần nhất), TF-IDF; briefing gồm task, data format, submission protocol, GPU rules, 5-hour time budget, BGE-M3 baseline reference. Loop: analyze data/errors → survey candidate methods → hypothesize → implement → self-evaluate on train → submit test predictions → observe leaderboard → revise.
- Configurations (mỗi cấu hình 3 runs): single agent vs parallel 5 agents, cùng infrastructure, 5-hour budget, no submission cap.

## Key Findings
- Best qualified coverage (≥95% P@1/category): baseline 33.3% (unqualified) → single agent 47.8 / 57.4 / 49.9% (3 runs, P@1 96.7/96.7/95.1, 22/44/46 qualified trên 60/124/81 submissions) → parallel 5 agents 62.8 / 69.4 / 68.2% (P@1 95.1 cả 3 runs, 105/238/103 qualified trên 274/550/301 submissions).
- Continuous improvement: loop hoạt động ngay cả single agent — cải thiện substantially over baseline chỉ bằng iterative resubmission.
- Narrow vs escape: cả 3 single-agent runs đều ở lại seeded embedding paradigm (BGE-M3 variants, score calibration, thresholds), KHÔNG BAO GIỜ thử lexical/string baseline mà practitioner sẽ thử đầu tiên; 1 run prematurely judged hardest category unsolvable và dừng sớm. Cả 3 5-agent runs: agents tự đạt được qualitatively different methods (TF-IDF re-ranking, string-similarity matching) trong vài phút.
- Gain tập trung ở category khó nhất (smartphone): single agents 0.8–1.9% coverage vs parallel 24.8–41.1%; Trading Card categories: single agent với GPU không tranh chấp competitive với parallel.
- Approach diversity (representative 5-agent run): 5 agents α–ε đều start từ BGE-M3 rồi diverge: score-gap confidence calibration (α, 50.7%); BGE-M3 + TF-IDF rescoring (β, 55.3%); card-number re-ranking với pure string (SequenceMatcher) matching (γ, 65.6%); string-matching + word/char TF-IDF fusion (δ, 69.4% — best); string-similarity re-ranking (ε, 63.6%). Tất cả 5 đều qualified; non-embedding string/TF-IDF methods (γ, δ) drive top results.
- Leaderboard dynamics: first qualified submission chỉ xuất hiện sau extended exploration (δ, BGE-M3, 27.5%); coverage climb qua threshold tuning + card-number re-ranking đến 65.6% rồi plateau; winning push đến LATE khi δ thêm string-matching + word-TF-IDF fusion → 69.4%.
- Depth-for-breadth trade: single agent iterate sâu nhưng hẹp (P@1 cao 95.1–96.7%); parallel agents mở rộng search với cost per-agent precision thấp hơn (95.1%) và GPU contention (tranh chấp) nặng.

## Actionable Insights
1. Withheld-test leaderboard làm reward signal đủ để 1 agent tự cải thiện liên tục — không cần multi-agent infrastructure. Áp dụng: với mọi workflow tối ưu có metric tự động (tuning prompt, query rewriting, data pipeline), dựng leaderboard chấm trên held-out set, cho agent nộp→điểm→sửa lặp lại; đặt qualification gate (cổng đủ điều kiện) theo worst category, không phải average.
2. Single seeded agent mắc structural trap (bẫy cấu trúc): iterate hẹp trong paradigm được seed, chưa bao giờ thử lexical baseline đơn giản; 1 run kết luận sai category không giải được và dừng sớm. Áp dụng: chạy N≥5 agent song song với cùng reward để escape paradigm; hoặc explicit seed agent với đối lập method families (embedding vs string vs TF-IDF).
3. Phương pháp thắng đến LATE (δ fusion 69.4%) sau plateau — đừng dừng early. Áp dụng: đặt time budget đầy đủ, moderator chỉ cảnh báo chứ không dừng agent sớm; theo dõi qualified submissions count chứ không chỉ best score.

## Assumptions & Limitations
- Điều kiện: task phải có automated evaluation (đánh giá tự động) nhanh + metric rõ ràng (P@1, coverage); cần withheld test set + infrastructure leaderboard, sandbox isolation, GPU lock.
- Limitation paper thừa nhận: KHÔNG có causal/agent-count claim — agent count đồng biến với total compute, simultaneous workers, GPU contention, leaderboard visibility; figures là descriptive ranges, không phải scaling law; 3 runs/config; decisive control là no-seed condition (tách seeded baseline khỏi model-specific prior); tất cả agents cùng LLM (Claude Sonnet 3.5); task bounded (metric tự động, iteration nhanh) — longer-horizon với ambiguous success criteria còn mở; instantiate 1 task — cross-task generalization chưa chứng minh; agent viết+submit code tự động, individual submissions không được human review safety — infrastructure boundaries chặn cross-agent damage nhưng KHÔNG audit LLM-generated code.
- Limitation paper KHÔNG nói: per-agent precision của parallel (95.1%) thấp hơn single (95.1–96.7%) → breadth có cost về quality margin; leaderboard visibility có thể gây herding (bầy đàn) vào 1 paradigm (dù data cho thấy ngược lại); 5-hour budget cố định không tối ưu cho mọi task.
