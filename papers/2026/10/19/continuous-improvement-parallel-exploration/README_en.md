# 2608.04341v1 Continuous Improvement and Parallel Autonomous Exploration: An LLM-Agent Framework for Searching Large Solution Spaces

## Problem
- Many practical optimization problems have a large solution space requiring task-specific strategies; prior work either evaluates individual agent capability (MLAgentBench, SWE-bench) or uses communicative multi-agent architectures (MetaGPT, ChatDev, CAMEL) — none answers: how can many agents search in parallel and self-improve with no human in the loop?
- Agent-K uses the Kaggle leaderboard as a reward signal for a single agent; Co-Mind uses local training-proxy rewards — no one had extended the withheld-test reward loop to parallel agents.

## Contribution
- A framework with two mechanisms: (i) a withheld-test leaderboard as a reward signal — each submission is scored on data the agent never sees, and the returned score drives iterative refinement, a loop that operates even with a single agent; (ii) a substrate for running many agents fully autonomously in parallel, no human in the loop: agents independently analyze, survey methods, hypothesize, implement, self-evaluate, submit, and revise; a moderator agent handles only logistics (time, GPU queue).
- Instantiated on product-to-catalog matching — a core e-commerce retrieval task in a Japanese C2C (consumer-to-consumer) marketplace — posed as selective prediction with a precision-coverage operating point.
- Case-study evidence: a finding that replicates across runs and is independent of agent count — a seeded single agent iterates narrowly within its seeded paradigm, while parallel agents escape to qualitatively different methods.

## Method
- Task: a listing q = (title, description, metadata, category) → correct catalog SKU from a catalog of up to 33K SKUs; each prediction carries a confidence score; listings below threshold are excluded — trading coverage for precision. Qualification: ≥95% Precision@1 (P@1) on EVERY category independently; qualified submissions ranked by maximum average coverage.
- 3 categories from a Japanese C2C marketplace: Smartphone (base P@1 100.0%, base coverage 1.3%), Trading Card Others (94.5%, 58.6%), Trading Card Pokemon (97.3%, 39.9%); BGE-M3 (embedding model) cosine-similarity baseline: avg 97.3% P@1 but only 33.3% coverage → NOT qualified (Trading Card Others <95%).
- Infrastructure: LeaderboardAPI scores submissions against withheld test ground truth, persistent JSON ledger; agents see scores + approach descriptions of all submissions but NOT code; an append-only chat log is the sole communication channel; per-agent working directory + read-only shared resources — attempts to reuse another agent's artifacts were observed and structurally blocked; automated pre-run leak check; organizer/shared/participant ownership boundary; GPU: two-level lock with a 30-minute CLAIM/RELEASE protocol, system-level watchdog terminating unauthorized GPU processes; liveness heartbeats + fixed-cadence progress posts; moderator warns at 30/5 minutes and forcibly terminates at the deadline.
- Agents: Claude Sonnet 3.5, Python environment with BGE-M3, Qwen3-Embedding, FAISS, TF-IDF; briefing covers task, data format, submission protocol, GPU rules, 5-hour time budget, BGE-M3 baseline reference. Loop: analyze data/errors → survey candidate methods → hypothesize → implement → self-evaluate on train → submit test predictions → observe leaderboard → revise.
- Configurations (3 runs each): single agent vs parallel 5 agents, identical infrastructure, 5-hour budget, no submission cap.

## Key Findings
- Best qualified coverage (≥95% P@1/category): baseline 33.3% (unqualified) → single agent 47.8 / 57.4 / 49.9% (3 runs; P@1 96.7/96.7/95.1; 22/44/46 qualified out of 60/124/81 submissions) → parallel 5 agents 62.8 / 69.4 / 68.2% (P@1 95.1 all runs; 105/238/103 qualified out of 274/550/301 submissions).
- Continuous improvement: the loop works even with a single agent — substantial improvement over baseline through iterative resubmission alone.
- Narrow vs escape: all three single-agent runs stayed in the seeded embedding paradigm (BGE-M3 variants, score calibration, thresholds), NEVER trying the lexical/string baseline a practitioner would try first; one run prematurely judged the hardest category unsolvable and stopped early. All three 5-agent runs reached qualitatively different methods (TF-IDF re-ranking, string-similarity matching) within minutes.
- Gains concentrate on the hardest category (smartphone): single agents 0.8–1.9% coverage vs parallel 24.8–41.1%; on Trading Card categories a single agent with an uncontested GPU is competitive with parallel runs.
- Approach diversity (representative 5-agent run): all five agents (α–ε) started from BGE-M3 then diverged: score-gap confidence calibration (α, 50.7%); BGE-M3 + TF-IDF rescoring (β, 55.3%); card-number re-ranking with pure string (SequenceMatcher) matching (γ, 65.6%); string-matching + word/char TF-IDF fusion (δ, 69.4% — best); string-similarity re-ranking (ε, 63.6%). All five qualified; the non-embedding string/TF-IDF methods (γ, δ) drove the top results.
- Leaderboard dynamics: the first qualified submission appeared only after extended exploration (δ, BGE-M3, 27.5%); coverage climbed via threshold tuning + card-number re-ranking to 65.6%, plateaued, and the winning push came LATE when δ added string-matching + word-TF-IDF fusion → 69.4%.
- Depth-for-breadth trade: a single agent iterates deeply but narrowly (P@1 95.1–96.7%); parallel agents widen the search at the cost of lower per-agent precision (95.1%) and heavy GPU contention.

## Actionable Insights
1. A withheld-test leaderboard as reward signal is enough for one agent to self-improve continuously — no multi-agent infrastructure needed. Apply: for any optimization workflow with an automated metric (prompt tuning, query rewriting, data pipelines), build a leaderboard scoring on a held-out set and let the agent submit → score → revise in a loop; set the qualification gate on the worst category, not the average.
2. A single seeded agent falls into a structural trap: it iterates narrowly within the seeded paradigm and never tries the simple lexical baseline; one run wrongly concluded a category was unsolvable and stopped early. Apply: run N≥5 agents in parallel under the same reward to escape the paradigm, or explicitly seed agents with opposing method families (embedding vs string vs TF-IDF).
3. The winning method arrived LATE (δ fusion, 69.4%) after a plateau — do not stop early. Apply: give a full time budget, let the moderator warn but never stop agents early, and track the qualified-submissions count, not just the best score.

## Assumptions & Limitations
- Conditions: the task needs fast automated evaluation with clear metrics (P@1, coverage); it requires a withheld test set plus leaderboard infrastructure, sandbox isolation, and a GPU lock.
- Stated limitations: NO causal or agent-count claim — agent count co-varies with total compute, simultaneous workers, GPU contention, and leaderboard visibility; figures are descriptive ranges, not a scaling law; 3 runs per configuration; the decisive control is a no-seed condition separating the seeded baseline from a model-specific prior; all agents use the same LLM (Claude Sonnet 3.5); the task is bounded (automated metrics, fast iteration) — longer-horizon settings with ambiguous success criteria remain open; instantiated on a single task — cross-task generalization undemonstrated; agents write and submit code autonomously and individual submissions were not human-reviewed for safety — infrastructure boundaries prevent cross-agent damage but do not audit LLM-generated code.
- Unstated limitations: parallel per-agent precision (95.1%) is lower than single-agent (95.1–96.7%) → breadth costs quality margin; leaderboard visibility could cause herding into one paradigm (though the data shows the opposite); the fixed 5-hour budget is not optimal for every task.
