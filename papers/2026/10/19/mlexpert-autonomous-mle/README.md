# 2610.22344v1 MLExpert: Towards a Generalist Agentic Model for Autonomous Machine Learning Engineering

## Problem
- Workflow-driven machine learning engineering (MLE — kỹ thuật học máy) systems dùng complex orchestration (điều phối) quản lý long-horizon experimentation (thí nghiệm dài hạn); recent MLE systems adopt model-directed interaction (tương tác do model điều khiển) — model tự organize experiments và adapt optimization strategies dựa trên execution feedback (phản hồi thực thi).
- Gap: feedback từ mỗi experiment phản ánh SEVERAL preceding decisions (nhiều quyết định trước đó), và 1 MLE run dài chứa nhiều experiment tốn kém → training phải (a) select useful supervision từ long interaction trajectories (hành trình tương tác), (b) learn from intermediate outcomes (kết quả trung gian) ngay khi available, (c) handle policy mismatch (lệch policy) khi asynchronous collection (thu thập không đồng bộ). Prior work (AIDE, MLE-STAR, MLEvolve, R&D-Agent, ML-Agent, Frontis-MA1) chủ yếu train single-step decisions hoặc local operations trong externally organized processes.

## Contribution
- MLExpert: 35B Mixture-of-Experts (MoE — hỗn hợp chuyên gia) agentic model (khởi tạo từ Qwen3.6-35B-A3B, 35B total ~3B active) cho autonomous MLE — model tự organize experiments, revise solutions dựa trên execution feedback, maintain submission candidates trong suốt interaction.
- Kaggle-MLE Factory: chuyển historical Kaggle competitions thành executable tasks (public workspace, hidden test split, unified evaluation interface) qua multi-agent pipeline: discovery agent (lọc competitions theo status, scale, submission format) → analyzer agent (trích xuất data structures, fields, modality characteristics → task specification) → generator agent (chuẩn bị task data, tạo held-out test split với hidden labels từ original labeled data, implement task-specific evaluator) → execute trên real data + iterative repair dựa trên validator checks (data integrity, submission format, evaluation behavior) → manual review loại tasks có unresolved label/scoring issues.
- Interaction Harness: ReAct-style loop (vòng lặp Suy nghĩ–Hành động–Quan sát), branch selection và optimization-path decisions thuộc về model (không phải external search policy); experimental states lưu trong solution nodes (candidate code, execution logs, metadata); parent-linked revisions tạo experiment tree để model revisit/compare → quyết định continue, backtrack, hoặc đổi hướng; tools: solution analysis, code revision, experiment execution (execute_code), history retrieval, submission management (update_answer); context compaction (tóm tắt messages cũ khi gần context limit, giữ recent); analyze delegates cho analysis sub-agent với independent context, trả về summary; invalidate_node loại candidates unreliable (chống overfitting/data leakage).
- Hierarchical agentic SFT: Stage 1 — coding + tool-use trajectories từ diverse agentic tasks (StepFun); Stage 2 — MLE-domain teacher trajectories (Kaggle-MLE Factory, MLE-Dojo, Nature-family papers) + literature-derived scientific tasks. Outcome-guided supervision selection: với trajectories đạt quality threshold, xác định first best-performing submission, đo post-peak degradation; nếu degradation vượt threshold → dùng first best submission làm anchor, retain trajectory prefix (kết thúc tại complete tool-interaction boundary gần anchor); else dùng last submission → loại degraded tails mà vẫn preserve useful exploration + failure recovery. Loss chỉ trên newly generated reasoning/text/tool-call tokens; tool feedback + inherited history masked.
- Windowed Interaction RL (WIRL): nhóm consecutive model decisions giữa 2 successive experiment results thành execution window (cửa sổ thực thi) u_m; window conditioned on accumulated interaction history, gắn với outcome của experiment tương ứng; shared outcome-based reward (phần thưởng dựa trên kết quả) cho mọi decisions trong window → policy updates dùng được intermediate feedback KHÔNG phải chờ toàn bộ trajectory kết thúc. Asynchronous collection + token-level policy correction (dùng log-probabilities ghi lại khi collect) handle policy mismatch.

## Method
- MLE formalization: task e = (d_e, D_e, m_e) — task description, task data, evaluation metric; candidate solution y = complete ML pipeline (data processing, feature engineering, model training, prediction); objective maximize E[S_e(ŷ_τ)] với S_e normalized score; agent truy cập task description + public data, improve qua code execution + self-constructed validation; final submission evaluated bằng hidden test labels (theo MLE-bench).
- WIRL reward (phần thưởng) cho window u_m: R_m = −1.0 nếu execution error do model actions; −0.6 nếu không lỗi nhưng không có scorable submission; −0.4 + T_m nếu valid submission dưới medal threshold (ngưỡng huy chương); 1.0 + T_m nếu bronze/silver; 2.0 + T_m nếu gold. T_m = local performance trend ∈ {−0.2, 0, 0.2} (giảm/không đổi/cải thiện so với valid submission trước, theo chiều metric), T_m = 0 cho first valid submission.
- Khác GRPO (Group Relative Policy Optimization): WIRL dùng verifiable execution reward làm shared optimization weight trực tiếp (A_m = R_m), KHÔNG group-relative normalization, áp dụng cho mọi main-model output tokens trong window.
- Policy correction: token t của model call j trong window u_m, q = exp(ℓ_old − ℓ_roll) (tỷ lệ log-prob dưới policy trước update vs rollout policy khi collect); c = sg(q · 1[q_min ≤ q ≤ q_max]) — tokens trong [q_min, q_max] weighted by q, tokens ngoài interval bị loại khỏi policy-gradient update.
- Loss: trung bình cửa sổ của (1/N_m) Σ c·L_PG + λ_KL·K (KL regularization vs fixed SFT reference) − λ_H·H (entropy bonus), N_m = số valid output tokens trong window.
- Implementation: mỗi MLE task tối đa 3,000 interaction steps, 12-hour runtime, 20 vCPUs, 220 GB RAM, 1 NVIDIA H200 GPU.

## Key Findings
- MLE-Bench Lite (22 tasks, MLExpert Harness): medal rate (tỷ lệ huy chương) base Qwen3.6-35B-A3B 37.9% → MLExpert 72.7% (+34.8pp); Med+ (vượt median human) 84.8%, Gold 50.0%, Silver 16.7%, Bronze 6.1%. Cao nhất same-scale; comparable GLM-5.3 (72.7%) và Kimi-K3 (72.7%); GPT-5.6 Sol cao nhất 77.3%. Same-scale: Ornith-1.5-35B-A3B 39.4%, Nex-N2.5-mini 47.0%. Frontier: DeepSeek-V4-Pro Preview 63.6%, MiniMax M3 68.2%, GPT-5.5 xhigh 72.7%.
- General-purpose harness (Claude Code): MLExpert 69.7% vs base 42.4% (+27.3pp), vượt strongest same-scale baseline 22.7pp → improvement KHÔNG phụ thuộc MLExpert-Harness riêng.
- NatureBench Lite (Claude Code): Match-SOTA (matching published results) 40.0% → 70.0%; Surpass-SOTA (vượt published results) 0.0% → 50.0% (Nex-N2.5-mini 20.0%, GLM-5.3 50.0%).
- Ablation (staged): Base 37.9% → +General Agent SFT 47.0% → +MLE SFT 62.1% → +WIRL 72.7% — mỗi stage thêm gain.
- RL comparisons (khởi tạo MLE-SFT 62.1%): GRPO 56.1%, PPO-style 60.6% — cả hai ĐỀU dưới MLE-SFT (hỗ trợ design windowed); WIRL w/o trend reward 66.7%, WIRL w/o policy correction 65.2%, full WIRL 72.7% → cả trend reward lẫn policy correction đều贡献.
- Case study MLSP 2013 Birds (audio): optimization path audio features + LightGBM → PANNs representations → AST fine-tuning với attention pooling + MLP head → training-schedule adjustments → snapshot averaging; ROC-AUC (diện tích dưới đường ROC) 0.58 → 0.964 (MLExpert) vs 0.60 → 0.88 (MLExpert-SFT).
- Agent scaffold optimization (GPT-4.1-nano solver, AIME 2025, evaluate on held-out years): scaffold do MLExpert optimize đạt 43.7% held-out accuracy vs 23.3% base (+20.4pp); Kimi-K3 47.8%, GLM-5.3 48.1%; calls 1.00 (base) → 9.39 (MLExpert).
- Algorithm-component optimization (MLS-Bench-Lite, 12 tasks/12 domains, 5-hour budget): mean verifier reward (phần thưởng kiểm chứng trung bình) 0.322 → 0.425; MLExpert outperform Base 10 tasks, tie 1, lower 1; gains span language-model demasking, multi-objective optimization, causal discovery.

## Actionable Insights
1. Outcome-guided trajectory trimming: khi collect agent trajectories để train/fine-tune, cắt trajectory tại first best submission khi post-peak degradation vượt threshold — loại bỏ degraded tails mà giữ exploration + failure recovery. Áp dụng: khi tự fine-tune agent cho workflow riêng, log mọi run, chỉ lấy prefix đến peak performance làm training data, KHÔNG dùng toàn bộ run có tail suy giảm.
2. Execution-window credit assignment (gán công cho cửa sổ thực thi): khi feedback chỉ đến sau nhiều decisions, group decisions giữa 2 kết quả thành window, thưởng chung cho cả window + trend bonus (±0.2) — ổn định hơn trajectory-level reward. Áp dụng: khi đánh giá agent tự động (content pipeline, data pipeline), chấm điểm từng "đoạn giữa 2 lần chạy thành công" thay vì chỉ điểm cuối.
3. Async collection + token-level policy correction cho phép update policy giữa chừng trajectory — rút ngắn thời gian chờ. Áp dụng: khi chạy batch agent jobs dài, không cần chờ job kết thúc mới cập nhật; dùng log-prob recorded để correct trọng số.

## Assumptions & Limitations
- Điều kiện: task phải có verifiable execution feedback (execution success, scorable submission, medal thresholds); evaluation metric phải chuẩn hóa được (normalized score); cần infrastructure 12h × 20 vCPUs × 220GB RAM × H200 GPU/task — tốn kém cho solopreneur.
- Limitation paper thừa nhận: KHÔNG có section Limitations riêng; paper chỉ nói training tasks overlapping MLE-Bench/NatureBench bị loại (tránh contamination).
- Limitation paper KHÔNG nói: teacher trajectories quality phụ thuộc frontier models (Kimi-K3, GLM-5.3 làm reference); medal thresholds task-specific → reward design không transfer trực tiếp sang domain không có medal; 12-hour budget/task giới hạn practical deployment; generalization tests (scaffold, algorithm optimization) chỉ vài chục tasks; calls tăng 1.00→9.39 (9.4× cost) cho scaffold optimization — accuracy-cost tradeoff chưa bàn; MoE ~3B active nghĩa capability concentrated — behavior với dense model khác size chưa test.
- Ethical: AI4AI/RSI (recursive self-improvement — tự cải thiện đệ quy) hướng tới AI tự build AI — paper không discuss safeguards.
