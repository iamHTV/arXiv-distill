# 2610.22344v1 MLExpert: Towards a Generalist Agentic Model for Autonomous Machine Learning Engineering

## Problem
- Workflow-driven machine learning engineering (MLE) systems use complex orchestration to manage long-horizon experimentation; recent MLE systems adopt model-directed interaction — the model autonomously organizes experiments and adapts optimization strategies from execution feedback.
- Gap: feedback from each experiment reflects SEVERAL preceding decisions, and a long MLE run contains many costly experiments. Training must (a) select useful supervision from long interaction trajectories, (b) learn from intermediate outcomes as they become available, and (c) handle policy mismatch during asynchronous collection. Prior work (AIDE, MLE-STAR, MLEvolve, R&D-Agent, ML-Agent, Frontis-MA1) primarily trains single-step decisions or local operations within externally organized processes.

## Contribution
- MLExpert: a 35B Mixture-of-Experts agentic model (initialized from Qwen3.6-35B-A3B; 35B total, ~3B active) for autonomous MLE — the model autonomously organizes experiments, revises solutions from execution feedback, and maintains submission candidates throughout interaction.
- Kaggle-MLE Factory: converts historical Kaggle competitions into executable tasks (public workspace, hidden test split, unified evaluation interface) via a multi-agent pipeline: discovery agent (filters competitions by status, scale, submission format) → analyzer agent (extracts data structures, fields, modality characteristics into a task specification) → generator agent (prepares task data, builds a held-out test split with hidden labels from the original labeled data, implements the task-specific evaluator) → execution on real data with iterative repair from validator checks (data integrity, submission format, evaluation behavior) → manual review excluding tasks with unresolved label/scoring issues.
- Interaction Harness: a ReAct-style loop where branch selection and optimization-path decisions belong to the model (not an external search policy); experimental states are stored in solution nodes (candidate code, execution logs, metadata); parent-linked revisions form an experiment tree the model can revisit/compare to decide continue, backtrack, or change direction; tools include solution analysis, code revision, experiment execution (execute_code), history retrieval, and submission management (update_answer); context compaction summarizes old messages near the context limit while retaining recent ones; analyze delegates to an analysis sub-agent with independent context, returning only a summary; invalidate_node excludes unreliable candidates (overfitting/data-leakage protection).
- Hierarchical agentic SFT: Stage 1 — coding and tool-use trajectories from diverse agentic tasks (StepFun); Stage 2 — MLE-domain teacher trajectories (Kaggle-MLE Factory, MLE-Dojo, Nature-family papers) + literature-derived scientific tasks. Outcome-guided supervision selection: for trajectories passing a quality threshold, identify the first best-performing submission and measure post-peak degradation; if degradation exceeds a threshold, use the first best submission as the anchor and retain the trajectory prefix (ending at a complete tool-interaction boundary near the anchor); otherwise use the last submission — removing degraded tails while preserving useful exploration and failure recovery. Loss applies only to newly generated reasoning/text/tool-call tokens; tool feedback and inherited history are masked.
- Windowed Interaction RL (WIRL): groups consecutive model decisions between two successive experiment results into an execution window u_m; the window is conditioned on accumulated interaction history and associated with the outcome of the corresponding experiment; a shared outcome-based reward covers all decisions in the window, so policy updates can use intermediate feedback without waiting for the full trajectory. Asynchronous collection + token-level policy correction (from log-probabilities recorded during collection) handle policy mismatch.

## Method
- MLE formalization: task e = (d_e, D_e, m_e) — task description, task data, evaluation metric; candidate solution y = a complete ML pipeline (data processing, feature engineering, model training, prediction); objective maximize E[S_e(ŷ_τ)] with S_e a normalized score; the agent accesses the task description + public data and improves via code execution + self-constructed validation; the final submission is evaluated on hidden test labels (following MLE-bench).
- WIRL reward for window u_m: R_m = −1.0 for execution error caused by model actions; −0.6 for no such error but no scorable submission; −0.4 + T_m for a valid submission below the medal threshold; 1.0 + T_m for bronze or silver; 2.0 + T_m for gold. T_m = local performance trend ∈ {−0.2, 0, 0.2} (decrease / unchanged / improvement vs the previous valid submission, in the metric's direction), T_m = 0 for the first valid submission.
- Unlike GRPO (Group Relative Policy Optimization), WIRL uses the verifiable execution reward directly as the shared optimization weight (A_m = R_m), with no group-relative normalization, applied to all main-model output tokens in the window.
- Policy correction: for token t of model call j in window u_m, q = exp(ℓ_old − ℓ_roll) (ratio of log-probabilities under the pre-update policy vs the rollout policy at collection); c = sg(q · 1[q_min ≤ q ≤ q_max]) — tokens within [q_min, q_max] are weighted by q; tokens outside the interval are excluded from the policy-gradient update.
- Loss: average over windows of (1/N_m) Σ c·L_PG + λ_KL·K (KL regularization vs a fixed SFT reference) − λ_H·H (entropy bonus), where N_m = the number of valid output tokens in the window.
- Implementation: each MLE task allows up to 3,000 interaction steps and a 12-hour runtime with 20 vCPUs, 220 GB RAM, and a single NVIDIA H200 GPU.

## Key Findings
- MLE-Bench Lite (22 tasks, MLExpert Harness): medal rate of base Qwen3.6-35B-A3B 37.9% → MLExpert 72.7% (+34.8pp); Med+ (above median human) 84.8%, Gold 50.0%, Silver 16.7%, Bronze 6.1%. Highest among same-scale models; comparable to GLM-5.3 (72.7%) and Kimi-K3 (72.7%); GPT-5.6 Sol leads at 77.3%. Same-scale: Ornith-1.5-35B-A3B 39.4%, Nex-N2.5-mini 47.0%. Frontier: DeepSeek-V4-Pro Preview 63.6%, MiniMax M3 68.2%, GPT-5.5 xhigh 72.7%.
- General-purpose harness (Claude Code): MLExpert 69.7% vs base 42.4% (+27.3pp), exceeding the strongest same-scale baseline by 22.7pp — the improvement is not specific to the MLExpert Harness.
- NatureBench Lite (Claude Code): Match-SOTA 40.0% → 70.0%; Surpass-SOTA 0.0% → 50.0% (Nex-N2.5-mini 20.0%, GLM-5.3 50.0%).
- Staged ablation: Base 37.9% → +General Agent SFT 47.0% → +MLE SFT 62.1% → +WIRL 72.7% — each stage adds gain.
- RL comparisons (from MLE-SFT at 62.1%): GRPO 56.1% and PPO-style 60.6% — both BELOW MLE-SFT, supporting the windowed design; WIRL w/o trend reward 66.7%, WIRL w/o policy correction 65.2%, full WIRL 72.7% — both the trend reward and policy correction contribute.
- Case study MLSP 2013 Birds (audio): optimization path audio features + LightGBM → PANNs representations → AST fine-tuning with attention pooling + MLP head → training-schedule adjustments → snapshot averaging; ROC-AUC 0.58 → 0.964 (MLExpert) vs 0.60 → 0.88 (MLExpert-SFT).
- Agent scaffold optimization (GPT-4.1-nano solver, AIME 2025, evaluated on held-out years): the MLExpert-optimized scaffold reaches 43.7% held-out accuracy vs 23.3% for the base model (+20.4pp); Kimi-K3 47.8%, GLM-5.3 48.1%; calls 1.00 (base) → 9.39 (MLExpert).
- Algorithm-component optimization (MLS-Bench-Lite, 12 tasks / 12 domains, 5-hour budget): mean verifier reward 0.322 → 0.425; MLExpert outperforms Base on 10 tasks, ties 1, scores lower on 1; gains span language-model demasking, multi-objective optimization, and causal discovery.

## Actionable Insights
1. Outcome-guided trajectory trimming: when collecting agent trajectories for training/fine-tuning, cut the trajectory at the first best submission when post-peak degradation exceeds a threshold — removing degraded tails while keeping exploration and failure recovery. Apply: when fine-tuning your own agent for a workflow, log every run and use only the prefix up to peak performance as training data, not the full run with a degraded tail.
2. Execution-window credit assignment: when feedback arrives only after many decisions, group the decisions between two results into a window, give the whole window a shared reward plus a trend bonus (±0.2) — more stable than trajectory-level rewards. Apply: when scoring automated agents (content pipeline, data pipeline), grade each "segment between two successful runs" instead of only the final outcome.
3. Async collection + token-level policy correction allow policy updates mid-trajectory, cutting waiting time. Apply: when running long batch agent jobs, do not wait for a job to finish before updating; use recorded log-probabilities to correct weights.

## Assumptions & Limitations
- Conditions: the task must have verifiable execution feedback (execution success, scorable submission, medal thresholds); the evaluation metric must be normalizable; infrastructure of 12h × 20 vCPUs × 220 GB RAM × one H200 GPU per task is expensive for a solopreneur.
- Stated limitations: the paper has NO dedicated Limitations section; it only notes that training tasks overlapping MLE-Bench/NatureBench are excluded (contamination avoidance).
- Unstated: teacher-trajectory quality depends on frontier models (Kimi-K3, GLM-5.3 serve as references); medal thresholds are task-specific, so the reward design does not transfer directly to domains without medals; the 12-hour budget per task limits practical deployment; generalization tests (scaffold, algorithm optimization) cover only a few dozen tasks; calls rise 1.00 → 9.39 (9.4× cost) for scaffold optimization — the accuracy-cost tradeoff is not discussed; with ~3B active parameters in the MoE, capability is concentrated — behavior with a dense model of a different size is untested.
- Ethics: AI4AI/RSI (recursive self-improvement) aims at AI building AI — the paper does not discuss safeguards.
