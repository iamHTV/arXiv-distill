# 2610.03769v1 Bayes-Sufficient Compression Is Not Enough: How Does Communication Help Multi-Agent Systems?

## Problem
- Multi-agent LLM systems pair a sender with broad context and an executor with a limited local view. Aggregate task metrics conflate three failure modes: an uninformative message, a useful message the receiver fails to use, or an error carried across steps.
- Gap: prior work (Anthropic harness studies, Kim et al. scaling, Cemri et al. failure analysis) reports coordination tax and topology-dependent error amplification at the aggregate level, but does not answer the step-level question: when does a message improve the executor's NEXT decision rather than adding burden? Protocol design needs to evaluate each message at the receiver's next decision.

## Contribution
- Framework of receiver-relative bounded coordination: communication is useful only to the extent that it improves the deployed receiver's next-step decision. Three commitments: the step is the unit of analysis; the action-sufficient target — not total information — defines what is useful; the executor is modeled as a bounded decoder, so an information-sufficient message need not be usable.
- Communication-Tax Identity (Prop 1): U = R(0) − R(1) = A* − τ — message utility = receiver gain − protocol tax. Positive tax means the message moves the deployed protocol farther from the best decoder in the same bounded class (extra parsing burden, distraction from irrelevant content, prompt-interface mismatch).
- Theorem 2 (Compression Wins by Saving More Tax Than It Loses): under log-loss, ∆U_cmp−raw = ∆τ_raw→cmp − I_omit − Λ_C(M→C) — compression wins when tax savings exceed losses from omitted information plus decoder mismatch.
- Theorem 3 (Bayes-Sufficient Compression Need Not Be Receiver-Optimal): for any 0<α<1, ε>0, there exist a task, an α-proper Bayes-sufficient compression (Definition 2.2: I(Z*; C|X, M)=0 and H(M) ≤ αH(C)), and a representation-sensitive receiver class on which raw context attains zero error while the compressed message incurs error ≥ 1/2 − ε. Bayes sufficiency is an information-level property, not a usability guarantee.
- Theorem 4 (Post-Message Loss Decomposes into Three Stages): for a bottleneck-factorized receiver Z* → C → M → Ẑ → A, L_total = L_ext + L_abs + L_close — externalization (sender-side loss: useful content in C does not reach M), absorption (receiver-side uptake loss: content in M does not enter Ẑ), action closure (receiver-side decision loss: recovered content does not become the correct action).
- Proposition 5: fixed-message replay — the same sender message across receivers — cancels externalization, so the paired difference depends only on absorption and closure.
- Theorem 6 (Sender-Upgrade Burden Threshold under Single Crossing): U_s' − U_s = ∆A − ∆τ; for a burden-indexed receiver family, if Ψ is continuous and single-crossing (negative at low burden, positive at high burden), there is a unique threshold b* where the stronger upstream agent changes from harmful to helpful.
- Section 3 residual risk in shared-state workflows: D_{t+1} = k_t + λ_t[D_t − q_t]_+; Prop 7 (Conditional Propagation): ∆_{t+h} = (Πλ_u)∆_t — the residual gap multiplies forward while both trajectories remain in the carry regime; weak coupling washes out local mistakes, persistent coupling turns them into future risk.
- Inference-time protocol selector: action set {skip, compress(B), raw, escalate(C'), refresh}; score J_t(α) = A* − τ − η_c·c(α) − η_r·r_t(α) (gain − tax − immediate cost − future residual risk); offline calibration from paired RO/SF/MA records; gain surrogate Â = clipped leading-token log-probability difference.

## Method
- Six benchmark families: BFCL (function calling), ToolSandbox (stateful tools), ContextBench (code context), RepoBench (retrieval), SWE-bench Lite (software repair), τ-bench (customer service); LongCLI-Bench as a shared-state stress test (appendix). Regimes: high-local-sufficiency, context-heavy, capability-transfer, boundary.
- Default sender Qwen3-Next-80B-A3B, receiver Qwen3.5-9B, message budget B = 128 tokens (SWE-Lite sender Qwen3-Coder-Next-FP8); matched-sender MA_match (9B→9B), stronger-sender MA_main, and fixed-message replay contrasts paired at the (instance, step) level. OpenAI extension: sender gpt-5.4 with receivers gpt-4o-mini / gpt-5.4-nano / gpt-5.4-mini / gpt-5.4 / o3 / o4-mini.
- Native supervision is mapped into acceptable artifact/action targets G_t = {(Z^art, Z^act)} — labels are never exposed to the sender, receiver, or selector. Primary accuracy is hit_joint (h_j); diagnostics: artifact accuracy h_a, conditional action-conversion h_action, content loss L_content, closure loss L_closure; identity 1−h_j = E[1−h_a] + E[h_a(1−h_action)].
- Contrasts: ∆_comm = Acc(MA_main) − Acc(RO); ∆_cmp = Acc(MA_main) − Acc(SF); ∆_strong = Acc(MA_main) − Acc(MA_match).

## Key Findings
- The same Qwen protocol (Qwen3.5-9B receiver, Qwen3-Next-80B-A3B sender, B=128): ContextBench joint accuracy 0.633 → 0.775 (+0.142; full-support bootstrap +0.1711, 95% CI [0.1417, 0.2012], 2,390 steps / 799 instances) while ToolSandbox drops 0.889 → 0.653 (−0.236), BFCL 0.980 → 0.750 (−0.23), τ-bench 0.139 → 0.139 (unchanged, CI includes zero), RepoBench 0.642 → 0.833 (+0.19; bootstrap +0.1611, CI [0.1340, 0.1891], 2,396 steps / 800 instances), SWE-Lite +0.48. Derived averages: ∆_comm −0.08, ∆_cmp −0.01 — the compression sign FLIPS across benchmarks.
- The regime belongs to the receiver + protocol + task: on ToolSandbox, a gpt-4o-mini receiver improves 0.803 → 1.000 with the same gpt-5.4 sender while the Qwen receiver drops 0.889 → 0.653. ContextBench improves across all OpenAI receivers (gpt-5.4: 0.600 → 0.853).
- Truncation control (ContextBench 480-step audit): MA exceeds RO by +10.64pp among 404 capped messages (95% CI [5.7, 15.8]) and +32.89pp among 76 uncapped (CI [22.4, 43.4]) — the gains are not a truncation artifact; capped messages still retain both decision fields.
- Strict-recoding probe (Theorem 3 evidence): recoding the message surface form (content held fixed) lowers accuracy by 13.5pp on τ-bench, 6.0pp on ContextBench, and 3.5pp on ToolSandbox; BFCL unchanged — surface form alone causes failures despite correct content.
- Fixed-message replay (Table 2, ContextBench, identical DeepSeek-V3.1 messages): GLM-5 h_j 0.382 with h_a 0.741, h_action 0.545, closure fraction 57%; MiniMax-M2.5 h_j 0.036 with h_a 0.613, h_action 0.053, closure fraction 60% — the correct artifact is recovered yet the wrong action is still chosen. L_content is low (0.259 / 0.053) while L_closure is high (0.581 / 0.337). DeepSeek-R1 / Qwen3.5-9B / Llama-70B have h_action ≥ 0.98 and closure ≤ 3%, so joint accuracy tracks artifact accuracy.
- Parsing audit (gpt-5.4 sender): wrong-action rates among valid outputs with correct artifact recovery: GLM-5 44.5%, MiniMax-M2.5 94.0%, o3 40.8% — outputs explicitly choose read when the evaluated action is edit. o3 audit: externalization + absorption ≥ 0.85 with conditional closure 0.60. SWE-Lite: RO artifact accuracy 0.885–0.917 while the zero-joint slice reflects action errors.
- Stronger-sender threshold (Theorem 6 evidence): sender upgrades help SWE-Lite (+52.1pp), ContextBench (+21.0pp), and RepoBench (+8.8pp) but hurt ToolSandbox (−26.4pp), BFCL (−16.0pp), and τ-bench (−2.8pp). Crossover estimate 0.6289 (bootstrap 95% CI [0.552, 0.706]; 41 anchors) — 34 of 38 nonzero anchors (89.5%) follow a single positive-to-negative crossing as local sufficiency increases; a hierarchical analysis of 12,540 paired steps favors single-crossing over linear and two-crossing alternatives in all 10 folds.
- Selector (Eq 5): ContextBench static audit (n=300): the selector reaches 0.7367 accuracy at 1,735 tokens/step — between always-skip (0.6500, 1,300 tokens) and always-send (0.7867, 3,235.4 tokens); it recovers +8.67 accuracy points over always-skip while using 46.4% fewer tokens than always-send. ToolSandbox online (36 steps): early-skip reaches 1.000 accuracy with 919.4 tokens and 6.60 s/step vs always-send 0.8056, 3,085.4 tokens, 9.56 s. Instance-disjoint calibration at 5–40%: accuracy 0.7368–0.7458. Learned-router utility 0.5692 vs 0.5191 for gradient boosting under the same cost weight. Failure case on τ-bench: rewriting reached 0.139 vs the selector's 0.083 at similar input-token cost.

## Actionable Insights
1. Message utility = gain − tax: before sending context to a sub-agent, estimate the receiver gain (does the receiver lack context?) minus the protocol tax (parsing burden, distraction, interface mismatch). Apply: when an orchestrator sends a task to a worker agent, measure accuracy with/without the message on a few instances — if the receiver already has enough context (high local sufficiency), skip the message to save tokens (ToolSandbox early-skip: 1.000 accuracy at 919 tokens vs 3,085).
2. Bayes-sufficient ≠ receiver-usable: a message with the right information but the wrong surface form still fails (strict-recoding −13.5pp on τ-bench; replay closure 57–60% for GLM-5/MiniMax). Apply: format messages for the receiver's interface (same template, field names, action keywords the receiver knows), not just correct content; test with fixed-message replay across receivers before deploying.
3. A stronger sender helps only above a receiver-burden threshold (~0.63 RO accuracy in the paper): when the receiver's local view is already sufficient, a stronger sender HURTS (−26.4pp ToolSandbox). Apply: do not always use the strongest model as planner — choose the sender by the receiver's burden: weak receiver / context-poor → a stronger sender helps; receiver already sufficient → a stronger sender only adds tax.

## Assumptions & Limitations
- Conditions: the task has measurable acceptable artifact/action targets (hit_joint); the receiver is a fixed model with a fixed prompt/parser/context window/tool interface (a representation-sensitive class, not closed under arbitrary recodings); drop-message closure holds (the decoder class contains a map that ignores the message).
- Stated limitations: the τ-bench selector failure case (rewriting 0.139 > selector 0.083 at similar cost) — the selector does not always win; OpenAI cells have unequal protocol coverage (60–300 cells); replay component coverage is non-uniform (loss columns are diagnostic means, not h_j reconstructed from marginal products); the static one-step ablation sets η_r = 0 (future residual risk not yet charged); the gain surrogate is a hit-based proxy, not measured log-probabilities.
- Unstated: the message budget B=128 tokens is fixed — the effect of budget size is not swept; the default receiver Qwen3.5-9B is one model family — receiver diversity is limited; selector calibration requires paired RO/SF/MA records (3× runs) before deployment; the Theorem 3 construction is an existence proof, prevalence in practice is not measured; LongCLI-Bench is appendix-only.
- Ethics: the paper does not discuss (production multi-agent systems, cost implications).
