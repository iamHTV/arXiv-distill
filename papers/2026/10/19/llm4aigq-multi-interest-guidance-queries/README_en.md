# 2609.03674v1 LLM4AIGQ: LLM-based AI Guidance Query Generation Framework for Multi Interest Mining

## Problem
- Guidance queries stimulate consumption by extracting preferences into search queries with guidance value, playing a crucial role in e-commerce.
- Traditional AI-generated queries (AIGQ) generation relies on a two-stage "Query-to-AIGQ" (Q2AIGQ) association paradigm: (1) recall user primary search queries from user profiles, historical behavior sequences, item-side information, and the current query through multi-path retrieval; (2) generalize AIGQ via rule-based methods.
- Two problems: (a) semantic drift due to information cascade loss — an intermediate-query bottleneck; (b) anchor-query inference is dominated by user-item co-occurrence relationships, lacking exploration of user multi-interests → guidance queries with low value and mismatched purchase intent.
- Three challenges: (1) multi-interest modeling under noisy interactions (accidental interactions, exposure bias); (2) effective supervision without explicit ground truth (AIGQ has no strictly defined correct answers); (3) efficient inference for online serving (latency constraints).

## Contribution
- LLM4AIGQ: an LLM-based solution for AIGQ tailored to users' multi-interests — segments user interests by integrating user profiles + historical interaction sequences, infers specific consumption intents for each sub-interest, and generates corresponding AIGQ — avoiding semantic drift and capturing personalized intent.
- Three-stage post-training pipeline SFT → RL → DPO: SFT learns AIGQ style (on single-interest subsequences); RL uses a multi-level reward design (multi-objective optimization + long-chain reasoning); DPO distills reasoning capability from think mode to non-think mode (fewer tokens, faster inference).
- Deployment: nearline-generation and online-read architecture — guidance queries are generated in advance, lightweight online retrieval → meets latency constraints. Deployed at Tmall at the scale of hundreds of millions of users.

## Method
- Data composition: input = task instruction R + user context C_u = user profile P_u (summarized/extracted by a Qwen model from consumption patterns + basic personal info) + user historical sequence S_u (recent behaviors B_u = timestamp t, behavior type a ∈ {like, favorite, add-to-cart, purchase, search}, behavior content c = query terms for search / item titles for other behaviors).
- Context compression: truncate history to the most recent 50 behaviors; format "<idx><time><type><content>" separated by "|"; time = interval relative to the current time. Item short titles: original titles lack standardized naming, have poor readability, and redundancy (marketing keywords, flagship stores) → Qwen3-30B-A3B summarizes a short title from item title id + CPV info ic (brand/style/attributes) + brand category info ib (treecate_full_cath, treecate_name), fine-tuned with DeepSeek-V4 Pro outputs as the standard answer.
- SFT stage (single interest): a teacher model (DeepSeek-V4 Pro) segments user interests and generates a guidance query per sub-interest as reference; the LLM receives ONLY single-interest subsequences → learns style/patterns instead of selecting among interests (fine-tuning directly on composite interests → autonomous extrapolation, unfriendly to low-frequency trigger words, candidate AIGQs focus on a single main interest). Instructions indicate application scenarios (single item consultation, comparative decision-making, category selection), requiring guidance value + content compliance + concise expression.
- RL stage (multi-interest): the model autonomously segments interests and generates AIGQ per sub-interest with step-by-step reasoning: Step 1 — summarize multiple interests, divide into at most 3 interest subsequences based on temporal proximity, semantic relevance, and profile preferences, with interest label I_k; Step 2 — infer current consumption intent M_k + predict the next preferred item i_k; Step 3 — generate 3 guidance queries + a confidence score c per query; Answer JSON {"interest_tag": [query1, query2, query3], ...}.
- Hierarchical multi-level rewards (4 granularities):
  (1) Think-level: R_match via an Optimal Ordered Matching Algorithm (DP — dynamic programming, Alg 1): reference subsequences Ŝ_u (m) vs model S_u (n), score(Î_i, I_j) = 2·(|Ŝ_i ∩ S_j|)/(|Ŝ_i|+|S_j|) · log(|Ŝ_i|+|S_j|) — primary interests earlier (length penalty); R_action(a,b) = 2(|Ŝ_a∩S_b|)/(|Ŝ_a|+|S_b|); R_logic(a,b) = cosine similarity between interest labels via the mge-small semantic encoder; R_think_format: detect ["Step1","Step2","Step3"] + JSON completeness → 1/0.
  (2) Query-level (per query): R_length ≤15 Chinese characters → 1/0; R_value: a judge model trained on manually annotated data, rating r_t ∈ {S, A, B} → 1/0.5/0 (S: targeting specific consumer groups/usage scenarios, reflecting decisions, helping users understand item parameter differences; A: flagship store channel words, advertising statements, vague content; B: not smooth, non-e-commerce, unmappable to a real item, brand category mismatch, unsafe content).
  (3) Interest-level (per cluster): R_sem = weighted cosine similarity between candidate queries and the reference query (weights = normalized confidence scores); R_style = Type-Token Ratio (TTR — unique tokens / total tokens); R_format: number of candidate queries = T exactly → 1/0.
  (4) Global-level: R_content = 1 − mean pairwise cosine similarity between mean-pooled cluster representations → encourages diversified interests, avoids homogeneous expressions across clusters.
- GRPO optimization: R_response = R_think + R_query + R_interest + R_global (weighted aggregation); group size G=8, r_i(θ) = π_θ(o_i|q)/π_old(o_i|q), advantage A_i = (R_i − mean({R}))/(std({R})+ε), clipped surrogate − β·DKL. Reward weights: ω_think_format 0.5, ω_match 2.0, ω_length 0.2, ω_value 0.8, ω_sem 0.5, ω_style 0.3, ω_format 0.2, ω_content 0.5.
- DPO stage: positive samples y_w = RL checkpoint think-mode responses' final answers (discarding reasoning traces); negative y_l = non-thinking-mode responses (70% from RL checkpoints, 30% from the base model); preference-pair filtering: remove the top 30% most semantically similar positive-negative pairs (unfiltered pairs contain many semantically similar cases → unstable optimization, templated/homogeneous outputs = "ineffective learning"); J_DPO with β temperature coefficient.
- Deployment: the nearline pipeline invokes the model after every N accumulated user interactions (clicks/favorites); non-thinking mode outputs multiple interest labels + guidance queries → written into a mapping table (user_id → guidance queries); the online pipeline uses efficient vector retrieval to locate the index and retrieve personalized candidates in real time.

## Key Findings
- Offline test set (1,000 samples, Taobao/Tmall logs June–July 2026) — Value metric (Table 1, S/A/B ratio = proportion of queries at rating S/A/B): S ratio: Qwen3-30B-A3B backbone 0.6405; Qwen3.5-122B-A10B 0.8251; Qwen3-235B-A22B 0.7940; GPT-oss-120B 0.7177; DeepSeek-V4-Pro 0.8152; LLM4AIGQ-MULTISFT 0.8044; LLM4AIGQ-ONESFT 0.8119; MULTISFT+RL 0.8138; ONESFT+RL 0.8360; MULTISFT+RL+DPO 0.8555; ONESFT+RL+DPO 0.8616 (best). B ratio drops 0.1043 (backbone) → 0.0274 (best variant). ONE (single-interest SFT) > MULTI (mixed-interest SFT) at every stage: 0.8119>0.8044, 0.8360>0.8138, and ONESFT+RL+DPO 0.8616 > MULTISFT+RL+DPO 0.8555.
- GRPO multi-level reward ablation (Table 3, Recall@10 / NDCG@10): LLM4AIGQ-ONESFT+RL 0.1771/0.2101; w/o think-reward 0.1696/0.1959 (relevance drops the most — the think-level reward supervises interest disentanglement); w/o query-reward 0.1727/0.2075; w/o interest-reward 0.1713/0.1922; w/o global-reward 0.1744/0.2034. Removing ANY reward component → declines in both relevance and value.
- DPO: ONESFT+RL+DPO Recall@10 0.2377 vs ONESFT+RL 0.1771 (+34.2% relative); w/o preference-pair filtering 0.2182 (filtering +8.9% relative); MULTISFT+RL+DPO 0.2364 vs w/o filter 0.2127.
- Context compression (Table 2, 100-sample stress test): short titles vs original titles — input tokens 2.35k vs 3.21k (−26.8%), output tokens 146 vs 153, TTFT (time to first token) 110ms vs 114ms, RT (response time) 2.84s vs 3.18s (−10.7%). The model's output style imitates the item title → shorter titles → more concise output.
- A/B pairwise evaluation (Table 4, LLM-as-Judge Gemini-3.5-Flash vs teacher DeepSeek-V4-Pro, same user context, criteria: consistency with consumption intent, preferences, shopping-guidance value, content rationality, linguistic quality): base model win rate 34.63%; +SFT 50.25%; +SFT+RL 57.53% (surpasses the teacher); +SFT+RL+DPO 54.95% (slight drop — the DPO trade-off between reasoning quality and inference efficiency; most RL capability preserved, still above the teacher).
- Online A/B test (Tmall, shopping guidance / search / item detail pages): introducing AIGQ consistently improves user click performance; initial 10% traffic: +4.46% uCTR (user click-through rate) vs the baseline bucket; scaled to 40% traffic: +2.53% uCTR over 6 days of online validation. Deployed online at the scale of hundreds of millions of users.
- Baselines insight: larger SOTA models show worse relevance than the 30B backbone — larger models tend to generate more novel queries (prone to hallucination in e-commerce), while smaller models rely on high-frequency contextual terms.

## Actionable Insights
1. Multi-interest segmentation before query generation beats single-interest generation: S ratio 0.8616 (ONESFT+RL+DPO) vs 0.6405 backbone (+22.1pp top-rated queries); B ratio (unsafe/unmappable) 0.1043→0.0274. Apply: when generating content/product suggestions for a customer, first segment the customer into ≤3 interest clusters (by temporal proximity + semantic relevance), generate queries per cluster — don't merge all history into one prompt (causes focus on a single main interest and loses low-frequency interests).
2. Hierarchical reward design (think/query/interest/global) with a judge model rating queries S/A/B: removing the think-level reward causes the largest relevance drop; removing the query-level reward degrades value. Apply: when using an LLM to generate content, score each output with a judge model on a 3-level rubric (S: specific customer group/scenario + parameter comparison; A: generic; B: unmappable to a product) — keep only S/A, reject B.
3. DPO distillation from think mode to non-think mode retains 96% of the gain (win rate 57.53%→54.95%) while reducing token/reasoning cost; preference-pair filtering (remove the top 30% most similar pairs) adds +8.9% Recall@10. Apply: when you need a fast LLM (real-time recommendations), distill reasoning into a non-reasoning mode via DPO + filter semantically duplicate preference pairs — don't use raw think-mode output for latency-sensitive production.
4. Item short-title compression (−26.8% input tokens, −10.7% RT) and output style imitating the input title → shorter titles, more concise output. Apply: when feeding product data into an LLM, preprocess into short titles (drop marketing keywords/flagship-store words) — cheaper and more concise output.

## Assumptions & Limitations
- Conditions: requires a teacher model (DeepSeek-V4 Pro) for short titles + interest segmentation + reference queries; behavior sequence truncated to 50 (captures only short-term interests — long-term interests only via the profile summary); at most 3 interest subsequences / 3 queries per interest; queries ≤15 Chinese characters.
- Stated limitations (implicit): DPO trade-off — win rate drops 57.53%→54.95% (reasoning quality vs efficiency); no universal evaluation metrics for AIGQ (uses relevance Recall/NDCG + S/A/B value ratings); user interests are complex and diverse → positive samples may be discrepant from history (mitigated by confidence-weighted evaluation).
- Unstated: labels depend on the teacher model (DeepSeek-V4 Pro) — teacher bias propagates into SFT/RL supervision; the judge model rating S/A/B is trained on manually annotated data — annotation cost/quality not discussed; the online A/B test only measures uCTR (not conversion/revenue); evaluation on Taobao/Tmall (Chinese e-commerce) — transfer to other markets untested; RL only 100 steps (early stage, possibly underfit); think-level matching uses subsequence overlap + semantic similarity — interest labels are not human-verified.
- Deployment dependency: the nearline pipeline needs mapping-table infrastructure + vector retrieval; non-thinking-mode output quality depends on DPO distillation.
