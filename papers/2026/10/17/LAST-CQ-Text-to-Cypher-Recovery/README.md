# 2609.12746 — What Drives Recovery in Agentic Text-to-Cypher? LAST-CQ: An LLM Agent Self-Refinement Framework

## Problem
- Agentic structured-query generation pipelines bundle ≥3 mechanisms — failure detection, feedback synthesis, re-generation — nhưng reported gains attribute to architecture as a whole. Nếu gain đến từ cheapest component, field đang over-investing vào expensive ones.
- Text-to-Cypher đặc biệt corrosive: query well-formed but wrong vẫn execute thành công và trả misleading data (silent failure); LLM routinely emit structurally hallucinated queries (non-existent labels, invalid relationship types, patterns execute but return nothing).

## Contribution
- LAST-CQ: five-agent, training-free, execution-grounded Text-to-Cypher framework làm instrumented testbed — mỗi mechanism removable independently, đo loss. Recovers 91.7% queries fail under single-pass generation (pooled 1,799/1,917 = 93.8%), lift hit retrieval +11.8%, trong khi query success first time cost đúng 1 LLM call (bằng single-pass).
- 3 counterfactuals trên 2,471 live-database queries (Neo4j Text2Cypher benchmark executable subset, Ozsoy et al. 2025, 16 domains) × 6 backbones (GPT-4o-mini, GPT-4o, Gemini 1.5 Flash, Gemini 1.5 Pro, Claude Sonnet 4, DeepSeek-Chat→V3; 3 vendor scale tiers; all T=0, in-context, no fine-tuning) → localise gain: detection + routing là load-bearing, feedback sophistication chỉ ~1 point exact match, parallel sampling actively harmful (−10.8%/−11.4%).
- Order-invariant evaluation: 13,563 executed results, 3 invariance classes (order-sensitive GLEU, order-invariant exact match, judge semantics); n-gram overlap không bound theo cả 2 hướng; LLM judge optimistic 9 points vs blind human labels.

## Method
- 5 agents orchestrated state machine: (1) Schema Parsing P (0 LLM calls) — deterministic parsers covering 8 formats, LLM extraction chỉ fallback; benchmark này deterministic path handle 100% 2,471 schemas, fallback never fires. (2) Generation G (1 call) — candidate từ parsed schema + question (Ozsoy methodology). (3) Validation V (0–2 calls) — EXPLAIN against live schema, rồi execute với LIMIT 1 để catch well-formed-but-empty; cả hai pass → return immediately, KHÔNG invoke model. Chỉ khi fail: parse query (1 call) + deterministic schema check (labels, relationship types, properties tồn tại?); chỉ khi violations → call 2 tổng hợp grounded hints H_val. (4) Correction C (1 call) — rewrite query từ hints, schema Σ, correction history Γ (pass trong prompt với instruction không repeat prior attempt). (5) Execution E (0 calls) — run validated query; nếu empty → inject fixed constant H_relax (6 hints: case-insensitive regex, substring rather than equality, canonical datetime() formatting, dropping over-restrictive labels, simplifying RETURN) rồi route về Correction. KHÔNG model nào produce H_relax.
- Control flow: inner loop Validation+Correction đến valid hoặc N=2 iterations; outer loop execute, nếu empty inject H_relax + refine 1 lần nữa, M=1 cycle (implementation: single-shot latch, larger M never measured). Terminate khi query validates + returns non-empty, budget hết, hoặc relaxation đã fire.
- Cost accounting: first-time success = đúng 1 call; mỗi failed cycle thêm tối đa 3 (parse, hint synthesis, correction). 53–97% queries cần no correction. Mean pipeline stages 3.14–4.19; derived LLM-call means 1.1 (Claude) đến 2.5 (Gemini Flash).
- Counterfactual baselines: No-refinement = re-score cùng LAST-CQ+DB run với mọi query vào correction loop assigned zero (counterfactual upper bound, KHÔNG phải independent run). Naive retry = giữ NGUYÊN detection/routing machinery (EXPLAIN, LIMIT 1, cycle budget, history Γ, routing) nhưng Correction Agent nhận raw Neo4j error string thay vì synthesised hints (mirror NeoDash). Best-of-3 = cùng budget, 3 candidates parallel (k=3, T=0.7), first non-empty selected.
- Metrics labelled by invariance: Execution Google-BLEU (order-sensitive — comparability metric, không phải correctness evidence); Execution Exact Match (order-invariant, canonical normalization sorts rows and keys); Judge semantic accuracy (CORRECT/PARTIAL/INCORRECT); set-based precision/recall/F1/Jaccard/set equality (order-invariant). Aggregate = unweighted mean over 6 backbones (KHÔNG pooling). GLEU convention credits non-empty result vs empty reference 1.0 → strict set-theoretic convention cho set numbers.

## Key Findings
- RQ1: LAST-CQ+DB cải thiện average GLEU +3.4% over Baseline (+6.5% small, +2.8% medium, +2.9% GPT-4o); aggregate 0.4587→0.4729. Schema-only LAST-CQ chỉ ~+1% và giảm GLEU nhẹ cho 2 strongest models (static validation không có execution evidence trigger unnecessary rewrites khi baseline quality đã cao). DeepSeek-Chat giảm 1.3% (schema-representation differences, không phải correction drift). Exact match +0.5%.
- Recovery: 91.7% per-model mean (pooled 93.8%), ΔHR +0.10/+0.44/+0.02/+0.04/+0.08/+0.03; Gemini Flash outlier: nửa queries fail baseline, 97.3% recovered, mean recovered GLEU 0.44 = strong models' first-pass output. Stable 16 domains (CV=0.147). Semantic accuracy 88.2% aggregate (52.3% correct) — KHÔNG track GLEU rank (DeepSeek lowest GLEU gain, highest judged accuracy); judge chỉ chạy trên LAST-CQ+DB outputs → không chứng minh refinement raise semantic correctness vs single-pass.
- RQ2-1 removing correction: vs no-refinement counterfactual +12.3% aggregate (0.4729 vs 0.4211), +80.7% Gemini Flash (0.4350 vs 0.2407), +7.6% mini, +2.4% Claude, +3.9% Pro, +8.9% GPT-4o, +2.7% DeepSeek — tất cả p<0.001 (paired bootstrap, n=10,000). vs single-pass baseline chỉ +3.1%. True value nằm giữa 2 bounds — nearer lower cho strong backbones, upper cho weak.
- RQ2-2 removing schema grounding (Naive retry, 1,917 corrected queries, same budget N=2): naive EM 19.9% vs LAST-CQ 20.9%; end-to-end aggregate GLEU gap 0.4729 vs 0.4718 (<0.2%). LAST-CQ dẫn 5/6 models bởi 1–2 points, thua DeepSeek (17.9% vs 20.2%). Paired subset 214 queries (Gemini-Pro + DeepSeek): set-F1 0.200 vs 0.219 (−0.019); two one-sided tests: equivalent to zero within ±0.075 set-F1 (p=0.002), KHÔNG within ±0.05 (p=0.053) → rule out schema-grounding advantage > ~0.075. Set equality, Jaccard đồng ý; restrict 148 rows both pipelines serialise GT identically: −0.023 unchanged.
- Empty-result convention flatters both systems: 230/1,917 (12.0%) có empty reference result, GLEU convention awards 1.0 khi reference empty + output non-empty — query nên trả nothing lại score perfect khi trả something (đúng failure relaxation pass induces). Excluding chúng: GLEU 0.350 LAST-CQ vs 0.365 naive (1,687 queries), set-F1 0.070 vs 0.104 (paired subset) — LAST-CQ's aggregate edge carried ENTIRELY bởi subset metric permissive nhất; schema-grounded feedback không cung cấp actionable guidance khi bỏ forgiving cases.
- Independent evidence: Tomczak (2026), CypherBench, gate design + model set khác — plain verbal rendering của database error đạt nearly correction success của richest category-typed structured feedback tại fraction of input-token cost.
- RQ2-3 Best-of-3 sampling: underperforms cả single-pass — GLEU 0.3728 vs 0.4180 (GPT-4o-mini, −10.8%) và 0.4671 vs 0.5270 (GPT-4o, −11.4%) so với LAST-CQ+DB 0.4378/0.5421. GPT-4o-mini hit rate FALLS vs chính T=0 baseline (87.6%→85.2%) — higher temperature raise chance MỌI candidate hallucinate trên hard queries. Chỉ 1.37/1.16 candidates tried avg, 79–91% queries answered by first. Caveat: T>0 confounds temperature với selection (no intermediate sweep); selector deliberately weak (first non-empty, không majority vote/EXPLAIN reranking) — claim hẹp hơn: equal-budget sampling với weak selector tệ hơn grounded sequential correction; competent selector cần verification machinery anyway → detector load-bearing theo cả 2 cách spend.
- RQ3 n-gram overlap không bound 2 hướng: BLEU vs set-F1 r=0.71, ρ=0.59; BLEU exceeds set-F1 trên 65.9% pairs, falls below 3.1% (mean 0.392 vs 0.229) — serialised overlap credits rows share tokens with wrong rows. Chiều ngược: 2.9% results set-identical mà score <1.0 purely from row ordering; set-identical average 0.891 → BLEU≥0.999 proxy UNDERSTATE order-invariant accuracy mọi model (naive aggregate rises 19.9%→22.6% under direct set equality). Against judged semantics: pessimistic — 33.9% partial-BLEU queries judged fully correct.
- Judge optimistic: Cohen's κ=0.63 (GPT-4o-mini vs GPT-4o) đo inter-model consistency, KHÔNG phải human agreement — 2 judges sharing training distribution có thể consistently wrong. 122 corrected queries labelled blind: human-judge agree 64.8% three-way (κ=0.48), 82.8% valid/invalid (κ=0.59) — cả hai dưới inter-judge figures; LLM–LLM agreement overstates validity. Gap directional: judge calls 74.6% at-least-partially-correct vs human 65.6% — 9-point optimism concentrated in over-use of PARTIAL → corpus-level 88.2% đọc như upper bound ~10 points. KHÔNG affect §6 (counterfactuals so sánh conditions scored identically).

## Actionable Insights
- Invest in detector + router, không phải feedback generator: nơi environment trả hard failure signal, majority gain đến từ noticing failure + spending bounded retry budget; marginal call biến error thành eloquent guidance chỉ mua 1 point exact match. Ví dụ: Text-to-Cypher agent — EXPLAIN pre-validation + LIMIT 1 empty detection + 2-cycle budget + raw error string retry = 91.7% recovery mà KHÔNG cần LLM-synthesised hints module.
- First-time success phải cost đúng 1 call: short-circuit validation (0 calls khi both checks pass) để overhead chỉ rơi lên minority queries fail (53–97% need no correction). Ví dụ: pipeline agent — validate statically trước, chỉ call model khi fail, mean 1.1–2.5 calls/query thay vì fixed multi-call.
- KHÔNG dùng parallel sampling thay sequential correction trong low-entropy output spaces (structured queries có ít correct forms): Best-of-3 degrade 10.8–11.4%, temperature T=0.7 làm hit rate FALLS (87.6%→85.2%). Ví dụ: budget cho query agent → sequential retry với error feedback, KHÔNG k=3 sampling.
- Fixed relaxation hint set (6 hints: case-insensitive regex, substring, canonical datetime(), drop over-restrictive labels, simplify RETURN) giải quyết empty results với 0 LLM calls — ví dụ thực tế: `CONTAINS "new energy technologies"` → `=~ '(?i).*new energy technologies.*'` áp dụng verbatim.
- Evaluation phải state invariances: order-sensitive overlap vừa over-report vs set equivalence (65.9% pairs) vừa under-report vs semantics (33.9% partial-BLEU fully correct) — measured gains partly metric artifact. Ví dụ: benchmark Text-to-Cypher report cả 3 classes (GLEU + order-invariant exact match + judge), không dùng BLEU≥0.999 làm EM proxy (understate 19.9%→22.6%).
- LLM judge optimistic ~9 points vs blind human labels (over-use PARTIAL): corpus accuracy figure là upper bound. Ví dụ: production Text-to-Cypher — sample 100+ results, human-label blind trước khi tin judge accuracy; counterfactual A/B so sánh conditions scored identically thì judge OK.

## Assumptions & Limitations
- Single benchmark + engine: executable subset of one Neo4j benchmark (2,471 queries, 16 domains) — only public Text-to-Cypher benchmark với live databases; generalization sang Memgraph, property-graph engines khác, schemas ngoài 16 domains untested. Gusarov et al. evaluate trên CypherBench + Memgraph → no direct numerical comparison possible; counterfactual design engine-agnostic (cần validator + executor + correction step), porting là next experiment không phải redesign.
- Metric coverage asymmetric: per-query result payloads retained cho 1,917-query correction subset + 214-query paired subset, KHÔNG full corpus → set-based precision/recall/F1/Jaccard report trên subsets; full-corpus order-invariant evidence = exact match + judge. Paired head-to-head covers 2/6 backbones.
- Comparison set conditioned on own failures: 1,917 queries là những LAST-CQ chose to correct — naive retry KHÔNG evaluated trên queries LAST-CQ answered first-pass → đo relative correction quality under shared detector, không phải relative end-to-end system quality.
- M=1 single-shot latch — larger M never measured; Best-of-3 confounds temperature với selection (no intermediate-temperature sweep); selector deliberately weak.
- Judge optimistic 9 points — §5 semantic accuracy column là upper bound, không dùng để claim refinement raises semantics vs single-pass (baseline payloads not retained).
- Fine-tuning gains (0.13–0.34 Google-BLEU, Ozsoy et al.) lớn hơn mọi inference-time result ở đây nhưng cần labelled data + training run per backbone — paper hỏi orthogonal question (frozen model behind API).
- No latency/cost-at-scale analysis across multiple graph engines.
