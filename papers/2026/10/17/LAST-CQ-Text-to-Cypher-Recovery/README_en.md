# 2609.12746 — What Drives Recovery in Agentic Text-to-Cypher? LAST-CQ: An LLM Agent Self-Refinement Framework

## Problem
- Agentic structured-query generation pipelines bundle ≥3 mechanisms — failure detection, feedback synthesis, re-generation — but reported gains are attributed to the architecture as a whole. If the gain comes from the cheapest component, the field is over-investing in the expensive ones.
- Text-to-Cypher is particularly corrosive: a well-formed but wrong query still executes successfully and returns misleading data (silent failure); LLMs routinely emit structurally hallucinated queries (non-existent labels, invalid relationship types, patterns that execute but return nothing).

## Contribution
- LAST-CQ: a five-agent, training-free, execution-grounded Text-to-Cypher framework built as an instrumented testbed — every mechanism is removable independently and the loss measured. It recovers 91.7% of queries that fail under single-pass generation (pooled 1,799/1,917 = 93.8%), lifting hit retrieval by +11.8%, while a query that succeeds first time costs exactly 1 LLM call (the same as single-pass).
- Three counterfactuals over 2,471 live-database queries (Neo4j Text2Cypher benchmark executable subset, Ozsoy et al. 2025, 16 domains) × 6 backbones (GPT-4o-mini, GPT-4o, Gemini 1.5 Flash, Gemini 1.5 Pro, Claude Sonnet 4, DeepSeek-Chat→V3; three vendor scale tiers; all T=0, in-context, no fine-tuning) → the gain localises to detection + routing (load-bearing), feedback sophistication buys ~1 point of exact match, and parallel sampling is actively harmful (−10.8%/−11.4%).
- Order-invariant evaluation: 13,563 executed results across three invariance classes (order-sensitive GLEU, order-invariant exact match, judge semantics); n-gram overlap is not a bound in either direction; the LLM judge is optimistic by 9 points against blind human labels.

## Method
- Five agents orchestrated as a state machine: (1) Schema Parsing P (0 LLM calls) — deterministic parsers covering 8 formats, LLM extraction only as fallback; on this benchmark the deterministic path handles 100% of 2,471 schemas and the fallback never fires. (2) Generation G (1 call) — a candidate from the parsed schema + question (Ozsoy methodology). (3) Validation V (0–2 calls) — EXPLAIN against the live schema, then execute with LIMIT 1 to catch well-formed-but-empty queries. If both checks pass → returns immediately, invoking NO model. Only on failure: parse the query (1 call) + a deterministic schema check (do these labels, relationship types and properties exist?); only if that reports violations → a second call synthesises the grounded hints H_val. (4) Correction C (1 call) — rewrites the query from the hints, schema Σ, and correction history Γ (passed in the prompt with an instruction not to repeat any prior attempt). (5) Execution E (0 calls) — runs the validated query; if it returns nothing → injects a fixed constant H_relax (six hints: case-insensitive regex, substring rather than equality, canonical datetime() formatting, dropping over-restrictive labels, simplifying RETURN) and routes back to Correction. NO model produces H_relax.
- Control flow: an inner loop alternates Validation+Correction until valid or N=2 iterations; an outer loop executes, and on an empty result injects H_relax and refines once more, M=1 cycle (implemented as a single-shot latch — larger M was never measured). It terminates when the query validates and returns non-empty, when the budget is spent, or when the relaxation pass has fired.
- Cost accounting: a first-time success costs exactly 1 call; each failed cycle adds up to 3 (parse, hint synthesis, correction). 53–97% of queries need no correction. Mean pipeline stages 3.14–4.19; derived LLM-call means range from 1.1 (Claude) to 2.5 (Gemini Flash).
- Counterfactual baselines: No-refinement = re-score the same LAST-CQ+DB run with every query that entered the correction loop assigned zero (a counterfactual upper bound, NOT an independent run). Naive retry = keeps the ENTIRE detection/routing machinery (EXPLAIN, LIMIT 1, cycle budget, history Γ, routing) but the Correction Agent receives the raw Neo4j error string instead of synthesised hints (mirroring NeoDash). Best-of-3 = the same budget, 3 candidates sampled in parallel (k=3, T=0.7), first non-empty result selected.
- Metrics labelled by invariance: Execution Google-BLEU (order-sensitive — a comparability metric, not correctness evidence); Execution Exact Match (order-invariant, canonical normalisation sorts rows and keys); Judge semantic accuracy (CORRECT/PARTIAL/INCORRECT); set-based precision/recall/F1/Jaccard/set equality (order-invariant). "Aggregate" = the unweighted mean over the 6 backbones (not pooling over queries). The GLEU convention credits a non-empty result against an empty reference with 1.0 → strict set-theoretic convention for all set-based numbers.

## Key Findings
- RQ1: LAST-CQ+DB improves average GLEU +3.4% over Baseline (+6.5% small, +2.8% medium, +2.9% for GPT-4o); aggregate 0.4587→0.4729. Schema-only LAST-CQ yields only ~+1% and slightly decreases GLEU for the two strongest models (static validation without execution evidence triggers unnecessary rewrites when baseline quality is already high). DeepSeek-Chat decreases 1.3% (schema-representation differences, not correction drift). Exact match improves +0.5%.
- Recovery: 91.7% per-model mean (pooled 93.8%); ΔHR +0.10/+0.44/+0.02/+0.04/+0.08/+0.03; Gemini Flash is the outlier — half its queries fail at baseline, 97.3% are recovered, and its mean recovered GLEU of 0.44 matches strong models' first-pass output. Stable across the 16 domains (CV=0.147). Semantic accuracy is 88.2% aggregate (52.3% correct) — it does NOT track GLEU rank order (DeepSeek has the lowest GLEU gain and the highest judged accuracy); the judge ran on LAST-CQ+DB outputs only, so it cannot establish that refinement raises semantic correctness vs single-pass generation.
- RQ2-1 removing correction: vs the no-refinement counterfactual, +12.3% aggregate (0.4729 vs 0.4211), +80.7% for Gemini Flash (0.4350 vs 0.2407), +7.6% mini, +2.4% Claude, +3.9% Pro, +8.9% GPT-4o, +2.7% DeepSeek — all p<0.001 (paired bootstrap, n=10,000). vs the single-pass baseline, only +3.1%. The true value lies between these bounds — nearer the lower for strong backbones, the upper for weak ones.
- RQ2-2 removing schema grounding (Naive retry, the 1,917 corrected queries, same budget N=2): naive EM 19.9% vs LAST-CQ 20.9%; end-to-end aggregate GLEU gap 0.4729 vs 0.4718 (<0.2%). LAST-CQ leads on 5 of 6 models by one to two points and loses on DeepSeek (17.9% vs 20.2%). On the 214-query paired subset (Gemini-Pro + DeepSeek): set-F1 0.200 vs 0.219 (−0.019); two one-sided tests: equivalent to zero within ±0.075 set-F1 (p=0.002) but NOT within ±0.05 (p=0.053) → a schema-grounding advantage larger than ~0.075 is ruled out. Set equality and Jaccard agree; restricting to the 148 rows where both pipelines serialise ground truth identically leaves it unchanged (−0.023).
- The empty-result convention flatters both systems: 230/1,917 (12.0%) have an empty reference result, and the GLEU convention awards 1.0 whenever the reference is empty and the output is not — a query that should return nothing scores perfectly for returning something, which is exactly the failure the relaxation pass induces. Excluding them: GLEU 0.350 LAST-CQ vs 0.365 naive (1,687 queries), set-F1 0.070 vs 0.104 on the paired subset — LAST-CQ's small aggregate edge is carried ENTIRELY by the subset where the metric is most permissive; schema-grounded feedback provides no actionable guidance once the forgiving cases go.
- Independent evidence points the same way: Tomczak (2026), on CypherBench with a different gate design and model set, ablates corrector feedback formats and finds a plain verbal rendering of the database error reaches nearly the correction success of the richest category-typed structured feedback, at a fraction of the input-token cost.
- RQ2-3 Best-of-3 sampling: underperforms even single-pass generation — GLEU 0.3728 vs 0.4180 (GPT-4o-mini, −10.8%) and 0.4671 vs 0.5270 (GPT-4o, −11.4%), against LAST-CQ+DB's 0.4378/0.5421. GPT-4o-mini's hit rate actually FALLS against its own T=0 baseline (87.6%→85.2%) — higher temperature raises the chance that EVERY candidate hallucinates on hard queries. Only 1.37/1.16 candidates tried on average, with 79–91% of queries answered by the first. Caveat: T>0 varies temperature and selection together (no intermediate-temperature sweep); the selector is deliberately weak (first non-empty, not majority vote or EXPLAIN-validity reranking) — the claim is narrower: equal-budget sampling with a weak selector is a worse use of the budget than grounded sequential correction, and a competent selector needs the verification machinery anyway, so the detector is load-bearing either way.
- RQ3, n-gram overlap is not a bound in either direction: BLEU vs set-F1 r=0.71, ρ=0.59; BLEU exceeds set-F1 on 65.9% of pairs and falls below on 3.1% (mean 0.392 vs 0.229) — serialised overlap credits rows that merely share tokens with rows that are wrong. In the other direction: 2.9% of results are set-identical yet score below 1.0 purely from row ordering, and set-identical results average 0.891 → exact-match figures using BLEU≥0.999 as a proxy UNDERSTATE order-invariant accuracy for every model (naive retry's aggregate rises from 19.9% to 22.6% under direct set equality). Against judged semantics it is pessimistic: 33.9% of partial-BLEU queries are judged fully correct.
- The judge is optimistic: Cohen's κ=0.63 (GPT-4o-mini vs GPT-4o) measures inter-model consistency, NOT agreement with humans — two judges sharing a training distribution can be consistently wrong. 122 corrected queries labelled blind to the verdicts: human-judge agreement 64.8% of three-way decisions (κ=0.48) and 82.8% of valid/invalid decisions (κ=0.59) — both below the inter-judge figures; LLM–LLM agreement overstates validity. The gap is directional: the judge calls 74.6% at least partially correct against the human's 65.6% — a 9-point optimism concentrated in over-use of PARTIAL, so the corpus-level 88.2% should be read as an upper bound by roughly ten points. This does not affect §6, whose counterfactuals compare conditions scored identically.

## Actionable Insights
- Invest in the detector and the router, not the feedback generator: where the environment returns a hard failure signal, most of the gain comes from noticing the failure and spending a bounded retry budget; the marginal call that turns an error into eloquent guidance bought one point of exact match. Example: a Text-to-Cypher agent with EXPLAIN pre-validation + LIMIT 1 empty detection + a 2-cycle budget + raw-error-string retry achieves 91.7% recovery WITHOUT an LLM-synthesised hints module.
- A first-time success must cost exactly one call: short-circuit validation (0 calls when both checks pass) so overhead falls only on the minority of queries that fail (53–97% need no correction). Example: a pipeline agent validates statically first and only calls the model on failure, averaging 1.1–2.5 calls per query instead of a fixed multi-call loop.
- Do NOT substitute parallel sampling for sequential correction in low-entropy output spaces (structured queries have few correct forms): Best-of-3 degrades quality 10.8–11.4%, and temperature T=0.7 makes the hit rate FALL (87.6%→85.2%). Example: budget a query agent for sequential retry with error feedback, not k=3 sampling.
- A fixed relaxation hint set (six hints: case-insensitive regex, substring, canonical datetime(), drop over-restrictive labels, simplify RETURN) resolves empty results with 0 LLM calls — a real trace: `CONTAINS "new energy technologies"` → `=~ '(?i).*new energy technologies.*'` applied verbatim.
- Evaluation must state its invariances: order-sensitive overlap both over-reports against set equivalence (65.9% of pairs) and under-reports against semantics (33.9% of partial-BLEU queries are fully correct) — measured gains are partly a metric artifact. Example: benchmark Text-to-Cypher systems with all three classes (GLEU + order-invariant exact match + judge), and never use BLEU≥0.999 as an exact-match proxy (it understates 19.9%→22.6%).
- An LLM judge is optimistic by ~9 points against blind human labels (over-use of PARTIAL): a corpus accuracy figure is an upper bound. Example: for production Text-to-Cypher, human-label a blind sample of 100+ results before trusting judge accuracy; for counterfactual A/B comparisons scored identically, the judge is fine.

## Assumptions & Limitations
- Single benchmark + engine: the executable subset of one Neo4j benchmark (2,471 queries, 16 domains) — the only public Text-to-Cypher benchmark with live databases; generalisation to Memgraph, other property-graph engines, or schemas outside these 16 domains is untested. Gusarov et al. evaluate on CypherBench + Memgraph, so no direct numerical comparison is possible; the counterfactual design itself is engine-agnostic (it needs only a validator, an executor, and a correction step), so porting it is the natural next experiment rather than a redesign.
- Metric coverage is asymmetric: per-query result payloads were retained for the 1,917-query correction subset and a 214-query paired subset, but not for the full corpus → set-based precision/recall/F1/Jaccard are reported on those subsets; full-corpus order-invariant evidence rests on exact match and judge accuracy. The paired head-to-head covers 2 of 6 backbones.
- The comparison set is conditioned on our own failures: the 1,917 queries are those LAST-CQ chose to correct — naive retry is never evaluated on queries LAST-CQ answered first-pass, so it measures relative correction quality under a shared detector, not relative end-to-end system quality.
- M=1 as a single-shot latch — larger M was never measured; Best-of-3 confounds temperature with selection (no intermediate-temperature sweep); the selector is deliberately weak.
- The judge is optimistic by 9 points — the §5 semantic accuracy column is an upper bound and cannot be used to claim refinement raises semantics vs single-pass (baseline payloads were not retained).
- Fine-tuning gains (0.13–0.34 Google-BLEU, Ozsoy et al.) exceed any inference-time result here but need labelled data and a training run per backbone — this paper asks the orthogonal question (a frozen model behind an API).
- No latency/cost-at-scale analysis across multiple graph engines.
