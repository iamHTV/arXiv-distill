# 2609.02745 — Incremental Pooled LLM Evaluation for Cost-Effective Retrieval Model Selection

## Problem
- Selecting a retrieval model for a production RAG system requires reliable comparative evaluation, but obtaining relevance judgments at scale is expensive and difficult to repeat as new candidate systems arrive. Evaluating N systems independently with an LLM judge costs O(N·Q·K) judgments (queries × top-k documents per system), with substantial redundancy since different retrieval systems often surface overlapping document sets.
- The gold standard (pooled human relevance judgments, à la TREC) is expensive, slow, and hard to repeat. Classical TREC pooling has pool bias: unjudged documents are treated as non-relevant, systematically disadvantaging systems with novel retrieval behavior.

## Contribution
- Pooled LLM evaluation: an LLM judges the UNION of documents retrieved by all systems under test, and these judgments are reused to compute standard IR metrics for every system in the pool. Incremental: a new system S_{N+1} is added by retrieving with it and judging ONLY the new documents it contributes (R_{N+1}(q)\P(q)); all previously computed judgments are reused exactly, and the new system is immediately comparable to all existing ones on an equal footing.
- Four advantages: (1) cost amortization — shared documents are judged once, each additional system incurs only marginal cost for its uniquely retrieved documents; (2) ranking stability — P@k and DCG@k are exactly invariant under pool expansion (they depend only on a system's own top-k and frozen labels); Recall@k, AP, and nDCG@k preserve per-query pairwise orderings (system-specific numerator fixed, query-specific denominator shared, all systems scaled by the same factor); macro-averaged benchmark-level invariance is NOT guaranteed in general (per-query scaling factors may differ) → tested empirically; (3) reduced pool bias — every newly retrieved document is judged, so no systematic penalty for novel retrieval behavior; (4) accuracy — nDCG@10 ρ = 0.69–0.95 against gold-standard human judgments, and 74% of pairwise ranking disagreements fall within the gold standard's own bootstrap sampling noise.
- Validation: four retrieval benchmarks × 11 systems (dense, sparse, hybrid); production deployment on 62 retrieval configurations for a financial news QA system.

## Method
- Four steps: (1) Retrieve — for each system Si and query q, obtain top-k Ri(q); (2) Pool — P(q) = ∪ Ri(q); (3) Judge — for each unique (q,d) pair, obtain a graded relevance judgment on a 3-point scale (0 not relevant, 1 partially, 2 highly) from an LLM judge; (4) Evaluate — compute standard IR metrics for each system using the shared pool judgments restricted to Ri(q).
- Datasets: FiQA (648 queries, 57K corpus, 249,865 pool, 1,706 qrels, ~2.6 rel/query, binary); TREC-COVID (50 queries, 171K corpus, 18,870 pool, 66,336 qrels, ~1,327 rel/query, 0–2 scale); NQ (first 500 of 3,452 test queries, 2.68M corpus, 188,903 pool, 3,452 qrels, ~1.0 rel/query, binary); FinRAG-V (536 queries, 10.9K corpus, 192,783 pool, 606 qrels, ~1.1 rel/query, binary — financial multimodal; a layout-aware parser extracts text/tables/figures, an MLLM generates NL descriptions for tables/figures, interleaved in natural reading order with XML tags marking modality provenance).
- Systems: 5 embedding families (OpenAI text-embedding-3-large, Cohere Embed v4, Amazon Titan Embed v2, Nomic embed-text-v1.5, Nomic embed-text-v2-moe) × 3 configurations (dense cosine similarity, sparse BM25, hybrid reciprocal rank fusion) → 5 dense + 5 hybrid + 1 sparse = 11 per dataset. Matryoshka truncation to 256 dimensions where supported.
- Judge: GPT-4.1 (gpt-4.1-2025-04-14), temperature 0.0, single-turn prompt (no in-context examples, no system-level calibration) → reproducible and order-independent. The prompt requires a brief chain-of-thought ("thought" field ≤2 lines) followed by the numeric score in structured JSON; documents are presented in Title/Content format.
- Judge consistency: re-judging 1,000 (q,d) pairs per dataset — exact 3-point agreement 93–96% (κ=0.84–0.90), ≥99.9% within ±1 grade; binarized (scores 1–2 = relevant) 96–98%.
- Cross-judge: Claude Sonnet 4.6 with the same prompt on 1,000 pairs per dataset — binarized agreement 84–92% (κ=0.65–0.77); re-judging the full TREC-COVID pool (18,870 documents): despite 27% item-level disagreement, system rankings remained highly correlated (ρ=0.89 nDCG@10, 0.92 R@100, 0.88 MAP), with 89% pairwise agreement for nDCG@10 and R@100; both judges identified the same top system on the two most important metrics; P@10 was less stable (sensitivity to a small number of judgments per query).
- Protocol: top-100 documents per query; P@k, R@k, nDCG@k, and MAP computed against pseudolabels (pooled LLM judgments, all datasets) and gold qrels (published human judgments, all four datasets; NQ and FinRAG-V qrels are very sparse, ~1 relevant document per query).
- Bootstrap: B=10,000 iterations resample queries with replacement, recompute the macro-averaged metric for every system, and re-rank; the swap probability for a pair (A,B) is the fraction of iterations in which their ordering reverses; a pair is "qrels-uncertain" if swaps occur in >5% of resamplings; a qrels-vs-pseudolabel disagreement is classified as within qrels noise if the qrels themselves are uncertain about that pair.

## Key Findings
- Rank correlation (pooled LLM vs gold qrels, all p<0.05): FiQA nDCG@10 ρ=0.909/τ=0.782, P@10 0.918/0.818, R@100 0.864/0.709, MAP 0.855/0.673; TREC-COVID 0.691/0.564, 0.636/0.527, 0.818/0.673, 0.736/0.527 (lower — the gap between a general-purpose LLM and specialist biomedical assessors); NQ 0.945/0.818, 0.864/0.745, 0.736/0.600, 0.718/0.600; FinRAG-V 0.909/0.782, 0.936/0.818, 0.936/0.855, 0.882/0.745. Strongest on FiQA and NQ (nDCG@10 ρ ≥ 0.91), where the LLM judge's broader relevance notion aligns well with the sparse qrels.
- Pairwise agreement (55 pairs per dataset): FiQA 89–91%, TREC-COVID 76–78%, NQ 80–91%, FinRAG-V 87–93%.
- Bootstrap: for nDCG@10, 20 of 27 disagreements across all four datasets (74%) fall within qrels noise — only 7 reflect genuine ranking differences; across all four metrics combined, 74 of 112 disagreements (66%) are within noise on the three BEIR benchmarks; FinRAG-V shows 4 of 6 nDCG@10 disagreements within qrels uncertainty. Most pseudolabel ranks fall within the bootstrap 95% rank confidence intervals of the qrels. Pooled LLM evaluation correctly identifies the rank-1 system on FiQA across all four metrics; the few disagreements on NQ and TREC-COVID occur only where the qrels margin between the top two systems is negligible (bootstrap swap probability >40%). 97% of pairwise orderings are preserved once bootstrap uncertainty in the qrels is taken into account.
- Cost amortization: FiQA 712,800→249,865 judgments (65% saved); TREC-COVID 550,000→188,903 (66%); NQ 589,600→192,783 (67%); FinRAG-V 55,000→18,870 (66%). Total 1,907,400→650,421 — pooling eliminates ~1.26M redundant judgments (66% reuse).
- Ranking stability under 500 random system-addition orderings (pool grown from 1 to 11 systems, checking whether any pairwise nDCG@10 ranking reverses): NQ and TREC-COVID show ZERO reversals across all 500 orderings; FiQA 53.8% of orderings trigger a reversal but confined to a single pair whose final nDCG@10 scores differ by only 0.000014 (dense-nomic-1.5 vs hybrid-titan-v2), plus a second pair (hybrid-nomic-1.5 vs hybrid-nomic-v2) reversing in only 2.4% of orderings; FinRAG-V 1.4% (dense-emb3-large vs dense-titan-v2, Δ=0.0006). No pair with a meaningful score gap (Δ>0.001) reverses under any ordering on any dataset — the fragile pairs are exactly those the bootstrap rank CIs identify as statistically indistinguishable.
- Calibration bias: pseudolabel scores differ in absolute magnitude — the LLM's broader relevance notion inflates nDCG (mean +0.1% to +51% depending on dataset) while deflating recall (−17% to −39%), but the bias is approximately uniform across systems (within-column std ≤12.8pp for nDCG, ≤11.1pp for recall) → ordinal system rankings are preserved.
- Pool bias (leave-one-family-out, six model families): classical pooling penalizes novel systems — FiQA 8 pairwise swaps (max nDCG@10 penalty 0.033), TREC-COVID 10 swaps (0.055), FinRAG-V 1 swap (0.012), NQ 0 swaps (0.008). Judging newly contributed documents whenever systems are added removed ALL 19 pairwise ranking errors that classical pooling introduced across the three affected datasets.
- Production deployment: ~300k news article pages indexed in OpenSearch (one month of licensed data); 303 queries from four sources (LLM-generated from semantic article clusters 135, LLM-generated from metadata-clustered articles by company/industry/topic 91, templatic "latest news" for frequently mentioned entities 50, real user queries from production API traffic downsampled 27), plus perturbations (keyword-reduced and instruction-framed variants). 62 retrieval configurations: 5 embedding models (emb3-large, Cohere Embed v4, Nomic v1.5, Nomic v2-moe, MiniLM-L12-v2) × 3 modes (dense/hybrid/sparse) × 2–3 dimensionalities (256/768/1536) × 3 query formulations (original, keyword-reduced, instruction-framed) + variants of the top system with/without query expansion. Final pool: 766,350 unique (q,d) judgments (all GPT-4.1) vs 3,765,643 for independent evaluation → 79.6% reuse rate, 4.9× cost reduction; the pool was built incrementally over four weeks and at no point did previously computed judgments need to be re-run. Cost ≈ $800 total (GPT-4.1 at $2/M input, $8/M output tokens).
- Production rankings: the top-5 systems by MAP@100 were all hybrid — (1) hybrid-emb3-large-768 (MAP 0.461), (2) hybrid-emb3-large-256 (0.459), (3) hybrid-nomic-1.5-768 (0.454), (4) hybrid-nomic-v2-moe-768 (0.454), (5) hybrid-cohere-v4-1536 (0.454). Selected hybrid-emb3-large-256 for production (results + latency + embedding cost).
- Findings: higher dimensions improve dense retrieval (mean ΔMAP +0.029 for 256→768/1536) but the gap narrows under hybrid retrieval (+0.012), suggesting BM25 fusion compensates for reduced embedding capacity. Hybrid is more robust to query formulation: keyword-reduced queries hurt dense models more (ΔMAP −0.013), and instruction-framed queries degrade ALL systems (ΔMAP −0.039) by diluting the retrieval signal. Query expansion does not help on well-formed queries (MAP 0.424 vs 0.459) but acts as a robustness mechanism against verbose formulations, nearly eliminating the framing-induced recall@100 penalty (−4.8pp → −1.1pp).
- Incremental pool growth works: began with 5 systems and grew to 62 over four weeks; early conclusions (e.g. "hybrid > dense") were not invalidated by later additions. The same pool answered questions the team had not originally planned (dimensionality under hybrid, keyword queries, query expansion on framed queries) — zero additional LLM cost.

## Actionable Insights
- Start a benchmark with 3–5 systems and grow incrementally: each new model only has its uniquely retrieved documents judged (65–80% reuse). Example: for a RAG system evaluating a new embedding model — retrieve top-100, judge only documents not already in the pool, and compare immediately against all previously evaluated systems on an equal footing.
- Pooled LLM judging avoids classical pool bias: judging every newly contributed document removed all 19 ranking errors classical pooling introduced. Example: don't use TREC-style pooling (unjudged = non-relevant) when comparing hybrid vs dense — novel behavior gets penalized by 0.033–0.055 nDCG@10.
- Bootstrap the qrels before trusting a pairwise disagreement: 74% of disagreements lie within the gold standard's own sampling noise; only 7 of 220 pairs are genuine. Example: a dashboard comparing two retrieval models should compute the bootstrap swap probability (10,000 resamples); if >5%, the pair is "effectively tied" — don't decide the model on that pair.
- Hybrid retrieval is the default for production RAG: the top-5 were all hybrid, and it is more robust to query formulation (keyword/framed degrade dense more); BM25 fusion compensates for low dimensionality → use 256-dim embeddings (Matryoshka truncation) + BM25 instead of 1536-dim dense — lower latency and embedding cost with comparable MAP (0.459 vs 0.461).
- Do NOT use instruction-framed queries for retrieval evaluation (they degrade ALL systems by ΔMAP −0.039 by diluting the retrieval signal); do NOT use query expansion on well-formed queries (0.424 vs 0.459) — use expansion only as a robustness mechanism for verbose formulations (−4.8pp → −1.1pp recall penalty).
- Pin the judge model version + temperature 0 to preclude drift within an evaluation campaign; if the judge is updated, selective re-judging of a sample validates continuity. Example: log the judge version in every evaluation run's metadata; re-judge 1,000 pairs when upgrading GPT-4.1 → GPT-5.

## Assumptions & Limitations
- Tight clusters: systems separated by <0.001 nDCG (e.g. the NQ top-2) cannot be reliably distinguished by either qrels or pseudolabels (bootstrap swap >40% for both label sources); the method is designed for comparative model selection, NOT for resolving effectively tied systems.
- Limited judge diversity: rankings derive from a single primary judge (GPT-4.1); the Sonnet 4.6 validation is a full re-judge on TREC-COVID only; correlation and bias characteristics may differ for smaller, open-weight, or domain-specialized judges. The frozen-model assumption means that if the provider deprecates the pinned checkpoint, a re-judging strategy is needed.
- The calibration bias is uniform but non-zero: pseudolabel nDCG is inflated +0.1%–51% and recall deflated −17%–39% → absolute scores are NOT comparable to human-scale metrics; only ordinal rankings are trustworthy.
- Macro-averaged benchmark-level invariance is NOT guaranteed theoretically (per-query scaling factors differ under pool expansion) — empirically stable over 500 orderings, but fragile pairs (Δ<0.001) can reverse.
- Judge consistency is 93–96% exact (κ=0.84–0.90) — 4–7% of judgments are not exactly reproducible; suitable for reuse, not for per-document certification.
- FinRAG-V qrels are very sparse (~1 relevant doc/query) — correlation is strong (ρ=0.91) but sparse qrels limit measurement precision.
- The production corpus is ~300k news pages, one month, licensed — generalization to other domains (biomedical TREC-COVID had lower correlation 0.64–0.82) is not established.
