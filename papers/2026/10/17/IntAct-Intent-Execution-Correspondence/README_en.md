# 2610.04375 — Do Tool Calls Execute as Intended? Measuring and Repairing Intent-Execution Correspondence in LLM Agents

## Problem
- A tool call reaches its program through several hops: harness serialization → host wrapper → shell parse → process interface → target parser. Any hop can change the call without notice (quote consumption: `console.log("test")` arrives as `console.log(test)`; re-expansion: `%PATH%`, `!x`; truncation: MSYS2 Git Bash cuts a quoted argument at 8,186 UTF-16 code units and collapses backslash pairs, cmd.exe ends a command at its first line break; arity change: an operand is dropped or split).
- Benchmarks and failure analyses read the call and its result but NOT what a hop received, so path-caused failures are misattributed to the LLM. Command-execution problems account for 25.0% of 3,864 bug reports of 3 coding agents. Trajectory-based analyses (Who&When) read the trajectory, which does not contain what a hop received.

## Contribution
- Defines intent-execution correspondence (IEC): the executed action matches the action the emitted call denotes under the tool contract. FD(a,Π) = first hop where the receiver-parsed action differs from intent. A divergence is silent when the tool result contains neither an error flag nor a parser/quoting error message.
- IEC protocol: (A) witnesses observe what each hop received WITHOUT executing the call (BASH_ENV file for Bash; PowerShell parse rules without execution for the appended launch; argv probe at the process interface; argv sentry recording ancestor processes with an LLM in the loop); (B) the first divergence is decided by the receiver's OWN parser (not string equality — string comparison misclassifies 15/35 unchanged pairs as changed; it compares operators/words/heredoc bodies for Bash, the parse tree for PowerShell, the argument vector for programs; verdicts for 99.98% of 32,259 Bash calls); (C) repair replay — re-execute the recorded run with ONLY the named hop repaired (a reply cache replays without an LLM).
- IntAct: delivers the call through a channel the named hop does not parse (the rendering condition) — a sourced file for the Bash wrapper, native argument rendering for the PowerShell 5.1 process interface (native(s) = Eq. 1: escape quotes, double backslash runs), -EncodedCommand Base64(UTF16) for the wrapper, switching off history expansion/completion before typing into interactive Bash. Refuses a call no rendering carries (multi-line text under cmd.exe) — the refusal names the hop. Composes renderings (later hop first) when a launch changes a call at 2 hops. It does NOT change the call itself — action, working directory, and environment stay.
- IEC-Bench: 67 pattern pairs (hazard vs control differing in exactly one literal), 10 multi-line programs, 135 ToolHop chains (3–7 steps), 46 Terminal-Bench 2 tasks, under 6 execution paths and 4 LLMs (qwen3-coder-plus, Qwen2.5-Coder-32B, Qwen2.5-72B, Hermes-3-Llama-3.1-70B).

## Method
- Measurement: replay recorded calls through the witness of each hop; compare the received action with the sent action using the receiver's own parser. Windows corpus: 47,828 shell calls, 261 sessions, 6 developers, 11 weeks (Claude Code + Codex through Git Bash and PowerShell 5.1). Exposed calls: heredoc, backslash pair, or ≥1,000 characters (Bash); native program with constant arguments containing a quote/backslash/whitespace/empty (PowerShell) → 11,982 exposed.
- Loud-failure attribution: parse the agent's text with execution disabled — does not parse = generation error; parses but the witness sees a difference = path; an error at a line beyond the end of the text = path (wrapper-appended text); parses, intact, invokes a further interpreter = nested hop.
- Repair selection: the named hop (FD, plus the second hop when a launch changes a call twice) selects the rendering; no further measurement per call.

## Key Findings
- RQ1 real-world: 1,199/11,982 exposed calls change (10.0%). Claude Code's Bash launch: 12.0% of 7,491 exposed calls change; 67.0% for calls with a backslash pair; 100% for calls ≥8,000 characters. 663 merged-backslash calls ran → 535 (80.7%) ran the wrong action silently with no error. All 11 cut calls fail with an error. IntAct rerouted 227 changed calls; 65/199 sessions (32.7%) with an exposed call had a change; 23/27 sessions with ≥100 Bash calls.
- All 10 harnesses change calls at 3 of the 5 hops, and the hop differs between harnesses and platforms. PowerShell paths deliver the script intact and change the call at the process interface (196/297 lose a double quote within a value, 127 receive a different number of arguments). Qwen Code's cmd.exe launch: 30/31 multi-line commands run as an empty program. Linux: 4 harnesses change none in 80 runs — a command passed as an argument to the shell always arrives intact (1,779 calls of 4 harnesses, 4,012 calls of 9 developers, 161,214 held-out Codex calls).
- Linux handlings without an LLM: bash -c argument 0 changed; Terminus-2 interactive typing 4 silent/3 errors; SWE-ReX split-and-rejoin 12/1; OpenHands escaping 29/5; dash as /bin/sh 45/27. Terminus-2 typing: 1,113/1,118 Toolathlon programs with an expandable ! change vs 2/12,030 without.
- Leaderboard: 4,434 Terminus-2/KIRA trials, 245 keystroke batches with a tab or expandable !, 186 change (81 at a tab, 105 by history expansion) in 137/4,356 scored trials. 203,710 public trajectories: "event not found" 2,546 times in 1,532/113,674 trajectories of typing harnesses, NEVER in 90,036 of non-typing harnesses.
- Parse errors: 426 Bash/Python parse errors → 306 path-caused (253 cut, 46 merged backslash pairs, 7 open quotes), 84 generation, 36 nested. All 306 were reported to the agent as an error in its own text. In 231/306 the shortest wrapper delivers the call as written and only the longer session wrapper changed it — the changed-call rate is a lower bound.
- MCP: 16/22 servers tested, 6/16 and 4/6 change payloads; the fetch server turns a backslash in a URL into a slash; the SQLite server describes a nonexistent table when the name needs quoting; the file-system server writes `a:b` into an alternate data stream of `a` on Windows. Every change is reported as success; the tool description mentions none.
- RQ2 IEC-Bench: the 4 LLMs encounter a changed call in 16/71/63/34 chains (one-argument launch) and 128–133/135 (appended launch). Appended: 737/1,165 calls of qwen3-coder-plus change, 662 at a value with a space. The first changed call is the first tool call in 483/524 affected chain runs; the parser rejects it in 492.
- Score: Qwen2.5-72B leads Hermes-3 by 29 chains with direct JSON calls, but trails by 2 chains on the one-argument launch; with IntAct it leads by 5 again. A passed task costs 2.4× tokens on the original launch vs IntAct; 12.3× for chains and 7.9× for pairs on the appended launch; 4.0× on Claude Code's Bash launch. Production: 162/306 path-caused failures recovered by retry (2–8 steps), 30 abandoned, 114 not retried; each finally-successful call cost 3.9× the tokens of a clean request.
- Pattern pairs: the hazard variant passes 4–11/67 on the appended launch vs 38–46/67 on the control transport. Every empty-argument hazard fails on both PowerShell launches; every truncation hazard fails on Claude Code's Bash launch; 0/10 multi-line programs pass on the appended launch. False-confirmation rate 70.1% (665/949 failed runs reported completed).
- Instruction delivery: as a command-line argument, 33/46 instructions are cut at their first line break, 3 lose all double quotes, 5 exceed the cmd.exe limit; as a file, all 46 arrive as written. Argument delivery: every run scores 0; file delivery: Qwen Code passes 6/30 on Windows vs 7/30 on Linux.
- Fix task: 13/13 API LLMs pass `"test_app (v2) & more.py"` to pytest correctly, but the appended launch converts it into an AmpersandNotAllowed error — 45/45 runs fail the first command, 2–7 steps total, median 1.8× tokens. Commit task: the intended message is carried in 1/39 runs, 19 false confirmations.
- RQ3 attribution: the IEC protocol agrees with human labels at κ 0.77 (102 failures, 56 path-caused); the all-at-once judge attributes 97/102 to the LLM; Who&When judges reach κ ≤ 0.04. The IEC protocol calls no LLM; a Bash witness takes 0.1s per call. Action-change agreement κ 1.00 on 115 pairs; string comparison κ 0.65.
- Replay baselines: Causal Agent Replay rescues 12/67 shell-only lost pairs WITH a changed call vs 29/53 WITHOUT — a rescue does not indicate the path. QuoteBench's fixed-reply replay detects 37.2% of path-caused losses (51/137), every loss at the wrapper, none at the process interface.
- RQ4 repair: 168 fault injections (7 faults × 5 hops × 24 payloads): 30 change what the target receives, and the first divergence names the hop in 30/30 and in none of the other 138. IntAct restores every call of the first 4 hops and refuses the 13 at the target parser; requoting or encoding restores only a fraction. Repair replay: 137/173 lost pairs with a changed call pass once the named hop is repaired (79.2%; 68.6% one-argument → 90.9% Claude Code's Bash); 0/187 without a changed call pass (Fisher p<.001). Appended launch: process interface alone recovers 0/69, wrapper alone 31, both 69/81.
- Agent in the loop: IntAct raises pass@1 for every LLM on every launch. Pooled Qwen2.5: +20 pairs/−1 loss (one-argument), +81/−5 (appended); +30 chains vs −1 and +46 vs −1 (exact McNemar p<.001); +13/−2 on Claude Code's Bash (p=.007). Reflexion gains 11.4–55.0% of IntAct's gain at 463–1,180 retries per cell. Evidence ablation (call as sent + as received + named hop in the tool result): NOT significant (p≥.500) — evidence does not help the agent repair the path. Boundary-disclosed contract: Qwen2.5-Coder-32B chains commands with &&, which PowerShell 5.1 rejects → drops from 50 pairs to 36 while still reporting completion.

## Actionable Insights
- Audit a harness hop-by-hop, not end-to-end: each harness changes calls at its own hop (Claude Code at the host wrapper, PowerShell paths at the process interface, typing harnesses at the shell parse). Example: run 20 payloads (quotes, backslashes, line breaks, special characters) through an argv sentry for each harness before trusting its benchmark score.
- A benchmark must report its launch and hold it fixed: the same LLM's score swings by 29 chains purely due to transport (Qwen2.5-72B: 29 ahead with direct JSON, 2 behind on PS 5.1). Example: when evaluating a coding agent, always run both a control transport (Git Bash from file) and direct JSON to separate LLM quality from launch loss.
- When an agent retries a correct call and still fails, suspect the path, not the LLM: 80.7% of merged-backslash changes are silent (no error), and the agent receives "success" for a wrong action. Example: log the received text at the wrapper (BASH_ENV witness) for every Bash call with a backslash pair/heredoc/≥1,000 characters — if received ≠ sent, attribute to the path before blaming the model.
- Deliver multi-line/long commands via a file or an argument vector, not a command line: cmd.exe cuts at the first line break (30/31 multi-line commands run as an empty program), MSYS2 cuts quoted arguments at 8,186 UTF-16 units. Example: replace `powershell.exe -Command <text>` with a script file + `-File`, or `-EncodedCommand Base64(UTF16(text))`.

## Assumptions & Limitations
- Rendering domain limits: multi-line text under cmd.exe can only be refused; 2/36 unrecovered pairs use constructs outside the rendering domain.
- 12/36 unrecovered pairs were abandoned after misleading feedback — an agent-side issue IntAct does not fix (evidence in the tool result does not help, p≥.500).
- The changed-call rate is a lower bound: in 231/306 path-caused failures only the longer session wrapper changed the call, which the shortest-wrapper replay does not see.
- Measurement on Windows 11 + PowerShell 5.1 + Git for Windows and a Linux shared host; macOS/zsh measured separately (zsh silently changes 5 reference solutions).
- IEC-Bench hazard classes are rewritten with new literals (no session text released) — generalization to other literals is not directly tested.
- The repair replay needs a recorded run (calls + tool results) — it does not apply to live production traffic without recording.
