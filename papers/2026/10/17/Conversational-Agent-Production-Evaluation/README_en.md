# 2609.32092 — On Evaluating and Improving Conversational Agents in Production

## Problem
- Offline evaluation of production conversational agents faces three obstacles: (i) a logged conversation cannot be replayed against a modified system — a different response invalidates every turn that follows; (ii) the unchanged system itself varies run-to-run (LLM stochasticity + products, prices, and personalization signals change daily); (iii) aggregate quality scores (relevance, intent understanding) combine distinct behaviors — they show quality changed but not which behavior caused it, so they don't say how to correct it.

## Contribution
- A four-part framework: an Evaluation Harness (commissions a targeted evaluation: targeted assertions + a fixed cohort of customer scenarios), grounded user simulation (the simulator writes new customer turns conditioned on recorded messages/context, NOT replaying the log), an Improvement Orchestrator (assertion results → hypotheses → isolated modifications → paired percentile bootstrap comparison), and a human-gated self-revising harness (revision after the investigation, human-approved, applied only to future investigations, never altering recorded decisions).
- Applied in production: the Zalando Production Assistant, serving 20+ European markets with millions of conversations per month.

## Method
- System under test: two guards (in-house malicious-intent classifier pre-processing + general content moderation during generation) → LLM router → verticals (fashion agent, in-house: product search, beauty/kids, size/fit, cart, small talk — runs speculatively in parallel with the router; customer care service: language detection, case classification, RAG help-center, order/return/shipment queries; gift card deep link; sensitive-data refusal). Search action: query generation (1–3 queries + structured filters) → retrieve/rank/personalize → merge (dedup against shown products) → LLM curation (carousel of ≤8 items; shortfall filled from pre-curation ranking WITHOUT a further check). State: message history + structured search state + consent-gated customer memory (sizes, brands, materials, past interactions). Web-search sub-agents for out-of-catalog questions (moderated).
- Cohort: a pool of production conversations from a defined period (reconstruction needs customer messages + request context + products shown); sampling: random / embedding-based (farthest-point, nearest-neighbor, stratified, hybrid) / intent-based (10 intents, ~40 subtopics). Pseudonymized. The cohort is NOT a random sample — its failure rate describes the cohort and does not estimate production.
- Assertions: an LLM compiler translates the behavior description into pass/fail conditions stored in a versioned assertion library; human review before freezing; profiles evaluate the same requirement at increasing strictness (any / first / ≥75% / all products). Evidence fields are fixed before any modified version is evaluated.
- Simulation: conversation-grounded (first recorded message unchanged; subsequent messages serve as examples of how the customer communicates, NOT a script; bounded turn limit) or goal-based (goal description + context + turn limit). A separate simulator scorer rates goal pursuit, task adherence, interaction efficiency, and stopping behavior.
- Paired decision rule: ≥3 runs per version; paired difference per scenario (modified mean − baseline mean); 2,000 percentile bootstrap resamples with a fixed seed; interval entirely >0 → signal+, entirely <0 → signal-, containing 0 → noise (half-width ≤ threshold: 0.05 on the 0–1 scale, 0.25 on the 1–5 scale) or borderline. The scenario is the unit of analysis. Roles frozen at commission: target / guardrail / diagnostic. Advancement: target signal+ + no guardrail signal- + a second evaluation satisfying the same conditions → human review → possible online A/B test.
- Improvement Orchestrator: prefers diverse hypotheses over variations of the same local change; autonomy budget caps the number of modified versions; isolated modification on a clean local version; sequential evaluation; borderline → extend to 5 runs; stops at the first reproducible improvement (to avoid optimizing for the frozen cohort).

## Key Findings
- Investigation 1 (category): carousels containing products outside the requested category; 51 production conversations, 50 scored in every run, 3 runs per version. Baseline: any 0.913±0.012, first 0.833±0.023, ≥75% 0.733±0.076, all 0.640±0.040 (~1 carousel in 3 had an out-of-category product). Fix: the curation prompt's preference became a strict rule (a prompt instruction, not a code filter). Modified: 0.947/0.893/0.747/0.647 (∆ +0.033/+0.060/+0.013/+0.007) — the profile shows the effect on prominent positions, not the whole result set. Deployed.
- Investigation 2 (gender): gender-silent requests from a men's context returned women's products; 10 goal-based scenarios (9 men's gender-silent + 1 women's-context guardrail), 5 runs per version. h1 (tool description at the suspected component): first product 0.733→0.800, +0.067 [−0.022, +0.178] borderline. h2 (shopping context as a binding default in a different agent's system prompt): 0.733→1.000, +0.267 [+0.067, +0.511] signal+; task completion 4.27→4.96 (+0.22, signal+ — but a higher guardrail score is not by itself a reason to accept). h2 reproduced in three further runs; the guardrail passed in every run. Confirmed offline.
- Judge audits found three defects: (a) an assertion lacked the evidence it needed (relevant result information had not been added to the judge's evidence); (b) the judge temperature was set to zero but the client did not pass the setting to the model — configured but not applied; (c) a separate benchmark report used between-scenario differences where it should have measured across-run variation. All three produced plausible-looking output; (a) and (b) could have changed a decision.
- E-value post hoc check (Waudby-Smith–Ramaswamy betting): the h2 betting interval's lower end is 0.00–0.01 vs the bootstrap's 0.067 — h2 would have been borderline at nine scenarios; doubling to eighteen scenarios raises the lower end to 0.08 = signal+.
- Cost: a 3-turn session ≈ 4,000 tokens (simulated customer) + 13,000 (task-completion score) + 6,000 per assertion; the category investigation (300 sessions, 4 assertions) cost ~10M tokens. Judging dominates (input tokens).
- Production traffic (4 months of 2026): ~50% product searches, style advice/outfits second, product details third, ~10% orders. Attributes: category > color > brand > gender > size > material.

## Actionable Insights
- Evaluate behavior-specifically, not aggregate: commissioned assertions at several strictness levels (any/first/≥75%/all) produce a profile showing WHERE in the result a failure lives → the right hypothesis (the category fix was in the curation prompt, not retrieval).
- Compare paired per-scenario, DON'T pool all sessions: pooling counts scenario-difficulty variation as uncertainty and loses small improvements that hold in every scenario. Use ≥3 runs + percentile bootstrap intervals over scenario-level differences.
- Audit the judge as software: check (1) the judge has the evidence each assertion needs, (2) the configuration actually reaches the model (temperature=0 configured but not applied), (3) the statistics use the right variance source. Plausible-looking output can still be wrong.

## Assumptions & Limitations
- Offline results only — an offline improvement does not establish customer satisfaction or business outcomes; controlled A/B tests are required.
- The simulator was validated by reproducing reported failures and reading simulated conversations; how closely it matches real customer behavior across a wide range of intents/scenarios is unmeasured.
- The paired bootstrap treats the judge and production environment as fixed; judge models differed across investigations; recorded scores predate the temperature fix.
- No formal multiplicity correction — the hypothesis count is not fixed in advance (50 nulls at 0.05 → P(≥1 false signal+) > 0.9); safeguards (fix roles, second evaluation, cap hypotheses) lower but don't bound the risk; classical corrections (Bonferroni) don't fit — the paper proposes anytime-valid inference with e-values (Ville's inequality, 1939).
- The gender case has only 9 paired scenarios — limited power; percentile bootstrap under-covers at this size.
- Cohort failure rates don't estimate production frequency (the cohort was selected to show the failure).
