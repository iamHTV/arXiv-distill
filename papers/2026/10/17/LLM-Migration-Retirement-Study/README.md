# 2609.31288 — When the Model Retires: An Empirical Study of LLM Migration in Open-Source Applications

## Problem
- Apps built trên commercial LLM API phụ thuộc model versions mà provider retire theo schedule riêng (notice 1 năm → 2 tuần). Khácác library, retired model KHÔNG pin được: ngày shutdown mọi request fail. Model lifecycles rút ngắn 18–24 tháng → 6–12 tháng. 2026: largest deprecation notice (OpenAI single-day shutdown GPT-3.5 Turbo/GPT-4/GPT-4 Turbo/o1/o3-mini/o4-mini ngày 23-10-2026; Assistants API shutdown 26-08-2026 sau 1-year notice; Anthropic retire mọi Claude 3.x giữa 10/2025–4/2026 với 60–114-day notices; Google shutdown Gemini 2.0 Flash family 1-6-2026).
- Prior work: migration difficulty (case study, regression tooling, EOL framework, aggregate scores hide item-level regressions) — nhưng KHÔNG đo chuyện gì xảy ra across ecosystem khi retirement landing: bao nhiêu apps migrate trước deadline, bao nhiêu break, migration cost bao nhiêu code.

## Contribution
- Dataset: 22,555 unique commits (17,703 non-fork repos, 2024–2026; TypeScript 28%, Python 27%, JavaScript 6%) matched tới event table biên soạn từ deprecation pages của 3 providers (30 OpenAI, 9 Anthropic, 7 Google entries) → 5,139 matched commits (4,544 repos), 3,933 concern events đã shutdown (timing analyses).
- First ecosystem-scale measurement of reactive (post-shutdown) vs proactive migration: 82% (95% CI 79–84) migrations committed SAU shutdown — sau khi app đã fail — reweighted by human-validated genuine rate (2 coders, stratified sample 300, κ=0.89–0.95; chỉ 62% matched commits genuine; genuine rate 24–80% pre vs 48–86% post → reweight theo stratum).
- Dose–response notice policy: 89% reactive (Anthropic 60–114-day notices) vs 13% (OpenAI 1-year Assistants API); logistic regression log(notice days): coefficient −1.36 (reweighted) — mỗi e-fold increase notice giảm odds post-shutdown migration ~74–78% (raw −1.52; Google soft-notice assumption −0.95). Event-level Spearman ρ=−0.53 (p=0.06, n=13).
- Keyword-and-manual taxonomy breakage (4 forms) + evidence migration size và architectural adaptation.

## Method
- GitHub commit-search API, 22 query strings (retired model identifiers/endpoint names + migration vocabulary: deprecated, retired, migrate, shutdown, model not found), quarterly windows (2024–mid 2025) + monthly (mid 2025–Sep 2026), 200–300 results/window. Forks excluded, SHA-dedup. GraphQL metadata (stars, forks, archived, language) 22,513 commits; REST file paths + patch hunks 3,933 retired-event commits (3,931 retrievable).
- Matching: most specific model/endpoint pattern với word boundaries (short ids như o1 cần delimiters 2 bên); require migration verb (migrate, replace, switch, upgrade, update, remove, drop, swap, retire, deprecate, sunset, shut down); exclude commits >30 days before announcement, AI-tool authorship headers embedding model id, dependency-bot commits; exclude commits mà retired identifier là destination of arrow hoặc destination là older model (migrations INTO model) — removed 33% candidates, concentrated in Google events.
- Timing: reactive = committed after shutdown date. Dose–response chỉ dùng events retired ≥28 days before collection, commits trong [−365, +180] days của shutdown (right-censoring control).
- Keyword classifiers: breakage (404, not found, fail, broke, error, crash), silent failure, pinned snapshots, abstraction layers (LiteLLM, OpenRouter, LangChain, router, gateway, fallback, provider-agnostic), evaluation, prompt/parameter changes, cost. Keyword rule performance vs human labels: breakage precision 0.81/recall 0.92; silent failure 0.57/0.57; abstraction 0.70/0.42; pinned snapshot 0.25/0.83 (không report pinned rate).

## Key Findings
- RQ1: 72% raw post-shutdown; 82% reweighted (CI 79–84). Median migration 39 days sau shutdown, 158 days sau announcement. Trong genuine post-shutdown migrations: 40% production repairs, 45% planned changes (không mention breakage), 14% catalogue cleanup (soft shutdowns, apps không active use). Popularity KHÔNG liên quan timing: raw 72% (0-star), 71% (1–9), 71% (10–99), 74% (100+); reweighted 82/80/81/82 — star count không phải proxy cho retirement readiness (cả sau khi loại catalogue-like projects, 16% commits). Reactive fixes chậm: 9% trong 1 tuần, 27% trong 1 tháng, 55% trong 3 tháng — retired model để app broken hàng tuần. Short-notice retirements thành wave: tuần sau Claude 3.5 Haiku/3 Haiku/Opus 4.1 shutdowns mỗi cái 25× weekly volume của 8 tuần trước, vs 2.1× Assistants API, 1.3× Gemini 2.0 Flash.
- RQ2: Reweighted reactive Anthropic 89% (CI 88–91) vs OpenAI 66% (59–73) vs Google 64% (52–78). Event level: 60–76-day Anthropic retirements 86–98% reactive; 1-year Assistants API 13%. Regression: −1.52 raw / −1.36 reweighted (SE 0.09, p<0.001) — mỗi e-fold notice giảm odds ~74–78%. Gemini 2.0 Flash natural experiment (date moved 31-3 → 1-6-2026): KHÔNG discontinuity — migrations trickle 23–29/tuần từ Feb–Jul, dip nhẹ 28.5→23.5/tuần trong 4 tuần sau postponement, KHÔNG spike sau actual shutdown — soft movable date không tạo deadline effect trước shutdown lẫn breakage wave sau (25-fold spikes của Anthropic firm 60-day retirements là đối chứng). Claude Sonnet 4 (62-day notice, 79% reactive): short notice trên current-generation model reaction nhanh hơn nhưng vẫn 4/5 migrate sau sự thật.
- RQ3: Keyword 41% matched commits mô tả breakage (48% post-shutdown, 29% pre). Human-validated genuine migrations: breakage 63% post-shutdown Anthropic, 29% Google, 19% OpenAI (pre: 42%/33%/4%). 4 forms: (1) hard failure — endpoint 404/not found, feature stops ("every outreach draft 404'd after discovery succeeded"); (2) silent failure (8% genuine migrations, 14/180) — exception handlers convert retired-model error thành apologetic chat message, null result, demo-mode fallback, hoặc constant answer ("breed identification always returned 'Golden Retriever'"); "AI analysis had been failing silently in production" hàng tuần sau Gemini 2.0 Flash shutdown; (3) parameter incompatibility (7.5% commits) — replacement model rejects max tokens hoặc non-default temperature, rename alone không restore service; (4) pinned snapshots — dated identifiers (claude-3-5-sonnet-20241022) proximate cause trong 6/118 agreed genuine migrations (keyword rule overstate order of magnitude → present but uncommon).
- RQ4: Median 2 changed files (P75 5), 14 added + 6 deleted lines. 94% migrations edit source — model identifier hard-coded (chỉ 6% config/docs alone; reweighted 6.4%; human-validated 1.7% config-only → hard-coding còn cao hơn trong true migrations). Identifier đổi median 1 file; 26% ≥3 files; 16% touch test file (12% prompt-only). Architecture: 78% prompt-only, 13% tool/agent, 8% retrieval, 2% fine-tuning. Effort scales: prompt-only 2 files/6 lines; agent 5 files/63 lines; RAG 7 files/155 lines; fine-tuned 14 files/693 lines (replacement base model invalidates tuned checkpoint). Human-validated: prompt-only 2 files/7 lines; agent/RAG/fine-tuned 8–9 files/224–411 lines. Reactive shares 58–74% across architectures — heavier apps KHÔNG proactive hơn, chỉ pay hơn.
- Abstraction layers rare + mostly retrofitted: chỉ 3% migrations trong code đã route qua abstraction (LiteLLM/OpenRouter/gateway/model map; 7% human-validated) — smallest non-trivial (4 files, 20 lines) nhưng KHÔNG less reactive (70%). 4% introduce layer during migration (largest non-fine-tuning: 6 files, 164 lines). 93% simply rename identifier in place. Retirement triggers architectural hedging 1/25 migrations; pre-existing layer giảm fix size KHÔNG làm nó timely.
- RQ5: 20% commit messages mention abstraction/gateway/fallback nhưng chỉ 4% thực sự add; 8% modify prompts; 13% mention cost; 4.5% mention evaluation/regression suite; 11% add assertion/evaluation line trong patch. Retirement triggers far more renaming than measurement — apps switch model KHÔNG có harness reveal item-level regressions. 43% commits có AI coding-assistant co-author trailer (report without interpretation).
- RQ6: 2,236/3,933 name destination; chỉ 8% switch provider (7% reweighted, 8% human-validated); 68–74% stay với provider (Claude 3.5 Sonnet → Sonnet 4.6 hoặc Haiku 4.5; GPT-4 Turbo Preview → GPT-4o); 16% add second provider alongside (hedging, không switching). Switch rate giống nhau reactive (7%) vs proactive (13%), breakage hay không (7% cả hai) — being burned KHÔNG drive apps away. KHÔNG learning: 85 repos hit ≥2 retirements, post-shutdown share 73% first event vs 73% later (CI difference −13 to +13pp), dù later migrations land sooner (median 22 vs 45 days). Retirement KHÔNG phải churn event — nó là forced upgrade funnel.

## Actionable Insights
- Externalize model identifier (env var/registry): 94% migrations edit source vì identifier hard-coded — indirection biến majority migrations thành one-line change. Ví dụ: coding app dùng `MODEL_ID` env var + model registry map → retire event chỉ cần đổi 1 dòng config, không phải sửa 94% codebase.
- Static deprecation check trong CI: flag model identifiers against providers' deprecation tables, CI failure TRƯỚC shutdown date — would have prevented most post-shutdown commits in corpus. Ví dụ: nightly job query OpenAI/Anthropic/Google deprecation pages, fail CI nếu codebase chứa identifier nằm trong danh sách retire <90 days.
- Notice length là lever duy nhất predict được proactive migration (dose-response −74–78% odds per e-fold): 60-day notice → 86–98% reactive; 1-year notice → 13%. Ví dụ: với provider chỉ cho 60-day notice (Anthropic-style), đặt internal migration deadline tại announcement + 30 ngày, không phải shutdown − 7 ngày.
- Migration playbook theo architecture: prompt-only 2 files/6 lines, agent 5 files/63 lines, RAG 7 files/155 lines, fine-tuned 14 files/693 lines (checkpoint invalidated). Ví dụ: trước khi adopt fine-tuned model, budget cho migration effort ~700 lines + retrain — retirement cost vượt deployment cost.
- Pre-existing abstraction layer KHÔNG đảm bảo timely (70% still reactive) — chỉ giảm fix size (4 files/20 lines). "We support multiple providers" và "we survived previous retirement" KHÔNG phải evidence of resilience (73%→73%). Ví dụ: don't rely on LiteLLM alone — cần retirement watch + migration drill định kỳ.
- Beware silent failure modes (8% migrations): exception handlers convert retirement error thành apologetic message/null/demo-mode/constant answer — app "hoạt động" nhưng sai. Ví dụ: monitoring alert trên rate của fallback/demo-mode responses, không chỉ error rate.

## Assumptions & Limitations
- Recall: chỉ observe migrations mà commit message names retired identifier; silent migrations và abandoned projects under-represented (archived <1%, abandonment without archiving common).
- Precision: 38% matched commits non-genuine (2-coder judgement), concentrated pre-shutdown và Google events → headline shares reweighted by stratum genuine rates; file-level/destination analyses report cả reweighted lẫn human-validated subset (agree within few pp).
- Search caps: GitHub commit search ≤1,000 results/query, windows retain first 200–300 → counts are lower bounds, popular months truncated; 12 random windows re-run: Jaccard 1.0 cho 9 uncapped, strict subsets cho 3 capped; Gemini 2.0 Flash (dominates Google sample) most truncated.
- Right censoring: recently retired events excluded from dose–response (retired ≥28 days before collection).
- Google excluded khỏi notice-length regression (announcement date not archived); sensitivity analysis với soft-notice assumption (GA 365-day, preview 14-day) cho weaker −0.95.
- Pinned-snapshot κ=0.62 (moderate) → report only as lower bound; keyword rule overstates order of magnitude → pinned rate not reported.
- 300-commit validation sample stratified on outcome → cannot re-estimate regression directly.
