# 2610.21267 — TRACER: Trajectory-Aware Tool Retrieval for LLM Agents

## Problem
- Agents select tools from large registries: exposing the entire registry incurs high token cost and impairs selection as registries grow (long, detailed inputs make relevant information harder to use reliably). Description-based retrieval confuses semantically similar tools; retrieval errors propagate to downstream execution.
- Core gap: each step is treated as independent search, when tool retrieval is really sequential prediction — which call comes next, given those already made. A τ² retail request resolves in a logical order: identify customer → pull account → open order → act on it. The calls already made constrain the next one.

## Contribution
- TRACER (Trie Retrieval Across Contextual Edges, Reweighted): a state-conditioned retrieval front-end with three ideas: (1) full-prefix conditioning (execution trie over observed tool-call sequences; the agent's prefix within a turn is a node; tools seen after it are candidates), (2) transition-specific usage memory (each edge stores the conversations in which that transition was taken), (3) state-dependent weighting (a learned per-step blend of empirical and contextual priors).
- A small candidate set (k ≪ |R|) at each step while still leaving the final choice to the model. Beats full-registry selection in 21 of 24 model-environment pairs, average +6–10 points, cutting per-step tokens by 55–90%.

## Method
- Trie construction: insert every prefix of every trajectory as a node; children C(Si) are the tools observed immediately after Si; each edge carries P_trie(t|Si) (empirical prior — normalized transition frequency, log + smoothing ε) and edge memory m(Si→t) (mean-pooled embedding of the training contexts in which the transition was taken). The trie is turn-local (resets at turn boundaries); the edge memory is NOT turn-local (embeds the full conversation, so cross-turn information reaches the retriever without entering the trie as structure).
- Contextual prior: embed the step context (all previous turns + step reasonings, tool-call signatures dropped to limit length) with a frozen embedder e; R(t) = cos(e(ctx(q,Si)), m(Si→t)); ReLU-normalize into a distribution over children (uniform if all similarities ≤0); L(t) = log(R̂(t)).
- Learned scoring: s(t) = (1/T)[(1−w)L(t) + wP(t)], top k presented. w and T come from a learned map fθ(x)=(w,T) over a five-dimensional state feature vector per step (two linear heads: logistic head for w — keeps the blend convex; floored softplus head for T — keeps temperature positive). Fit θ with Adam + ℓ2, minimizing NLL of the gold next call under a softmax over C(Si), with inner-fold isolation (each step is scored against a trie and edge memory built without its own trajectory).
- Confidence gate + OOD fallback: unseen state (C(Si)=∅) or flat score distribution (κ<τ, τ=0.20) → global vector search over the full registry (cosine of embedded step context to tool descriptions), replacing trie candidates entirely.
- TRACER+G: for registries concentrated in generic utility tools, union a global set G (|G|=3 tools with the highest prefix entropy H(S|t)) into every candidate set. TRACER-fixed ablation: fixed blend s(t)=L(t)+P(t).
- Benchmarks: Mixed Tau2 R&T (retail+telecom, 128 deliberately confusable tools; real τ²-bench trajectories + vetted synthetic ones from a co-occurrence graph; 99.8% retail / 99.9% telecom clear the non-cloning gate; blind human study: 67.8% picked the synthetic as human-authored), Tau3 Banking (~700 interconnected documents, compliance gating via unlock:X), BFCL v3 (weakly-related API families), API-Bank (homogeneous reference). Four models: GPT-5.4, GPT-5.4-mini, Grok-4-20-reasoning, Mistral-Large-3; embedder text-embedding-3-small; 5-fold CV; teacher-forcing (primary — measures the front-end in isolation) and free-running (errors compound; 20-step cap; grader scores by database hash + required read operations).

## Key Findings
- Teacher-forcing, Mixed Tau2 Large, k=5: GPT-5.4 TRACER 61.9% vs LLM-ONLY 57.2% (+4.7) vs VECTOR 27.7%; CIC 2.8k vs 14.2k prompt tokens per step (−80%). Gains exceed 1 SD in 31 of 34 winning cells. Grok trails by 0.3 (within that cell's 3.8-point SD).
- 21 of 24 model-environment pairs improve over full-registry (average +6–10 points); the 3 exceptions trail by at most 2.2. CIC reduction grows 55%→80% as the Mixed Tau2 pool grows; from 31% (Tau3 Banking — long conversation histories dominate the prompt) to 90% (BFCL v3).
- Free-running: GPT-5.4 reaches parity — Large +0.1 points at 23% of the registry, Medium +1.2 at 33%, Small +2.3 at 43%; GPT-5.4-mini gains +13.7→+15.2 on Large (from 3.9% of the registry upward). Full turn: task success 58.3% vs 58.2% (match), 23% of tools, −61% per-step input tokens. 16 of 24 cells within 3 points (median 2.2); GPT-5.4 is below LLM-ONLY at 8 of its 12 budgets (a single early miss → unseen prefix → vector fallback).
- Specificity trap: LLM-ONLY falls back on the generic hub get_order_details on 36.4% of steps where one of five order-management APIs is correct (split_order_shipment 14%, add_gift_message 32%, request_return_pickup 16%, schedule_installation 29%, file_shipping_insurance_claim 49%); TRACER cuts the trap rate to 16.4%. Example: a prepaid return label — LLM-ONLY invoked the destructive return_delivered_order_items, while TRACER ranked that tool 9th on the contextual prior, so the model correctly chose get_return_label.
- Procedural controls: banking requires unlock:X before a write — the trie withholds the raw write (no successful trajectory reaches open_bank_account without passing unlock); LLM-ONLY skips the unlock step.
- Ablations: description-only Trie-Bayesian scores 21 points lower than TRACER-fixed (API-Bank, GPT-5.4-mini) — the contextual prior is the key mover; learned vs constant blend: +8.0/+5.9/+6.0/+7.6 (Mixed Tau2), +3.9/+3.5/+7.1/+5.8 (BFCL), only +0.6–1.1 (Tau3 — generic tools dominate); w averages 0.019 (contextual prior dominant), rising early in the conversation and where the empirical prior is confident; last-2 trie +1.5–2.9 (within SD), 9.6% out-of-trie vs 12.4% for the full prefix.
- TRACER+G: +5.8 points on Tau3 Banking (generic KB_search/grep dominate); hurts τ² mixes and BFCL v3 (adds distractors).

## Actionable Insights
- Don't expose the whole registry: 5 of 128 tools (k=5) beats full-registry selection by +4.7 points with −80% tokens — a smaller candidate set improves the model's own selection accuracy, not just cost.
- Index execution history as a trie (prefix → candidates) instead of query→tool similarity: prefix conditioning separates "same tool, different purpose at a different step" (specificity trap 36.4%→16.4%) and enforces procedural ordering (unlock before write) for free.
- Blend the two signals per state, don't fix them globally: the learned blend is worth +0.6–8.0 points depending on benchmark; the contextual prior (the conversations each transition was taken in) matters more than the empirical prior on diverse tries (w≈0.02) — edge memory is not droppable (−21 points with description-only).

## Assumptions & Limitations
- Cold start: requires a dataset of graded trajectories — a registry with no usage history has no trie, so every step falls to the vector fallback (accuracy 38 points below); the method assumes a deployment that already logs successful runs. How quickly a trie becomes useful is unmeasured with fixed-size corpora.
- Free-running regressions: a single early miss moves the turn onto an unseen prefix → vector fallback (out-of-trie rate ~3× teacher-forcing); prefix-independent lookups (no prefix predicts them) are the weakest point — the paper proposes presenting the full registry ONLY on out-of-trie steps in future work (+38 points average on those steps, retaining 84% of the token reduction).
- Premise: every tool is available at every step (edge counts reflect what the agent chose, not what was offered) — does not apply to permission-gated registries.
- Trie key depth is fixed (full current-turn prefix); a last-2 trie performs nearly identically (within SD). Budget k and global set G are fixed — should adapt per domain/model (future work).
- Mixed Tau2 includes synthetic trajectories (validated: 67.8% blind human study).
