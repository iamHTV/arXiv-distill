### [1] Context Is a Pipeline, Not a Window: Information Attrition in LLM Agent Harnesses (2610.36114v1)
- What it does: Measures WHERE information is lost on the path from a tool producing results to the model reading them, modeling it as a 5-stage pipeline. Finds that the agent harness truncates tool output by character position (prefix slice), so evidence at the end of a payload is deleted entirely.
- What we learned: 34% of tool results (3,827/11,189) are truncated before reaching the model; the second field in the same payload reached the model in only 4.7% of calls while the first field reached 99.3%; resident-container faults were diagnosed correctly only 0-24/60 times. The context window was only 5.75% used (23k/400k tokens) — not a capacity problem, a truncation problem. When the agent has an alternative path to the answer, truncation doesn't immediately cause wrong answers but wastes work: tool calls +43%, yield drops 0.61 → 0.31.
- Apply it: When building agents (e.g., price comparison across marketplaces), don't let middleware truncate tool output by leading characters. First step: replay the same query with raw vs truncated output and count which evidence reaches the model; switch to structure-aware cutting (by line or JSON field) and force a "MISSING" label instead of guessing.

### [2] Do We Need an LLM to Know Why Sources Conflict? Decision Models for Knowledge-Conflict Typing in RAG (2610.36915v1)
- What it does: Compares 11 decision models (typed models returning probabilities over fixed answers in one forward pass, no text generation) against LLMs at classifying WHY sources conflict (5 types: no conflict, complementary info, conflicting opinions, outdated info, misinformation) on the CONFLICTS benchmark (458 queries).
- What we learned: 10/11 decision models matched or beat the LLM (Gemini 2.5 Flash: 61.3%; decision models: 50.0-67.0%, median 62.6%) while being 4-39× cheaper ($0.04-0.41 vs $1.66 per 1,000 queries) and 2.6-6.0× faster (0.26-0.72s vs 1.55s). Their confidence ranks their errors (AUROC 0.64-0.76), so escalating the least-confident 25% of queries to a stronger LLM (Gemini 3.8 Flash) matches the single-LLM pipeline at 25-37% of the cost. Direct flat choice questions beat decomposing into yes/no questions.
- Apply it: For a RAG chatbot (AI answering from retrieved web pages), add a cheap conflict-typing step before generating: label the conflict type (outdated → take newest; opinions → show both sides; unreliable → prefer official sources) and only escalate uncertain queries to the expensive LLM. First step: require the output of your product/price-comparison bot to include a "conflict type" column before any conclusion.

### [3] Grounding LLM Agents in Business Processes: Process-Aware Knowledge Graphs (2610.37242v1)
- What it does: Builds a typed property graph combining OData service metadata (service data description) with BPMN 2.0 process diagrams (business task ordering) so agents make correct multi-step enterprise API calls — right order, required keys, valid codes — not just the right endpoint. Benchmark OData-Proc: 42 services, 14 processes, 288 queries.
- What we learned: A ReAct (reason+act interleaved) agent with full typed context completed 38.7% of tasks vs 10.3% for chunk-RAG. Hybrid retrieval (dense embedding seeds + expansion along process edges) Recall@3 0.810 vs 0.787 dense-only; on process-chain probes 0.732 vs 0.675. Invalid API calls: 0.03 (3/101 POSTs) vs 0.79 for chunk-RAG (100/127, incl. 60 invented codes) — pasting valid-code lists as plain text stopped invented codes but still left 0.46 invalid calls. Benefits exist only with a process layer: on a benchmark without BPMN, both methods tie.
- Apply it: For agents automating business workflows (booking, accounting, CRM — customer relationship management), supply call order, required keys, cardinality (1:N ratios), and valid code lists in the retrieval context, not just an API list. First step: map your business API call chains into a simple ordering diagram and embed it in the agent's knowledge base.

### [4] LM-DSB: Lightweight Multi-agent System for Daily Safety Bulletin Generation in Construction (2610.36433v1)
- What it does: A lightweight multi-agent system (planner-researcher-writer, strictly sequential) running local Llama 3-8B on consumer hardware to generate daily safety bulletins (DSBs) for construction sites, grounded in 37 HSE (health, safety, environment) documents via RAG + LoRA fine-tuning (Low-Rank Adaptation).
- What we learned: Document completeness (length ratio — output vs ground-truth length) hit 1.01 (fully complete, matching expert-written documents) while single-agent RAG reached only 0.39 (~1/3 of content). Metrics: TF-IDF 0.696, BLEU 0.39, ROUGE-1 0.657, ROUGE-2 0.409 vs single-agent RAG 0.629/0.273/0.480/0.378. Expert evaluation (N=40, 5-point Likert): regulatory compliance 4.20, factual accuracy 4.10, actionability lowest at 3.50. Surprise: fine-tuning alone without RAG scored BELOW the untouched baseline on all 4 metrics (TF-IDF 0.422 vs 0.487).
- Apply it: To generate recurring reports/bulletins from proprietary documents without API fees: split into 3 specialized agents (outline → evidence → writing) run sequentially, ground with RAG first, fine-tune only for domain terminology fluency, on a 12-16GB VRAM GPU. First step: write a JSON schema listing your document's standard sections; measure completeness (length ratio), not just word overlap.

### [5] Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness (2610.37657v1)
- What it does: A prompt-injection defense that trains one gate table per attention head — 46,080 parameters, 0.00007% of Llama-3.3-70B's weights — so each head learns to reduce attention to untrusted tokens (tool outputs, web content) while still reading them.
- What we learned: Against RL-Hammer (black-box reinforcement-learning attack): attack success rate (ASR) 97% → 10% on GPT-OSS-20B, 99% → 1% on Llama-3.3-70B; even more robust than GPT-5.6-Luna (attacker reached 36% on Luna). White-box attacks (Claudini, optimized specifically against HoS) need 2.6-3.6× more compute to reach 50% ASR. Utility nearly intact: MMLU-Pro 5-shot 67.2% vs 68.3% base, while SecAlign (DPO — Direct Preference Optimization fine-tuning) collapses to 59.4%, ASIDE to 52.1%, SecAlign's GSM8K 1-shot to 2.0%. On AgentDojo: ASR 23.1% → 0.9% while utility-under-attack improves +16.2 points. Cost: HoS 46K params vs SecAlign 349M, ASIDE 70B.
- Apply it: If your agent reads emails/web/tool output with an open-weight model: tag token trust channels (TRUSTED/UNTRUSTED/TEMPLATE) before feeding the model, then train gate tables (code + models public: imperial-aisp/heads_of_security). First step: write middleware that tags channels by data source — the single point of failure to guard.

## WHAT YOU CAN APPLY TODAY
1. **Measure attrition in the pipeline, not just correctness**: 34% of tool outputs are truncated before the AI reads them while the context window is 94% empty. Today: audit the truncation middleware in your agent; switch from character-prefix cuts to structure-aware cuts.
2. **Classify first, generate later, cascade when uncertain**: cheap decision models classify source conflicts (4-39× cheaper, 2.6-6.0× faster) + escalate the least-confident 25% to a strong LLM → same quality at 25-37% of LLM cost. Apply to any customer-facing RAG bot.
3. **Enterprise API agents need process order + schema, not just endpoints**: invalid API calls drop from 0.79 to 0.03 when retrieval context includes call order, required keys, and valid code lists.
4. **Small model + specialized agents beats a single big model**: the sequential planner-researcher-writer pipeline on Llama 3-8B hit completeness 1.01 vs 0.39 single-agent — and NEVER fine-tune alone (fine-tuning without RAG performs worse than the baseline).
5. **Prompt-injection defense without full fine-tuning**: 46K attention-gate parameters, ASR 99% → 1%, utility preserved; full-model fine-tuning (SecAlign pattern) on narrow data instead collapses few-shot performance (16.1% MMLU-Pro).
