## CÓ GÌ ÁP DỤNG ĐƯỢC CHO BẠN

Dưới đây là những insight từ 10 bài hôm nay mà bạn — làm solopreneur content/AI tại Việt Nam — có thể **áp dụng ngay** mà không cần reproduce paper:

- Scale review effort theo PR complexity: PR nhỏ homogeneous → config rẻ; PR lớn heterogeneous → model mạnh + reasoning cao + human review; tách unrelated change thành PR nhỏ.
- Steer agent bằng custom instruction theo priority (usability, portability, backward compatibility, maintainability) — default agent focus vào severe functional bug.
- Feed repository knowledge cho agent khi review proprietary/large repo — bug cần project context là nơi agent yếu nhất (-25.5%).
- Định nghĩa control theo protected action/asset, KHÔNG theo interface: cùng secret/file/shell/plugin/browser/network boundary áp dụng cho mọi route (CLI, API, MCP, browser, headless, batch) — vì 96.8% projects có inconsistent control across overlapping paths.
- Thêm failure-oriented test/replay case cho mỗi high-authority route: test phải FAIL khi bỏ approval/sandbox/policy/redaction/domain-scope/extension check — vì 97.8% repos thiếu prompt-injection/adversarial tests và 52.4% thiếu red-team-like paths.
- Audit theo 8 risk-chain templates (secret-to-tool, workspace-to-persistent-state, extension-to-authority, mode-switch-to-privilege, runtime-code, model-to-process, session-to-action, untrusted-context-to-action): mỗi chain đặt tên trigger, protected asset, required control, regression check.
- Gate trước khi chạy tác vụ tốn kém: một bước review ngữ nghĩa pre-execution bắt 1 lỗi DDP = tiết kiệm cả chục giờ GPU — với workflow automation, luôn validate plan trước khi execute tốn cost.
- Chỉ can thiệp khi tắc: critic bắn mỗi iteration sinh noise; bắn trên plateau (8%/5 iteration) mới tạo paradigm shift — áp dụng cho content pipeline: trigger review chiến lược chỉ khi KPI đi ngang 5 chu kỳ.
- Bộ nhớ thất bại phải bền: ghi negative result vào storage cross-job ngày đầu — agent vẫn re-test 100-epoch 6 lần dù program.md đã cấm.
- Đừng giữ toàn bộ discovered tools: QF+ULF nén 1,283→87 APIs (−93%) với near-unchanged correctness (60.4→59.9 without fallback) — redundancy trong tool collections là real cost, không phải insurance.
- Dùng fallback-aware filter ordering: ULF một mình làm correctness −9.7pp (50.2%) vì bỏ "ít dùng nhưng essential" APIs — luôn giữ highest-score API mỗi semantic cluster (score ≥3) để preserve coverage, và dùng ReAct fallback bù đắp phần còn lại.
- Adapt tool inventory online theo actual usage: DR chọn 33 APIs (từ pool 87) match runtime distribution — 90.6% correctness với −57.8% token cost; asymmetric policy (add nhanh khi gap, prune sau 50-task inactivity) tránh churn.
- Đừng hỏi "rewrite nào thắng" — hỏi "method nào fail trên query khác nhau". Thêm S3/S4 (modest solo) vào S1+HyDE+Q2D vẫn lift Enterprise 50.00→51.70/52.98 — solo performance KHÔNG predict ensemble value.

- Invest in detector + router, không phải feedback generator: nơi environment trả hard failure signal, majority gain đến từ noticing failure + spending bounded retry budget; marginal call biến error thành eloquent guidance chỉ mua 1 point exact match. Ví dụ: Text-to-Cypher agent — EXPLAIN pre-validation + LIMIT 1 empty detection + 2-cycle budget + raw error string retry = 91.7% recovery mà KHÔNG cần LLM-synthesised hints module.
- First-time success phải cost đúng 1 call: short-circuit validation (0 calls khi both checks pass) để overhead chỉ rơi lên minority queries fail (53–97% need no correction). Ví dụ: pipeline agent — validate statically trước, chỉ call model khi fail, mean 1.1–2.5 calls/query thay vì fixed multi-call.
- KHÔNG dùng parallel sampling thay sequential correction trong low-entropy output spaces (structured queries có ít correct forms): Best-of-3 degrade 10.8–11.4%, temperature T=0.7 làm hit rate FALLS (87.6%→85.2%). Ví dụ: budget cho query agent → sequential retry với error feedback, KHÔNG k=3 sampling.
- Đo failure bằng ledger structured (record arguments verbatim + refusal codes + verdict), không phải process exit — production ledger chỉ record refusal code, arguments vô hình 10 ngày; capture chúng exposed 5 server defects.
- Repair server-side trước khi blame model: 5 changes không đụng model/prompt/sampling đã move 6 models 6–21 cells/30 — transport failure là mechanical shapes, sửa được bằng reader nhận diện call theo naming chứ không strict JSON parse.
- Control confound memory trước khi kết luận "model yếu": cap serving context (12B model, 262k-token window, 51GB RAM trên 64GB machine → planning cell 0/5; cap 32k → 5/5); watch swap growth, không phải free memory.
- Monitor document novelty (fraction new docs per iteration) như early-warning stagnation — signal cao nhất correlation với productive iteration (AUROC 0.81); novelty ≈ 0 nghĩa là agent đang lặp, nên intervene hoặc stop.
- Critical re-thinker pattern: khi trajectory stale nhưng recoverable, inject 1 external nudge (đánh giá why stagnating + creative different query) thay vì để agent tự lặp — intervention win gấp ~2× loss.
- Coverage signal chỉ dùng khi có human-defined criteria; nếu criteria do LLM generate, bỏ Cov (hại trên 2/3 datasets) — đừng giả định multi-signal luôn tốt hơn.
- Externalize model identifier (env var/registry): 94% migrations edit source vì identifier hard-coded — indirection biến majority migrations thành one-line change. Ví dụ: coding app dùng `MODEL_ID` env var + model registry map → retire event chỉ cần đổi 1 dòng config, không phải sửa 94% codebase.
- Static deprecation check trong CI: flag model identifiers against providers' deprecation tables, CI failure TRƯỚC shutdown date — would have prevented most post-shutdown commits in corpus. Ví dụ: nightly job query OpenAI/Anthropic/Google deprecation pages, fail CI nếu codebase chứa identifier nằm trong danh sách retire <90 days.
- Notice length là lever duy nhất predict được proactive migration (dose-response −74–78% odds per e-fold): 60-day notice → 86–98% reactive; 1-year notice → 13%. Ví dụ: với provider chỉ cho 60-day notice (Anthropic-style), đặt internal migration deadline tại announcement + 30 ngày, không phải shutdown − 7 ngày.
