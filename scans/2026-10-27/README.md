### [1] Towards Mitigating Fabricated Consensus: The Active Provenance Gate (arXiv 2609.31422)
- Làm gì: Multi-agent debate (MAD — tranh luận đa tác nhân) thường kết thúc bằng "đồng thuận giả tạo" (các agent đồng ý với nhau nhưng kết luận vô căn cứ). Paper đặt một Active Provenance Gate (cổng kiểm soát nguồn gốc chủ động): mỗi kết luận tổng hợp phải truy xuất được đến bằng chứng/tác nhân/bước cụ thể, nếu provenance (nguồn gốc, khả năng truy vết) dưới threshold thì bị chặn, không cho vào kết luận cuối. Khác prior work: PROV/PROV-AGENT chỉ coi nhật ký tranh luận như artifact (đối tượng) thụ động để kiểm tra sau; self-refine (tự sửa lỗi) không ép ràng buộc cứng.
- Học được gì: Trên testbed 90 trajectories, provenance-free baseline đạt provenance fraction (tỷ lệ kết luận có nguồn gốc) 0,288 (terminal)/0,183 (REST), APG đạt 0,617/0,586. Cấu hình: ngưỡng provenance ≥0,95 + self-healing (tự chữa) tối đa 3 retry + Divergence Report (báo cáo khác biệt) khi agents không đồng thuận. User study N=33: 75,8% người dùng tin report divergence hơn bản câu trả lời bịa (p=0,0039). Symmetric-validator (validator y hệt proposer) thất bại 85,6% → validator phải MẠNH HƠN và KHÁC proposer.
- Áp dụng cho bạn: Khi nhờ 2–3 AI agent "hội đồng" quyết định (chọn giá, chọn kênh đăng content), đừng lấy majority vote mù quáng. Thêm rule: mỗi kết luận phải kèm bằng chứng cụ thể (số liệu, link); nếu bằng chứng không khớp → xuất "báo cáo khác biệt" thay vì gộp câu trả lời. Validator (người/agent kiểm tra) phải khác người đề xuất.

### [2] Poisoning Agentic Alpha: Adversarial Vulnerabilities Across Multi-Agent Trading Frameworks (arXiv 2608.24069)
- Làm gì: Đo lỗ hổng adversarial (tấn công đối nghịch) trên các hệ thống agent giao dịch đa tác nhân: jailbreak (vượt rào an toàn) Risk Manager, persuasive (thuyết phục) attack, data poisoning (nhiễm độc dữ liệu), objective hijacking (chiếm mục tiêu). Backtest thật: 5 tài sản × 2 backbone × 61 ngày.
- Học được gì: Jailbreak Risk Manager đạt attack success rate — ASR (tỷ lệ tấn công thành công) 98,9%/95,5%; persuasive attack 41,9–53,3% (p<0,005); poison 10%→80% dữ liệu đẩy ASR 19,1%→30,6%. Thứ tự defense-in-depth (phòng thủ nhiều lớp): Decentralized ASR 0,00 < Hybrid 0,33 < Linear 0,50 < Centralized 1,00 (tương quan r=0,85/0,88 — càng tập trung càng dễ sập). Quorum requirement (ngưỡng biểu quyết) 44,6%→68,7%. ASR ≠ harm (thiệt hại): jailbreak median harm $0 nhưng objective hijacking −$85, expected value +$40. 1 channel bị compromise → 44,6% (theo ngày) / 44–52%, 2 channel → 68,7%. Clean degradation: Dec −2,68% nhưng degrade −12,01/−12,38 percentage points khi phòng thủ thêm lớp sai chỗ.
- Áp dụng cho bạn: Nếu agent AI của bạn handling tiền/đơn hàng, defense phân tán (nhiều agent độc lập kiểm tra chéo) tốt hơn ủy quyền cho 1 "manager" duy nhất; đặt ngưỡng biểu quyết cao (~2/3) cho hành động có tiền; đánh giá thiệt hại ($) chứ không chỉ "tỷ lệ tấn công thành công".

### [3] Agentic AI Defense: Decode-Time Provenance Binding for MCP (arXiv 2610.31974)
- Làm gì: Defense cho MCP (Model Context Protocol — giao thức kết nối LLM với công cụ) chống tool-output poisoning ẩn: attacker nhúng chỉ thị vào payload trả về qua carrier ẩn (steganography — giấu tin): LSB (bit ít quan trọng nhất), DCT (biến đổi cosin rời rạc), metadata — mỗi loại × 8 cách né tránh (plain, benign-worded, Base64, token-split, Cyrillic homoglyph, zero-width, Unicode-confusable, HTML-comment) = 24 payloads, test trên FastMCP server thật, model Qwen2.5-0.5B-Instruct.
- Học được gì: Undefended 100% leak; keyword/regex filter 62,5%; defense "contain-don't-detect" (chứa đựng thay vì phát hiện) cơ chế-layer **0%**. Mechanism: MCP layer mint nhãn Untrusted có HMAC signature (chữ ký mật mã) tại decode boundary + layer-maintained lineage ledger (sổ cái dòng dõi dữ liệu); ablation proof: HMAC và lineage necessary, không thay thế cho nhau; stego forgery (làm giả nhãn giấu tin) bị block; promotion audit 67%→100% legitimate completion. Overhead ≈17 µs/call (+0,16%), depth-1000 ≈6,6 ms. Fidelity: PSNR LSB ≈76 dB, DCT ≈18 dB/SSIM 0,94, metadata lossless. Code: github.com/ericyocam/stego_provenance_defense. Scope: "fully mediated execution contexts" — không cover paraphrase không qua layer.
- Áp dụng cho bạn: Mọi tool output trả về cho agent AI (RSS, API, web scrape) nên được gắn nhãn "untrusted" tại điểm nhận (decode boundary), sau đó chỉ thăng cấp thành "tin được" khi pipeline kiểm tra xong — đừng để agent đọc raw output của công cụ ngoài như thể instruction đáng tin.

### [4] OneLatent: Latent Reasoning for Efficient Foundation Recommendation Models (arXiv 2610.30675)
- Làm gì: Foundation recommendation model (FRM — mô hình đề xuất nền tảng dùng LLM backbone) thường "think-then-answer" với chain-of-thought (CoT — chuỗi lập luận viết ra) dài: overthinking (lập luận quá mức) + interest drift (trôi quan tâm). OneLatent nén trace thành 3 learnable latent tokens (token ẩn học được, ID cố định chia sẻ mọi sample) — "Latent-Reason-then-Answer". Teacher Qwen3-235B sinh MV-ACoT (Multi-View Adaptive CoT — CoT thích ứng đa góc nhìn): Exploration/Evaluation/Attribution; align theo 3 stage (single-view → multi-view → SID prediction); curriculum post-training (SFT high→low activity users, mix 1:1 latent/standard).
- Học được gì: Industrial (Kuaishou Locallife: 100,063 SFT/59,113 CoT/20,393 test) + public Kuaishou LLM-Rec (60,000/30,000/10,000). SID@64 (độ chính xác dự đoán Semantic ID 3-token qua Res-Kmeans trong top-64) +17,44% vs Think, +9,33% vs No-Think (cùng checkpoint); 9B: 0,2008 vs 0,1857 (+8,13%). Hiệu suất: 3,17s/274,29 QPS (queries per second — truy vấn/giây) vs CoT 55,59s/15,68 QPS (17,49×) trên 872 instances; codebook retrieval Hit@L1 0,354→0,401; adaptive teacher giảm 35% độ dài rationale (~0,92 similarity case phức tạp); 1→3 latent tokens cải thiện, >3 không thêm. A/B production Kuaishou local-services advertising 7 ngày (Sep 3–10, 2026, 5% traffic): impressions +2,566%, ad spend +5,157%, estimated revenue **+9,6%** → đã roll out toàn bộ production.
- Áp dụng cho bạn: Nếu bạn chạy model gợi ý "bài tiếp theo/sản phẩm tiếp theo" cho khách, đừng generate lập luận dài mỗi lần serving — distill reasoning vào latent tokens (hoặc đơn giản: precompute ranking offline) → quality giữ/↑ nhưng latency ↓ ~17×. Tối cost: teacher mạnh (sinh rationale 1 lần offline) + student nhỏ (0,8B) serving online.

### [5] Profile-Driven User Simulation via RL with Hierarchical Rewards for Task-Oriented Dialogues — ProfileSim (arXiv 2610.32435)
- Làm gì: Thiếu dữ liệu thoại thật (privacy + expensive). ProfileSim sinh user simulator (mô phỏng người dùng) cho marketing outbound call (cuộc gọi chào hàng): user profile = objective (giới/tuổi/nghề/ngôn ngữ) + subjective (Big Five personality traits — 5 yếu tố tính cách: hướng ngoại, dễ chịu, tận tâm, ổn định cảm xúc, cởi mở); business profile (intent + chuyển tiếp intent) reverse-engineered (đảo ngược engineer) từ real call logs; customer service agent với SOP (quy trình chuẩn) + RAG (retrieval-augmented generation — tạo text có truy xuất). Pipeline: 242,438 raw sessions → desensitize (ẩn danh) → 72,296 valid dialogues (avg 7 turns); 73 fine-grained intents/9 intent groups + Markov transition (xác suất chuyển intent-group) + pstay=0,1; SFT người sinh profile (10,000 pairs annotate bằng GPT-5, 95,4% valid) và user sim (Qwen3.5-9B, LoRA); GRPO (Group Relative Policy Optimization — tối ưu chính sách nhóm) với hierarchical rewards (reward phân tầng): dialogue-level profile cosine + utterance-level coherence 0,30/nonrep 0,15 (cos>0,8→0)/natural 0,25/business-compliance 0,30; turn reward 0,5/0.5, G=8 rollouts, turn-level advantage.
- Học được gì: DeepSeek-R1 backbone agent + frozen simulator so sánh zero-shot (GPT-5, DeepSeek-V3/R1, Qwen3-Max): ProfileSim Full đạt colloquial naturalness (sự tự nhiên khẩu ngữ) 4,97/5 (SFT 4,46; GPT-5 4,21), utterance length 11,14 chars (GPT-5 44,54; DeepSeek-V3 153,96), user profile adherence (bám profile) 92,55% (SFT 84,29%), agent score 3,49 — THẤP NHẤT = stress-test long-tail intent (20% hiếm nhất) mạnh nhất. User profile conditioning dominant: perplexity (độ ngạc nhiên model) 58,48 → +user profile 22,24 (−36,24) vs +business profile 43,04 (−15,44); full SFT 17,52, full model 17,49 (GRPO giữ phân phối). Adaptive CoT giảm 35% avg length (100→65 normalized) với ~0,92 similarity. Human spot-check 500/metric Cohen's κ≥0,72. Cost ~4,2s & $0,04/target query. 58% utterance user tương ứng scenario-specific intents.
- Áp dụng cho bạn: Muốn test chatbot/call-script bán hàng trước khi tung mà không vi phạm privacy: sinh "khách hàng giả" đa dạng persona (demographics + Big Five) từ history ẩn danh, cho chúng gọi agent của bạn trên intent thật đã reverse-engineer từ call log; judge bằng rubric 9 chiều; agent nào tệ nhất trên intent hiếm → vá trước khi production.

### [6] Where Should Agents Live? Energy-Memory Characterization of Agentic AI for the Edge-Cloud Continuum — agentic-eCAL (arXiv 2609.18283)
- Làm gì: Framework kế toán energy (năng lượng) đầy đủ cho agentic workflow: per-call two-rate closed-form energy model — prefill (compute-bound) c_pre·p_in + decode (memory-bound) (a_dec/b + c_0)·p_out (b = batch, decode amortizes weights theo batch); workflow energy E_W = (1+γv)[ΣE_call + ΣE_tool + ΣE_ret + E_tx] với 7-layer OSI transport cost; agentic-eCAL [J/b] = (E_W + embodied share)/useful bits. Memory feasibility: weights βN_params + dynamic context γΣc_a ≤ M_u per site. Tiers: Core cloud ≥80GB (A100/H100; ≥70B, 27B), telco edge/MEC 24–64GB (7B–14B), far edge/device ≤8GB (≤3B–4B).
- Học được gì: Hundreds of GPU benchmark configs NVIDIA A100/H100 vLLM (R²≥0,99 MAPE ~10%), 16 open-weight models 5,7–50,3 GB, 8 orchestration topologies, 270 configs/model (b 2–256, N 2–30). Findings: (1) inter-agent TEXT transport <0,25% workflow energy trên 5G/metro/optical (10⁻⁶/10⁻⁷/10⁻⁸ J/bit) → cost of distribution là EXTRA INFERENCE + context processing, không phải truyền text; E_tx/E_prefill ≈ 1/496 (hand-off 2,700 tokens qua 5G). (2) History-carrying loop: p_in ~ s·k → Σp_in quadratic — K=6 tốn +32,8% (89J vs 67J Qwen, +21,7% Llama). (3) Batch amortization: −38,1% năng lượng N=2 nhưng chỉ −15,4% N=30 (4,400J vs 5,200J) — quadratic prefill thắng. (4) Memory binding: GPT-OSS-20B (KV 48 kB/token) host 112 concurrent sessions vs OLMo-2-7B (KV 512 kB/token) chỉ 7 session trên cùng accelerator — KV width, không weight class, quyết định; capacity 1–2 session (8GB) → 59 (A100). (5) Hand-off protocol dynamic range 3,7×10⁵: incremental 0,051 Mbit vs transcript 0,33 Mbit vs KV-cache migration 18,9 Gbit (5 orders above transcript) → KV state effectively non-transportable trên mọi cellular bearer, binds context to local accelerator. (6) ZSM telco benchmark (Kubeply Infra-Bench k3s, 24 incidents): multi-agent topology tốn 23,9× (Qwen2.5-7B)/4,0× (Qwen3.5-9B) energy mà remediation success không nhất quán — Single ReAct solves 61,7%, best multi (P+R+W+V) 64,6% với 2,9× energy; kJ/solved-task: Single 17,4 vs multi 29,0–79,2 (7B: Single 9,2% vs multi 0,4–4,6% TỆ HƠN). Exponent a 1,10→1,42 (Qwen, b 2→256).
- Áp dụng cho bạn: Trước khi nhân rộng team agent (30 agent all-to-all debate = 32–158× 1 call), đo kJ/solved-task single vs multi — multi chỉ worth nếu accuracy gain thật. Giữ context bounded: summarize (0,079) hoặc gửi increment (0,051) thay vì full transcript (0,33, ×30 growth K=1→6). Chọn model theo KV width nếu concurrency cao; chọn bearers/cloud theo memory fit, đừng tối ưu "chi phí truyền data" (text transport <0,25%).

### [7] Learning Who Talks to Whom: Role-Aware Communication Topology Scheduling — ACTS (arXiv 2610.25851)
- Làm gì: Team LLM agent thường dùng topology cố định (full-mesh debate) hoặc LLM-chosen adaptively — cả hai đều waste token. ACTS scheduler (huấn luyện MARL CTDE — centralized training decentralized execution) để mỗi agent tự quyết WHEN/HOW giao tiếp: role-conditioned relational attention (attention theo vai trò) chọn variable-cardinality directed partner sets từ role embedding + evolving state; 6 modes (off, solo, broadcast, attn-broadcast, receive, attn-receive); topological attention mixer embed directed topology vào value decomposition cho credit assignment (gán công) với IGM consistency preserved; objective max E[w_task·R_task − w_tok·min(Σc_tok/B,1)] (token penalty clamp B).
- Học được gì: 9 benchmarks 4 domains (LiveCodeBench v6, HumanEval, MMLU-Pro, HLE 250, HotpotQA, AIME 2025/2026, HMMT 2025, Beyond-AIME), backbone frozen GPT-OSS-120B/DeepSeek-V4-Flash, 3 role agents + answer-aggregation node, 3 seeds. Avg accuracy 75,01%/69,43% — +3,18/+6,19 percentage points over Agent Q-Mix (best or tied-best mọi benchmark); token 5,97k/4,03k/sample (−15,42%/−13,84%). Ablation: topological mixer → QMIX mất −3,18/−6,19pp (token 7,41k/4,96k); learned routing → fixed partners worst 72,50%/8,10k; role embeddings removed 73,40%/6,80k. Information-gain (IG — độ nâng accuracy) gate: task IG≈0 (ΔACC < threshold 2/n) → off-share 4,2%→21,3%, attn-receive pull 28,3% dominant; HotpotQA (high-IG) broadcast 22,7%. Single-agent prompting −27pp accuracy HotpotQA dù rẻ token. Slope a≈1,10–1,42 theo batch; independent agents collapse to linear Θ(N); all-to-all Θ(N²).
- Áp dụng cho bạn: Team agent content (nghiên cứu/viết/hiệu đính): route critique chỉ đến agent liên quan (attn-receive/pull), KHÔNG broadcast full-mesh; cho phép agent "off/solo" khi task đơn giản — test IG trước (single vs team trên ~30 task mẫu, Δ <≈6–7pp thì dùng single); credit agent theo message nào thật sự thay đổi downstream, không phải ai nói nhiều.

### [8] ReFilter: Bridging Embeddings and LLM Filtering for Similar Mobile App Retrieval (arXiv 2609.25306)
- Làm gì: "Similar apps" trên store = semantic similarity (gần nhau về từ ngữ), KHÔNG phải functional similarity (cùng nhu cầu người dùng — user sẽ chấp nhận làm substitute). ReFilter hybrid retrieve-then-filter: (1) embedding recall — 6 method (text-only: BGE-AVG, BGE-FIRST, Linq-Embed-Mistral full description; multimodal: SigLIP2-AVG/TopN, Voyage AI) cosine similarity top-k (k 5→50); (2) LLM contextual filter — GPT-5 verdict từng candidate pair (run 3× average vì không có temperature=0). Corpus: Google Play scrape Aug 2025, 34,364 seed → preprocess (loại Games/Family, non-English, noise, <200 chars, <100 downloads) → 20,635 apps; ground truth: 10 target apps top-10 categories → top-50 merge → 1,315 pairs (450 dev/450 test unseen categories), 2 annotators Cohen's κ=0,79 (substantial); 1,156-app RQ3 sample (15 categories, 95% conf 10% margin).
- Học được gì: Embedding-only ceiling: Linq (text-only, LLM-based) best F1 60% tại k=45 (precision 86% k=5); LLM-based model capacity > pooling strategy; BGE-FIRST > BGE-AVG (functional cues ở đầu description); multimodal SigLIP2/Voyage ≤ text-only (screenshots gây noise — password manager vs expense tracker cùng UI list). LLM filter 2-shot optimal: precision 97%, conditional recall 84% (0-shot chỉ 74%) → **F1 90%** (pooled recall 70%, F1 86%); 4/6-shot flat (không thêm); output count dynamic 0–45/target — đúng khi trả ZERO (app không có substitute). False-negative error taxonomy (75 cases): core-feature secondary 28, same-goal-different-method 18, partial fulfillment 11, misidentified core 10, different-purpose-same-feature 8. RQ3: counts vary by category (Personalization/Social/Photography cao; Business/Tools/Sports thấp) và download range (low-download apps có nhiều biến thể gần giống — Kruskal-Wallis H=180,0, p<0,001, ε²=0,15; Dunn post-hoc); Google Play "similar" mean ~93 apps vs framework ~21 (Wilcoxon signed-rank p<0,001; Play lớn hơn 1,031/1,156) — Play discovery-oriented vs functional-equivalent; temporal clusters k=3 (slow-linear entropy 0,98 avg release 2019; early-rapid 0,97/2016; late-rapid 0,82/2022 Personalization-dominated). Cost ~4,2s & $0,04/target query.
- Áp dụng cho bạn: Tính năng "similar content/products" cho shop/blog: cosine recall top-45 rồi LLM verdict 2-example few-shot ("user đọc/buy item A có chấp nhận item B làm thay thế không — cùng nhu cầu, không cùng từ ngữ") → precision ~97%; để số lượng output thay đổi (có khi 0), KHÔNG hardcode top-10; đặt core purpose ở câu ĐẦU description; đừng dùng marketplace "similar items" cho competitor analysis (chúng discovery-driven).

### [9] Auditing Tool Traces in Agentic LLMs: Source Localization and Counterfactual Dependence Testing (arXiv 2610.25540)
- Làm gì: Agent LLM augment tool results (output công cụ serialized) có thể chứa hidden label shortcuts (lối tắt nhãn ẩn): entry identifiers, file paths, template artifacts — model "thành công" nhờ memorize identifier pattern chứ không reasoning. Two-stage audit: Stage 1 PT2D (Per-Tool TF-IDF Decomposition — phân rã TF-IDF theo từng công cụ): cho mỗi scope (full trace hoặc tool đơn), TF-IDF (word 1–2-gram + char 2–5/3–5-gram) + balanced logistic regression trên Dfit → AUROC trên Deval, rank carriers so với full-scope/chance/tools khác (KHÔNG threshold universal); Stage 2 Token-Class Redaction (xóa theo lớp token): nhóm suspect values theo generating semantics, replace toàn bộ occurrences trong prompt-bearing fields bằng placeholder, re-evaluate FROZEN LLM → counterfactual dependence (kiểm tra phụ thuộc phản thực tế). Case study: TCR-pMHC binding prediction (immunoinformatics), fine-tuned Qwen3-4B trên 5-tool traces (peptide-disjoint cluster splits Slone et al/Abeer et al: 12,940 train/1,438 val/4,898 test), tools gồm CDR3β descriptors, McPAS-TCR retrieval, ThermoMPNN ∆∆G, stability/hotspots, interface descriptors — tools KHÔNG bao giờ nhận label.
- Học được gì: Original A_orig = 0,8136 test AUROC vs no-evidence 0,4928 — "ngon" trên mặt. PT2D: full-trace scope ≈ chance (0,4818–0,4876) nhưng Tool 3 (ThermoMPNN) A3 = 0,6365 (char 3–5-gram) — gap 0,1489 → aggregation DILUTES tín hiệu (real tools appended 0,6365→0,4876 monotonic; synthetic label-free additions reproduce, chance tại K=5); word features Tool 3 ở chance (0,4946) → signal là identifier fragments, không phải ngôn ngữ sinh học; top fragments "_21" (binder) / "_17" (non-binder), prefix-lookup AUROC 0,6967 (pattern filename ThermoMPNN_inference_<pdb_id>.csv). Stage 2: redact PDB-ID class → 0,4972 (∆A=+0,3163 collapse về chance); redact peptide class (control) → 0,8152 (∆A=−0,0017 stable). Verdict: model phụ thuộc PDB identifiers, KHÔNG phải biological reasoning. NeurIPS 2026 AgenticLS workshop; data/code github.com/wherecyberagentsstruggle.
- Áp dụng cho bạn: Trước khi tin agent "phân tích dựa trên dữ liệu liệt kê": xóa class identifier nghi ngờ (ID, timestamp, filename pattern) khỏi tool output → chạy lại frozen model — accuracy collapse = shortcut, phải sanitize identifier tại tool-serialization layer (hash ID server-side) rồi re-eval; screen MỌI tool result RIÊNG biệt (concatenated trace = false negative do dilution); luôn kèm 1 control class (peptide-style) — drop không có stable control chứng minh nothing.

### [10] Where Cyber Agents Struggle: Bottleneck Analysis of Multi-Stage LLM Agents (arXiv 2609.28572)
- Làm gì: Success rate của multi-stage agent (orchestrator + executor + validator LLMs) che giữ inefficiency, repetition-as-"recovery", và hiểu sai execution evidence. ## CÓ GÌ ÁP DỤNG ĐƯỢC CHO BẠN
1. **Multi-agent "hội đồng" không tự đúng — thêm provenance gate**: mỗi kết luận kèm bằng chứng cụ thể; below threshold → xuất divergence report thay vì majority. APG cắt provenance-free 0,288→0,617; 75,8% user tin report khác biệt hơn câu trả lời bịa (N=33, p=0,0039). Ví dụ: 2 agent chọn giá bán → bắt mỗi đề xuất trích dẫn số liệu; không khớp → ghi "khác biệt" ra cho bạn xem, đừng gộp.
2. **Test "agent có thật sự dùng dữ liệu" bằng redaction**: xóa class ID/timestamp/filename khỏi tool output → chạy lại model frozen — accuracy collapse (0,81→0,50 paper) = shortcut. Ví dụ: agent tóm tắt "dữ liệu đơn hàng" → ẩn order-ID thử lại; nếu kết luận đổi chữ → sanitize ID tại tool layer (hash server-side).
3. **Verify end-state, không tin agent claim "done"**: validator accept process creation/echoed output làm success (framework contributions 72–100%); success explanations overstated (cautiousness 0,70 vs 0,92 failure). Ví dụ: agent báo "đã đăng bài lên fanpage" → check bài thật sự xuất hiện + link live trước khi tính xong việc.
4. **Route thông minh + IG gate cho team agent**: attn-receive/pull (critique đến đúng agent) thay broadcast; task có ΔACC <≈2/n noise → dùng single agent (off-share 21,3% ở task IG-null). ACTS: +3–6pp accuracy, −15% token. Ví dụ: pipeline 3 agent viết blog — editor chỉ pull section liên quan từ researcher; task "đổi định dạng" → 1 agent.
5. **Similar-item precision +90% F1, $0,04/query**: embedding recall top-45 → LLM filter 2-shot ("user A có chấp nhận B thay thế không?") → output count 0–45 dynamic, KHÔNG hardcode top-10. Ví dụ: shop thời trang — "khách xem áo này cũng xem" thay vì "cùng tag" (ReFilter phát hiện semantic ≠ functional: Spanish vs Danish app KHÔNG substitute).
