### [1] Towards Mitigating Fabricated Consensus: The Active Provenance Gate (arXiv 2609.31422)
- What it does: Multi-agent debate (MAD) often ends in fabricated consensus — agents agreeing with each other on an ungrounded conclusion. The paper adds an Active Provenance Gate: every synthesized claim must be traceable to specific evidence/agent/step; claims whose provenance (source traceability) falls below a threshold are blocked from the final conclusion, not just logged. Prior work differs: PROV/PROV-AGENT treat debate logs as passive artifacts for post-hoc checking; self-refine imposes no hard constraints.
- Key findings: On a 90-trajectory testbed, the provenance-free baseline reached provenance fraction (share of claims with sources) 0.288 (terminal)/0.183 (REST); APG reached 0.617/0.586. Configuration: provenance threshold ≥0.95 + self-healing up to 3 retries + a Divergence Report when agents disagree. User study N=33: 75.8% trusted the divergence report more than the fabricated answer (p=0.0039). Symmetric validators (validator identical to the proposer) failed 85.6% → the validator must be STRONGER than and DIFFERENT from the proposer.
- Apply it: When you ask 2–3 AI agents to "committee" a decision (pricing, content channel), don't take a blind majority vote. Add a rule: every conclusion must cite specific evidence (numbers, links); if evidence doesn't match → emit a divergence report instead of merging. The checker must not be the proposer.

### [2] Poisoning Agentic Alpha: Adversarial Vulnerabilities Across Multi-Agent Trading Frameworks (arXiv 2608.24069)
- What it does: Measures adversarial vulnerabilities in multi-agent trading systems: jailbreaking the Risk Manager, persuasive attacks, data poisoning, and objective hijacking. Real backtest: 5 assets × 2 backbones × 61 days.
- Key findings: Risk-Manager jailbreak attack success rate (ASR) 98.9%/95.5%; persuasive attacks 41.9–53.3% (p<0.005); poisoning 10%→80% of data pushes ASR 19.1%→30.6%. Defense-in-depth ordering: Decentralized ASR 0.00 < Hybrid 0.33 < Linear 0.50 < Centralized 1.00 (correlation r=0.85/0.88 — more centralization, easier collapse). Quorum requirement 44.6%→68.7%. ASR ≠ harm: jailbreak median harm $0 vs objective hijacking −$85 (expected value +$40). One compromised channel → 44.6% (per-day)/44–52%; two channels → 68,7%. Clean degradation: Decentralized −2.68% but mis-placed defenses degrade −12.01/−12.38 percentage points.
- Apply it: If your AI agents handle money or orders, prefer distributed defense (independent cross-checking agents) over delegating to a single "manager"; require a high quorum (~2/3) for monetary actions; evaluate damage in dollars, not just "attack success rate".

### [3] Agentic AI Defense: Decode-Time Provenance Binding for MCP (arXiv 2610.31974)
- What it does: Defends MCP (Model Context Protocol) against hidden tool-output poisoning: attackers embed commands into returned payloads via covert carriers — LSB (least significant bit), DCT (discrete cosine transform), metadata — each × 8 evasion styles (plain, benign-worded, Base64, token-split, Cyrillic homoglyph, zero-width, Unicode-confusable, HTML-comment) = 24 payloads, tested on a real FastMCP server with Qwen2.5-0.5B-Instruct.
- Key findings: Undefended: 100% leak; keyword/regex filters: 62.5%; the "contain-don't-detect" mechanism-layer defense: **0%**. Mechanism: the MCP layer mints an HMAC-signed (cryptographic signature) Untrusted label at the decode boundary plus a layer-maintained lineage ledger (data-provenance ledger); ablation proof: HMAC and lineage are both necessary and non-interchangeable; stego forgery is blocked; promotion audit 67%→100% legitimate completion. Overhead ≈17 µs/call (+0.16%), depth-1000 ≈6.6 ms. Fidelity: PSNR LSB ≈76 dB, DCT ≈18 dB/SSIM 0.94, metadata lossless. Code: github.com/ericyocam/stego_provenance_defense. Scope: "fully mediated execution contexts" — unmediated paraphrases are out of scope.
- Apply it: Every tool output feeding your agent (RSS, APIs, scrapes) should be labeled "untrusted" at the point of receipt (decode boundary), then promoted to "trusted" only after pipeline checks — never let agents read raw external tool output as if it were trusted instruction.

### [4] OneLatent: Latent Reasoning for Efficient Foundation Recommendation Models (arXiv 2610.30675)
- What it does: Foundation recommendation models (FRMs) using LLM backbones tend to "think-then-answer" with long written chain-of-thought (CoT) traces: overthinking plus interest drift. OneLatent compresses the trace into 3 learnable latent tokens (fixed IDs shared across all samples) — "Latent-Reason-then-Answer". A Qwen3-235B teacher generates MV-ACoT (Multi-View Adaptive CoT): Exploration/Evaluation/Attribution views; alignment in 3 stages (single-view → multi-view → SID prediction); curriculum post-training (SFT high→low-activity users, 1:1 latent/standard mix).
- Key findings: Industrial (Kuaishou Locallife: 100,063 SFT / 59,113 CoT / 20,393 test) + public Kuaishou LLM-Rec (60,000/30,000/10,000). SID@64 (accuracy of predicting the 3-token Semantic ID via Res-Kmeans within top-64) +17.44% vs Think, +9.33% vs No-Think (same checkpoint); 9B: 0.2008 vs 0.1857 (+8.13%). Efficiency: 3.17s/274.29 QPS (queries per second) vs CoT 55.59s/15.68 QPS (17.49×) on 872 instances; codebook retrieval Hit@L1 0.354→0.401; the adaptive teacher cuts average rationale length 35% (~0.92 similarity on complex cases); 1→3 latent tokens help, >3 add nothing. Production A/B at Kuaishou local-services advertising (Sep 3–10, 2026, 5% traffic, 7 days): impressions +2.566%, ad spend +5.157%, estimated revenue **+9.6%** → rolled out to all production traffic.
- Apply it: If you run a "what to read/buy next" recommender, don't generate long reasoning at serving time — distill reasoning into latent tokens (or simply precompute rankings offline) → quality holds/improves while latency drops ~17×. Cost pattern: strong teacher (generates rationales once, offline) + small student (0.8B) online.

### [5] Profile-Driven User Simulation via RL with Hierarchical Rewards for Task-Oriented Dialogues — ProfileSim (arXiv 2610.32435)
- What it does: Real voice-dialogue data is scarce and privacy-sensitive. ProfileSim builds a user simulator for marketing outbound calls: user profile = objective (gender/age/occupation/language style) + subjective (Big Five personality traits: extraversion, agreeableness, conscientiousness, emotional stability, openness); business profiles (intents + intent transitions) reverse-engineered from real call logs; a customer-service agent with SOP (standard operating procedure) + RAG (retrieval-augmented generation). Pipeline: 242,438 raw sessions → desensitization → 72,296 valid dialogues (avg 7 turns); 73 fine-grained intents / 9 intent groups + Markov transition probabilities + pstay=0.1; SFT for the profile generator (10,000 pairs annotated by GPT-5, 95.4% valid) and the user simulator (Qwen3.5-9B, LoRA); GRPO (Group Relative Policy Optimization) with hierarchical rewards: dialogue-level profile cosine + utterance-level coherence 0.30 / non-repetition 0.15 (cos>0.8→0) / naturalness 0.25 / business-compliance 0.30; turn reward 0.5/0.5, G=8 rollouts, turn-level advantage.
- Key findings: DeepSeek-R1 agent compared against zero-shot frozen generators (GPT-5, DeepSeek-V3/R1, Qwen3-Max): ProfileSim Full reaches colloquial naturalness 4.97/5 (SFT 4.46; GPT-5 4.21), utterance length 11.14 chars (GPT-5 44.54; DeepSeek-V3 153.96), user-profile adherence 92.55% (SFT 84.29%), and the LOWEST agent score 3.49 — i.e., the strongest stress test on long-tail intents (bottom 20% rarest). User-profile conditioning dominates: perplexity 58.48 → +user profile 22.24 (−36.24) vs +business profile 43.04 (−15.44); full SFT 17.52, full model 17.49 (GRPO preserves the distribution). Adaptive CoT cuts average length 35% (100→65 normalized) at ~0.92 similarity. Human spot-checks: 500 samples/metric, Cohen's κ≥0.72. Cost ≈4.2s & $0.04 per target query; 58% of user utterances map to scenario-specific intents.
- Apply it: To test a chatbot or sales call script before launch without privacy violations: generate diverse "fake customers" (demographics + Big Five) from anonymized history, let them call your agent on real intents reverse-engineered from call logs; judge with a 9-dimension rubric; whichever agent fails worst on rare intents → fix before production.

### [6] Where Should Agents Live? Energy-Memory Characterization of Agentic AI for the Edge-Cloud Continuum — agentic-eCAL (arXiv 2609.18283)
- What it does: A complete energy-accounting framework for agentic workflows: per-call closed-form two-rate energy model — prefill (compute-bound) c_pre·p_in + decode (memory-bound) (a_dec/b + c_0)·p_out (b = batch; decode amortizes weights across the batch); workflow energy E_W = (1+γv)[ΣE_call + ΣE_tool + ΣE_ret + E_tx] with 7-layer OSI transport cost; agentic-eCAL [J/bit] = (E_W + embodied share)/useful bits. Memory feasibility: weights βN_params + dynamic context γΣc_a ≤ M_u per site. Tiers: core cloud ≥80GB (A100/H100; 70B, 27B models), telco edge/MEC 24–64GB (7B–14B), far edge/device ≤8GB (≤3B–4B).
- Key findings: Hundreds of NVML-metered GPU configs (NVIDIA A100/H100, vLLM; R²≥0.99, MAPE ~10%), 16 open-weight models (5.7–50.3 GB weights), 8 orchestration topologies, 270 configs/model (batch 2–256, N 2–30). (1) Inter-agent TEXT transport <0.25% of workflow energy over 5G/metro/optical (10⁻⁶/10⁻⁷/10⁻⁸ J/bit) — the real cost of distribution is EXTRA INFERENCE + context processing, not the transfer; E_tx/E_prefill ≈ 1/496 (2,700-token hand-off over 5G). (2) History-carrying loops make p_in ~ s·k → Σp_in quadratic — K=6 costs +32.8% (89J vs 67J Qwen; +21.7% Llama). (3) Batch amortization saves −38.1% energy at N=2 but only −15.4% at N=30 (4,400J vs 5,200J) — quadratic prefill wins. (4) Memory binding: GPT-OSS-20B (KV 48 kB/token) hosts 112 concurrent sessions vs OLMo-2-7B (KV 512 kB/token) only 7 on the same accelerator — KV width, not weight class, decides; capacity 1–2 sessions (8GB) → 59 (A100). (5) Hand-off protocol dynamic range 3.7×10⁵: incremental 0.051 Mbit vs transcript 0.33 Mbit vs KV-cache migration 18.9 Gbit → KV state is effectively non-transportable on every cellular bearer, binding context to the local accelerator. (6) ZSM telco benchmark (Kubeply Infra-Bench, k3s clusters, 24 incidents): multi-agent topologies cost up to 23.9× (Qwen2.5-7B) / 4.0× (Qwen3.5-9B) energy with inconsistent remediation success — Single ReAct solves 61.7%; best multi (P+R+W+V) 64.6% at 2.9× energy; kJ per solved task: Single 17.4 vs multi 29.0–79.2 (on 7B: Single 9.2% vs multi 0.4–4.6% — multi WORSE). Energy exponent a rises 1.10→1.42 (Qwen, batch 2→256).
- Apply it: Before scaling a team of agents (30-agent all-to-all debate = 32–158× one call), measure kJ per solved task single vs multi — multi is only worth it if the accuracy gain is real. Keep context bounded: send summaries (0.079) or increments (0.051), not full transcripts (0.33, ~30× growth from K=1→6). Pick models by KV width when concurrency matters; pick hosts by memory fit — don't optimize "data transfer cost" (text transport <0.25%).

### [7] Learning Who Talks to Whom: Role-Aware Communication Topology Scheduling — ACTS (arXiv 2610.25851)
- What it does: LLM agent teams usually use fixed topologies (full-mesh debate) or adaptively LLM-chosen ones — both waste tokens. ACTS trains a scheduler (MARL, CTDE — centralized training decentralized execution) so each agent decides WHEN/HOW to communicate: role-conditioned relational attention selects variable-cardinality directed partner sets from role embeddings + evolving states; 6 modes (off, solo, broadcast, attn-broadcast, receive, attn-receive); a topological attention mixer embeds the directed topology into value decomposition for credit assignment (IGM consistency preserved); objective max E[w_task·R_task − w_tok·min(Σc_tok/B,1)] (token penalty clamped at B).
- Key findings: 9 benchmarks across 4 domains (LiveCodeBench v6, HumanEval, MMLU-Pro, HLE 250, HotpotQA, AIME 2025/2026, HMMT 2025, Beyond-AIME), frozen backbones GPT-OSS-120B/DeepSeek-V4-Flash, 3 role agents + answer-aggregation node, 3 seeds. Average accuracy 75.01%/69.43% — +3.18/+6.19 percentage points over Agent Q-Mix (best or tied-best on every benchmark); tokens 5,97k/4,03k per sample (−15.42%/−13.84%). Ablations: replacing the topological mixer with QMIX loses −3.18/−6.19pp (tokens 7,41k/4,96k); learned routing → fixed partners is worst (72.50%/8.10k); removing role embeddings 73.40%/6.80k. Information-gain (IG) gate: on IG≈0 tasks (ΔACC below the 2/n noise threshold), off-share rises 4.2%→21.3% and attn-receive pull dominates (28.3%); on HotpotQA (high-IG) broadcast 22.7%. Single-agent prompting saves tokens but loses −27pp accuracy on HotpotQA. Slope a≈1.10–1.42 with batch; independent agents collapse to linear Θ(N); all-to-all is Θ(N²).
- Apply it: For a content team agent (research/write/edit): route critique only to the relevant agent (attn-receive/pull), no full-mesh broadcast; allow "off/solo" on simple tasks — test IG first (single vs team on ~30 sample tasks; Δ below ~6–7pp → use single); credit agents by which message actually changed downstream outcomes, not by who talked most.

### [8] ReFilter: Bridging Embeddings and LLM Filtering for Similar Mobile App Retrieval (arXiv 2609.25306)
- What it does: Store "similar apps" reflect semantic similarity (similar wording), NOT functional similarity (same user need — would the user accept it as a substitute?). ReFilter is a hybrid retrieve-then-filter: (1) embedding recall — 6 methods (text-only: BGE-AVG, BGE-FIRST, Linq-Embed-Mistral on the full description; multimodal: SigLIP2-AVG/TopN, Voyage AI) cosine similarity top-k (k 5→50); (2) LLM contextual filter — GPT-5 verdict per candidate pair (averaged over 3 runs because temperature=0 isn't supported). Corpus: Google Play scrape Aug 2025, 34,364 seed apps → preprocessing (drop Games/Family, non-English, noise, <200 chars, <100 downloads) → 20,635 apps; ground truth: 10 target apps across top-10 categories → merged top-50 candidates → 1,315 pairs (450 dev / 450 test on unseen categories), 2 annotators, Cohen's κ=0.79 (substantial); RQ3 sample of 1,156 apps (15 categories, 95% confidence, 10% margin).
- Key findings: Embedding-only ceiling: Linq (text-only, LLM-based) best F1 60% at k=45 (precision 86% at k=5); LLM-based model capacity beats pooling strategy; BGE-FIRST > BGE-AVG (functional cues appear early in descriptions); multimodal SigLIP2/Voyage ≤ text-only (screenshots add noise — password managers and expense trackers share list-style UIs). The LLM filter with 2 shots is optimal: precision 97%, conditional recall 84% (0-shot: only 74%) → **F1 90%** (pooled recall 70%, F1 86%); 4/6 shots add nothing; output count is dynamic 0–45 per target — correctly returning ZERO when no substitute exists. False-negative error taxonomy (75 cases): core-feature secondary 28, same-goal-different-method 18, partial fulfillment 11, misidentified core feature 10, different-purpose-same-feature 8. RQ3: similar-app counts vary by category (Personalization/Social/Photography high; Business/Tools/Sports low) and download range (low-download apps have more near-identical variants — Kruskal-Wallis H=180.0, p<0.001, ε²=0.15, Dunn post-hoc); Google Play "similar" lists average ~93 apps vs the framework's ~21 (Wilcoxon signed-rank p<0.001; Play larger in 1,031/1,156) — discovery-oriented vs functional-equivalent; temporal clusters k=3 (slow-linear entropy 0.98, avg release 2019; early-rapid 0.97/2016; late-rapid 0.82/2022, Personalization-dominated). Cost ≈4,2s & $0.04 per target query.
- Apply it: For "similar content/products" in a shop or blog: cosine recall top-45, then a 2-example LLM verdict ("would a user of item A accept item B as a substitute — same need, not same words") → ~97% precision; let the count vary (sometimes 0) — don't hardcode top-10; put the core purpose in the FIRST sentence of descriptions; don't use marketplace "similar items" for competitor analysis (they're discovery-driven).

### [9] Auditing Tool Traces in Agentic LLMs: Source Localization and Counterfactual Dependence Testing (arXiv 2610.25540)
- What it does: Tool results fed to LLM agents (serialized tool output) can contain hidden label shortcuts — entry identifiers, file paths, template artifacts — so the model "succeeds" by memorizing identifier patterns rather than reasoning. Two-stage audit: Stage 1 PT2D (Per-Tool TF-IDF Decomposition): for each scope (full trace or single tool), TF-IDF (word 1–2-grams + char 2–5/3–5-grams) + balanced logistic regression on Dfit → AUROC on Deval, ranking carriers against the full-scope/chance/other tools (no universal threshold); Stage 2 Token-Class Redaction: group suspect values by generating semantics, replace all occurrences in prompt-bearing fields with placeholders, re-evaluate the FROZEN LLM → counterfactual dependence testing. Case study: TCR-pMHC binding prediction (immunoinformatics), fine-tuned Qwen3-4B on 5-tool traces with peptide-disjoint cluster splits (12,940 train / 1,438 val / 4,898 test); tools (CDR3β descriptors, McPAS-TCR retrieval, ThermoMPNN ∆∆G, stability/hotspots, interface descriptors) never see labels.
- Key findings: Original A_orig = 0.8136 test AUROC vs no-evidence baseline 0.4928 — looks great on the surface. PT2D: the full-trace scope sits at chance (0.4818–0.4876) but Tool 3 (ThermoMPNN) reaches A3 = 0.6365 (char 3–5-grams) — a gap of 0.1489 → aggregation DILUTES the signal (appending real tools decays it monotonically 0.6365→0.4876; synthetic label-free additions reproduce the decay, reaching chance at K=5); word features for Tool 3 stay at chance (0.4946) → the signal is identifier fragments, not biological language; top fragments "_21" (binder) / "_17" (non-binder), prefix-lookup AUROC 0.6967 (filename patterns like ThermoMPNN_inference_<pdb_id>.csv). Stage 2: redacting the PDB-ID class → 0.4972 (∆A=+0.3163, collapse to chance); redacting the peptide class (control) → 0.8152 (∆A=−0.0017, stable). Verdict: the model depends on PDB identifiers, not biological reasoning. NeurIPS 2026 AgenticLS workshop.
- Apply it: Before trusting that an agent "analyzes the listed data": delete the suspect identifier class (IDs, timestamps, filename patterns) from tool output → rerun the frozen model — an accuracy collapse means a shortcut; sanitize identifiers at the tool-serialization layer (hash IDs server-side) and re-evaluate; screen EVERY tool result SEPARATELY (concatenated traces give false negatives via dilution); always include one control class — a drop without a stable control proves nothing.

### [10] Where Cyber Agents Struggle: Bottleneck Analysis of Multi-Stage LLM Agents (arXiv 2609.28572)
- What it does: A multi-stage agent's (orchestrator + executor + validator LLMs) success rate hides inefficiency, repetition-as-"recovery", and misinterpretation of execution evidence. Two-resolution diagnostic framework: (1) task-level localization — with a shared expert-defined decomposition, z-normalize tokens/attempts/time per subtask across models, B = α[z(tokens)]+ + β[z(N)]+ + γ[z(time)]+ (equal weights); (2) trajectory-level — a 5-judge panel (DeepSeek V4 Pro, GPT-5.6 Sol, Kimi K3, Gemini 3.6 Flash, GPT-5.6 Luna Pro) over the full trace → modal category (planning / action execution / state tracking / recovery / validation-framework / environment / other), ≤2 contributing bottlenecks, 7 mechanism tags, severity 1–5; support A(τ) = max n_c/J_t, ties kept explicit (a unique mode can have only 2/5 votes); meaningful adaptation defined up front (change hypothesis / resolve prerequisite / gather discriminating evidence / change dependencies / different strategy — changing syntax/wrappers/tools while keeping the failed assumption is repetition, NOT recovery). System: Autonomous Adversary, 6 acting models (Opus 4.5, Sonnet 4.5, Gemini 3 Pro Preview, GPT-5.1, GPT-4o-mini, DeepSeek-V3.2-Speciale) × 2 lateral-movement scenarios (S1 low-privilege workstation, 9 subtasks; S2 jump-server admin foothold, 10 subtasks) × 3 modes (expert-defined / self-scaffolded / fully autonomous); validator = same model as the actor; 29 complete panels = 145 judgments; 45,000-token per-call reference.
- Key findings: Validators are relevant and evidence-grounded but nonspecific and overly optimistic: explanation quality 0.79/0.84 (success/failure), grounding 0.81/0.90, specificity only 0.69/0.68, cautiousness 0.70/0.92 → success verdicts overstate when evidence is incomplete; a validator-accepted outcome is NOT independently verified (process creation or echoed output accepted as success evidence). Bottlenecks cluster at credential/lateral-movement stages — S1-E: action execution (command realization, quoting/escaping, credential-tool invocation; Gemini support only 2/5 vs GPT-5.1's 5/5); S1-S: ALL planning-limited 4/5–5/5 (self-generated decomposition is hard); S1-A: heterogeneous (Opus recovery-limited; Gemini planning-limited unanimously — credentials ASSUMED rather than established); S2 reverses the ordering — S2-S has 3 action-execution trajectories (agent deployment with wrong executables, placeholder commands, process creation ≠ operational callback); S2-A: all planning at 3/5. Mean modal support 0.60–0.90; deletion robustness: 12/23 panels ≥4/5; no meaningful adaptation: S1 5/20(E) → 15/20(S) → 20/20(A), S2-E/S2-S 20/20; mechanisms: unsupported assumptions 25/30 (S1-S) and 13/15 (S2-A); command-construction errors 18/30 (S1-E) and 13/20 (S2-S); mean severity 4.03–5.00/5; validator/framework contributions in 72–100% of judgments. GPT-4o-mini omitted (failed structured output); DeepSeek omitted (provider errors); Opus S2-A panel INC (a provider cybersecurity safety filter blocked the judge call) — missing data ≠ failure.
- Apply it: Evaluate your agent pipelines on four axes (outcomes, evidence interpretation, resource use, adaptation after failure) — not just "did it finish"; flag retry loops that keep the same root assumption (they burn budget without progress); the autonomy level determines where to audit (fixed playbook → audit command/tool execution; self-planning → audit plan construction + dependency validation); "done" checks must verify an observable end-state (the post actually appears in the CMS), not the agent's claim; when auto-diagnosing with LLM judges, report the vote distribution + support, don't force a single root cause.

## WHAT'S APPLICABLE TO YOU
1. **Multi-agent "committees" aren't automatically right — add a provenance gate**: every conclusion must carry specific evidence; below threshold → emit a divergence report instead of a majority. APG lifts provenance-free 0.288→0.617; 75.8% of users trusted the divergence report over the fabricated answer (N=33, p=0.0039). Example: 2 agents picking a selling price → require each proposal to cite data; on mismatch → surface "divergence" for you to review, don't merge.
2. **Test whether your agent "really uses the data" via redaction**: delete the suspect ID/timestamp/filename class from tool output → rerun the frozen model — an accuracy collapse (0.81→0.50 in the paper) means a shortcut. Example: an agent summarizing "order data" → hide order-IDs and rerun; if conclusions change → sanitize IDs at the tool layer (hash server-side).
3. **Verify the end-state; don't trust the agent's "done" claim**: validators accept process creation or echoed output as success (framework contributions 72–100%); success explanations are overstated (cautiousness 0.70 vs 0.92 on failures). Example: the agent reports "posted to the fanpage" → check the post actually appears live before counting the task done.
4. **Smart routing + IG gate for agent teams**: attn-receive pull (critique goes to the right agent) instead of broadcast; tasks with ΔACC below ≈2/n noise → use a single agent (off-share 21.3% on IG-null tasks). ACTS: +3–6pp accuracy, −15% tokens. Example: a 3-agent blog pipeline — the editor pulls only relevant sections from the researcher; "reformat this" tasks → one agent.
5. **Similar-item precision at 90% F1, $0.04/query**: cosine recall top-45 → 2-shot LLM filter ("would user A accept B as a substitute?") → dynamic output count 0–45, don't hardcode top-10. Example: a fashion shop — "customers who viewed this also viewed" instead of "same tag" (ReFilter shows semantic ≠ functional: Spanish vs Danish learning apps are NOT substitutes).
